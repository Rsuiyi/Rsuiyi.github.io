2. 各论文填补的空白与局限性

2.1 AMA: Adaptive Memory via Multi-Agent Collaboration

填补的空白：

  • 将记忆生命周期拆解为四个专业化智能体（Constructor、Retriever、Judge、Refresher），解决了单一模型记忆系统中存储粒度僵化、冗余累积、粗粒度更新的问题
  • 引入逻辑驱动的冲突检测与一致性维护（Judge-Refresher 循环），填补了记忆系统中缺乏主动一致性验证的空白
  • 多粒度存储（Raw Text、Fact Knowledge、Episode Memory）与自适应路由，使检索粒度与任务需求动态对齐

局限性：

  • 多智能体协作带来额外推理开销和通信复杂度
  • Judge/Refresher 的冲突检测质量高度依赖底层 LLM 的推理能力
  • 未讨论跨 session 的长期记忆演化与主动遗忘机制
  • 缺乏对多模态输入的支持
  • 智能体间的协调机制可能成为性能瓶颈
  • 在智能体数量增加时系统的可扩展性未充分验证

2.2 A-Mem: Agentic Memory for LLM Agents

填补的空白：

  • 受 Zettelkasten 方法启发，实现无预定操作的动态记忆组织（笔记构建→链接生成→记忆演化）
  • LLM 驱动的动态链接机制，支持多跳推理（在 DialSim 数据集上表现尤其突出，至少 2× 性能提升）
  • 开源生产级系统，支持多种 LLM 后端（OpenAI、Ollama、SGLang、OpenRouter）

局限性：

  • 链接质量依赖 LLM 判断，存在不稳定和偏差的可能
  • 记忆演化触发条件不够明确，缺乏主动遗忘机制
  • 向量相似度检索在超大规模记忆库上可能退化
  • 缺乏对矛盾信息的检测与解决机制
  • 上下文窗口压力虽缓解但未解决根本问题

2.3 AtomMem (Learnable Dynamic Agentic Memory with Atomic Memory Operation)

填补的空白：

  • 首次将记忆管理形式化为 POMDP 决策问题，用原子 CRUD 操作替代手工工作流，填补了”记忆操作可学习”的空白
  • 两阶段训练（SFT + GRPO）使模型自主学习任务对齐的记忆策略
  • Scratchpad 机制维持全局连贯性
  • 随文档长度增加性能优势扩大（体现可扩展性）

局限性：

  • CRUD 操作空间虽然完备但表达能力有限——复杂记忆行为可能难以用原子操作组合
  • 训练需要大规模标注数据和计算资源
  • 评估限于多文档 QA（HotpotQA、2WikiMultihopQA、Musique），未覆盖对话场景
  • POMDP 建模假设记忆完全可观测性受限，实际环境更复杂
  • Learnable 策略的可解释性不足

2.4 AtomMem (Building Simple and Effective Memory System for LLM Agents via Atomic Facts)

填补的空白：

  • 细粒度原子事实提取（含指代消解和时间锚定）→ 分层事件结构 → 时序用户画像
  • 关联记忆图谱检索（三种边类型：实体边、事件边、时序边 + RWR 重启随机游走算法）
  • 在 LoCoMo 上 SOTA 且节约 61.4% token

局限性：

  • 事实抽取器质量成为瓶颈——错误传播问题严重，抽取错误会无声污染后续结构
  • 图检索复杂度随记忆规模增长，在超长期部署中延迟可能上升
  • 评估集中在 LoCoMo，真实场景多样性可能带来额外挑战
  • 原子事实的”原子性”界定缺乏统一规范
  • 时序画像的版本管理机制较简单

2.5 CMI-Mem: Toward Generalizable Long-Term Memory Management via CMI-Augmented RL

填补的空白：

  • 引入条件互信息（CMI）作为内在奖励信号，解耦记忆价值评估与特定查询采样
  • 混合奖励（下游 QA 正确性 + CMI）实现了更通用的记忆管理——CMI 补充而非替代 QA 基准
  • 轻量级记忆管理器（4B 参数），适合资源受限场景

局限性：

  • CMI 计算本身引入额外复杂度
  • 记忆管理器和下游 LLM 之间的协同仍需改进
  • 在极端长时场景（>1M tokens）下的泛化能力未充分验证
  • 记忆价值评估仅从信息论角度，未考虑任务语义和用户偏好
  • CMI 与 QA 奖励之间的权衡策略需要更多探索

2.6 D-Mem: A Dual-Process Memory System for LLM Agents

填补的空白：

  • 受认知科学双系统启发（System 1 快速向量检索 / System 2 完整原始对话推演）
  • 多维度质量控制门控（Relevance、Faithfulness & Consistency、Completeness）
  • 在效率与准确性之间实现了原则性的平衡——恢复 System 2 96.7% 性能的同时大幅节省计算

局限性：

  • System 2 的 Full Deliberation 增加 10× 以上计算开销和输入 token
  • 门控评估本身也是 LLM 调用，带来额外成本和延迟
  • 仅评估了对话场景（LoCoMo、RealTalk），对工具使用和代码生成场景未知
  • 双系统切换的触发条件偏后验（门控评估输出后才决定），不够主动

2.7 Does Memory Need Graphs? A Unified Framework and Empirical Analysis

填补的空白：

  • 首次系统性质疑”图结构带来性能提升”这一假设，通过统一框架 ⟨K, V, Q, I, R, A⟩ 实现公平对比
  • 关键发现：图结构的收益来自系统级设计选择（Key 设计、Value 组织、检索策略）而非图本身
  • DescGraph（实体级自然语言描述）优于传统图结构

局限性：

  • 分析性质论文，未提出新方法
  • 实验限于对话记忆，未覆盖更广泛的 Agent 记忆场景
  • 框架的六元组抽象可能过度简化某些系统的独特设计
  • 结论可能因 LLM 基础模型能力提升而过时
  • 对图重建质量的分析停留在任务层面，缺乏细粒度归因

2.8 Dynamic Long Context Reasoning over Compressed Memory via End-to-End RL

填补的空白：

  • 将长期记忆建模为可学习的压缩表示（KV-cache 风格），而非检索式——填补了”端到端学习压缩”的空白
  • 基于端到端 RL 联合优化压缩器和推理器
  • 从 7K 外推到 1.75M token，展示了出色的长度泛化
  • 2× GPU 内存降低 + 6× 推理加速

局限性：

  • 压缩过程中的信息丢失不可逆
  • Gate 模块单独训练，与压缩器/推理器未联合优化
  • 评估集中在多跳 QA，对话和指令跟随场景未充分测试
  • 1024 token 的最优工作记忆容量在更长上下文上可能不最优
  • 压缩 LoRA 模块的通用性需要更多跨模型验证

2.9 General Agentic Memory Via Deep Research

填补的空白：

  • 将 JIT 编译思想引入记忆：无损页面存储 + 轻量级 memo + 查询时深度研究
  • 迭代搜索-整合-反思循环（plan → search → integrate → reflect），实现了任务自适应上下文生成
  • 本质重新定义了”记忆即搜索”而非”记忆即存储”
  • 多工具并行搜索（embedding、BM25、ID-based）

局限性：

  • 在线延迟过高（12-20s），不适合实时产品循环
  • Researcher 的规划/整合/反思具有固有随机性
  • 通用 page-store 存在跨范围信息泄漏风险
  • 修正如何在 memo/page 中传播未解决
  • 多次 LLM 调用的累积成本较高

2.10 Graph-based Agent Memory: Taxonomy, Techniques, and Applications

填补的空白：

  • 首个从图视角全面综述 Agent 记忆的论文，覆盖 2025-2026 年图记忆研究
  • 多轴分类体系（短/长期、知识/经验、非结构化/结构化）+ 四阶段生命周期（Extraction、Storage、Retrieval、Evolution）
  • 系统梳理了图作为索引 vs 图作为真相源的架构区分

局限性：

  • 综述性质，缺乏实证对比
  • 对非图方法的覆盖偏少
  • 对评估标准化的讨论不够深入
  • 实践指南的粒度较粗，特定场景的选型建议不够具体

2.11 GRAVITY: Architecture-Agnostic Structured Anchoring

填补的空白：

  • 提出结构化的锚定上下文（实体画像 + 时序因果事件元组 + 跨 session 主题摘要），将结构化信息注入非结构化提示中
  • 架构无关——无需修改宿主模型即可增强 5 种不同记忆系统，平均提升 7.5-10.1%
  • 随基线强度提升收益递减规律的发现

局限性：

  • 结构化信息的抽取本身需要 LLM 调用
  • 未解决结构信源不一致或冲突时的融合策略
  • 对弱基线的提升大（12.2%）但对强基线提升有限（3.8-5.7%）
  • 在超长场景（>100 轮）中结构化锚定的维护开销上升

2.12 Mem-T: Densifying Rewards for Long-Horizon Memory Agents

填补的空白：

  • 解决 RL 训练记忆智能体中的时间信用分配问题——稀疏二值终端奖赏无法有效指导长期记忆策略
  • MoT-GRPO：记忆操作树回溯 + 事后信用分配，将稀疏反馈稠密化
  • 联合优化记忆构建、演化和检索，超越 A-Mem 和 Mem0 达 14.92% F1 提升

局限性：

  • 训练计算开销大
  • 向量数据库的检索质量影响整体性能
  • MoT 树的构造和剪枝策略需要进一步探索
  • 事后信用分配的因果归因可能存在偏差

2.13 Mem-α: Learning Memory Construction via Reinforcement Learning

填补的空白：

  • 让智能体通过交互和反馈自主学会管理复杂记忆系统（而非手工提示工程）
  • 三组件认知架构（Core Memory 512 tokens + Episodic + Semantic）各支持增/删/改
  • 出色的长度泛化（训练 30K → 推理 400K+ tokens, 13× 外推）和高效压缩（~50% 内存节省）
  • Qwen3-4B 从 38.9% 到 64.2% 的显著提升

局限性：

  • 奖励函数设计（正确性 + 工具调用 + 压缩 + 内容有效性）的权重需要精细调优
  • Core Memory 512 token 上限可能不足
  • 冲突解决场景因缺乏真实基准而被排除在训练外
  • 训练数据和测试分布的差异可能影响实际部署

2.14 Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

填补的空白：

  • 生产级增量记忆管道（Extraction → Update：ADD/UPDATE/DELETE/NOOP）
  • Mem0g 图变体：Neo4j 有向带标签图，支持冲突软失效
  • 广泛的工程优化——91% p95 延迟降低、90%+ token 节省、跨平台 SDK

局限性：

  • 增量处理范式丢失了查询时可能需要的上下文（查询未知前已做压缩决策）
  • 记忆操作依赖 LLM 判断，不一致性可能累积
  • 图变体引入 Neo4j 依赖，增加部署复杂度
  • 大规模多租户场景的性能和隔离性未深入讨论

2.15 MemCoT: Test-Time Scaling through Memory-Driven Chain-of-Thought

填补的空白：

  • 将链式推理与记忆系统融合：多视角长程记忆感知（Zoom-In 证据定位 / Zoom-Out 因果结构重建）
  • 任务条件双短期记忆（语义状态跟踪 + 情节轨迹记录）引导迭代搜索
  • 在 LoCoMo 和 LongMemEval-S 上取得 SOTA（开源和闭源模型均适用）

局限性：

  • 迭代推理过程增加了推理延迟
  • Zoom-In/Zoom-Out 的切换策略带来额外决策开销
  • 双短期记忆的状态管理在极长对话中可能退化
  • 对底层 LLM 的推理能力依赖度高

2.16 Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents

填补的空白：

  • 从认知神经科学出发，提出记忆是”重构”而非”检索”的核心范式转变
  • 活跃重构机制：迭代推理循环 + Cue-Tag-Content (CTC) 关联记忆图
  • 多步重构严格是单步被动检索的超集（理论证明）
  • 在 LoCoMo 上达到 88.32（Claude），且 token 消耗最低（118k，远低于 LangMem 的 3,268k）

局限性：

  • 路由和剪枝决策高度依赖 LLM 推理质量
  • 多步重构引入比单次检索更多的 LLM 调用
  • 验证集中在对话基准，代码/多模态/大规模知识库未测试
  • 重构的终止条件缺乏理论保证

2.17 Memory OS of AI Agent

填补的空白：

  • 操作系统内存管理启发：分段分页架构（Short-Term → Mid-Term → Long-Term Personal）
  • 热度计分迁移策略（检索计数 + 交互时长 + 指数衰减时效性）
  • 在 LoCoMo 上实现 F1 49.11% 和 BLEU-1 46.18% 提升
  • LLM 调用数低于 A-Mem（4.9 vs 13）

局限性：

  • MTM→LPM 的热度迁移策略可能丢失低频但重要信息
  • 硬编码的 FIFO/热度策略缺乏自适应性
  • 分层之间的语义鸿沟（对话片段 vs 个人画像）
  • 评估在 300+ 轮对话上进行，更长场景下的表现未知

2.18 MemoryBank: Enhancing LLMs with Long-Term Memory

填补的空白：

  • 首次将艾宾浩斯遗忘曲线引入 LLM 记忆系统，实现了基于时间衰减和相对重要性的选择性保留
  • SiliconFriend 展示了长期陪伴场景的可行性
  • 模型无关设计（支持 ChatGPT 和 ChatGLM）

局限性：

  • 遗忘曲线参数是固定的，无法适应不同用户的记忆模式
  • 记忆更新偏被动（基于时间衰减），缺乏主动整合
  • 评估以模拟为主，真实用户研究有限
  • 记忆表示形式简单（文本摘要），信息丢失多
  • 未处理记忆冲突和修正

2.19 MemOS: A Memory OS for AI System

填补的空白：

  • 将记忆提升为一等可调度系统资源——三种统一记忆基板（Plaintext、Activation、Parameter）+ 跨格式转换
  • MemCube 标准化单元 + 三层架构（Interface、Operation、Infrastructure）
  • 全面的治理机制（ACL、TTL、审计、水印、版本链、回滚）
  • 预测性”下一场景”预加载

局限性：

  • 系统复杂度和表面积过大，依赖多个交互组件的正确性
  • Activation/Parameter 记忆引入的安全攻击面增大
  • 版本链的冲突解决语义不够明确
  • 复现性存疑——基线配置和调优选择可能主导结果
  • 全实现对于小型代理系统过于沉重

2.20 MemPrivacy: Privacy-Preserving Personalized Memory Management for Edge-Cloud Agents

填补的空白：

  • 首个专注边缘-云端 Agent 记忆隐私的系统化方案
  • 本地可逆假名化（类型感知占位符保护语义角色同时隐藏真实值）
  • 四级隐私分类法（PL1-PL4）+ 首个隐私基准 MemPrivacy-Bench（200 合成用户、52K+ 隐私实例）
  • 隐私保护下精度仅下降 0.71%-1.60%（远优于不可逆掩码的 12-42% 下降）

局限性：

  • 本地检测模型本身可能泄漏隐私（模型逆向攻击）
  • 类型占位符在高细粒度分类下的隐私保护强度未充分论证
  • 边缘端存储的映射数据库成为单点攻击目标
  • 当前仅支持文本模态，多模态隐私场景未覆盖
  • 仅在 LangMem、Mem0、Memobase 上评估，泛化性待验证

2.21 What Deserves Memory: Adaptive Memory Distillation (NEMORI)

填补的空白：

  • 基于预测编码理论 + 互补学习系统的训练无关自适应蒸馏框架
  • 用”预测误差”替代人为启发式（重要性分数、情感标签、事实模板）来决定什么值得记忆
  • 第三方管理系统集成实现 45-64% 存储缩减而不损失性能

局限性：

  • 预测误差的计算本身需要 LLM 推理
  • 评估主要定量，对蒸馏过程的语义保真度分析不足
  • 与不同下游管理系统的兼容性可能差异大
  • 对”新奇”和”重要”的区分不够精细——预测误差捕获一切意外事件但不一定一切意外都值得记忆

2.22 PlugMem: A Task-Agnostic Plugin Memory Module

填补的空白：

  • 以知识单元（命题/技能）而非原始经验为记忆基本单元，提出”决策相关信息应以抽象知识而非原始经验存储”
  • 三种记忆类型（Episodic 经验、Semantic 事实、Procedural 技能）的知识中心图
  • 即插即用设计，6 行代码集成，在 LongMemEval / HotpotQA / WebArena 三个异构基准上超越任务特定系统

局限性：

  • 从经验到知识的抽象过程可能丢失任务特定信号
  • 程序性记忆（技能）的表示和泛化仍有限
  • 主要在文本任务上验证，对具身/视觉等模态扩展不足
  • 插件的通用性以牺牲深度定制为代价

2.23 Remembering More, Risking More: Longitudinal Safety Risks in Memory-Equipped LLM Agents

填补的空白：

  • 首次提出记忆安全性是轨迹属性而非快照属性——需要纵向评估
  • 时间记忆污染：良性记忆累积跨独立任务间导致不安全行为增加（即使没有对抗输入）
  • 触发-探测协议 + NullMemory 反事实基线
  • 检索时诊断记忆诱导风险的监控器（召回率 0.970-0.984）

局限性：

  • 仅在办公助手和工具使用两个场景上评估
  • 记忆架构的多样性有限（8 种架构虽有覆盖但深度不足）
  • 触发-探测协议的自动化程度不够，需要人工设计触发
  • 监控器的误报对用户体验的影响未讨论
  • 未提供具体的防御/缓解方案，仅诊断

2.24 Retain or Consolidate? Budget-Dependent Operator Selection

填补的空白：

  • 将记忆操作选择形式化为预算约束下的效用最大化问题——覆盖效果 + 符号替换效果
  • 发现预算压力是决定保留 vs 合并的关键因素（紧缩预算下合并提升 48%，宽松下保留领先 8-11%）
  • OAS 轻量学习器实现实例级路由

局限性：

  • 仅考虑 Merge/Abstract/Rewrite 三种合并操作，操作空间有限
  • 线性回归 + MLP 的效用估计可能过度简化
  • 预算设定本身是超参数，缺乏自适应机制
  • 离线评估为主，在线动态场景待验证
  • 跨 session 的操作依赖未建模

2.25 SimpleMem: Efficient Lifelong Memory for LLM Agents

填补的空白：

  • 语义”无损”压缩（指代消解 + 时间锚定 + 熵感知过滤）
  • 递归记忆整合（在线 intra-session 合并）+ 自适应查询感知检索（动态 k 范围 3-20）
  • 26.4% F1 提升 + 30× token 节省

局限性：

  • “无损”取决于模型抽取保真度——错误可能无声传播
  • 原始证据指针和审计追踪不够完善
  • 跨 session 时序推理未被完全解决，记忆项被独立处理
  • 安全性多租户隔离不是核心关注点

2.26 Storage Is Not Memory: A Retrieval-Centered Architecture for Agent Recall

填补的空白：

  • 核心洞见：”摄入时提取是错误的原语”——查询未知时丢弃的信息无法恢复
  • 完整保留事件 + 查询时多阶段检索（L0-L5 六层架构）
  • 纯 SQLite + CPU 运行，无需 GPU/向量库/图谱存储（LoCoMo 93.0%）
  • 56 配置消融显示检索管道本身（而非单个组件）驱动性能

局限性：

  • 完整保留导致存储膨胀
  • Encoding Gate 的三信号（新颖性、显著性、预测误差）偏保守
  • 纯 CPU 方案在超大规模下的检索延迟未充分讨论
  • 架构的六层设计偏工程，概念创新相对有限
  • 对频繁更新的场景（如实时协作）支持不足

2.27 Zep: A Temporal Knowledge Graph Architecture for Agent Memory

填补的空白：

  • 生产级时序知识图谱 + 三层层次（Episode → Semantic Entity → Community）
  • 双时模型（事件时间 + 事务时间）支持历史查询和拓扑语义更新
  • 长期记忆评估 18.5% 准确率提升 + 90% 延迟降低

局限性：

  • 图谱构建和维护成本较高
  • 社区子图的摘要生成在大规模上可能成为瓶颈
  • Neo4j 依赖增大了部署复杂度
  • 时序边失效策略在处理快速变化的信息时可能滞后

2.28 Choosing How to Remember: Adaptive Memory Structures (FluxMem)

填补的空白：

  • 打破”单一记忆结构”假设：根据交互特征自适应选择 Linear/Graph/Hierarchical 结构
  • Beta 混合模型（BMM）概率门控替代固定相似度阈值
  • 三层次（STM/MTM/LTSM）+ 基于 eligibility 的剪枝
  • 在 PERSONAMEM 上 9.18% 平均提升

局限性：

  • 结构选择的分类器用离线监督训练，无法在线自适应
  • 特征工程（scale、time signals、entity-relation patterns）需手动设计
  • BMM 门控在高维语义空间中的表现需进一步验证
  • 不同结构之间的切换开销在实践中可能显著

2.29 HeLa-Mem: Hebbian Learning and Associative Memory for LLM Agents

填补的空白：

  • 首次将赫布学习规则（”fire together, wire together”）引入 LLM 记忆系统
  • 情节记忆图（共同激活驱动的动态演化）+ 赫布蒸馏->语义知识
  • 三生物学机制（Association、Consolidation、Spreading Activation）的数字化实现
  • 在 LongMemEval-S 上 65.40%（超越 Mem0 的 53.61% 和 A-MEM 的 62.60%）

局限性：

  • 赫布学习在数字记忆系统中的生物学保真度有待商榷
  • 凝聚中心的蒸馏质量依赖 Reflective Agent
  • 在 LongMemEval-S 上 65.40% 领先但绝对数字仍有提升空间
  • 图动力学在长时间跨度的稳定性未充分验证

2.30 HiMem: Hierarchical Long-Term Memory for LLM Long-Horizon Agents

填补的空白：

  • 话题感知事件-惊奇双通道分割（兼顾话题转换和情感/意图突变）
  • 冲突感知记忆重构（Independent/Extendable/Contradictory 三类关系）+ 动态更新
  • 在 LoCoMo 上达到 80.71%（GPT-Score）的出色表现，远超 Mem0（68.74%）和 A-MEM（51.88%）

局限性：

  • Episode Memory 的构建依赖事件边界检测质量
  • 惊奇检测的”惊奇”定义较窄（仅意图/情感突变）
  • 适应性遗忘机制被标记为”可选”，主动遗忘未深入研究
  • 多跳推理 70.92% 和开放域 54.86% 仍有显著提升空间

2.31 Rethinking How to Remember: Beyond Atomic Facts in Lifelong LLM Agent Memory (TriMem)

填补的空白：

  • 揭示原子事实范式的三大缺陷：丢弃细粒度细节、无法深度推理、不一致的抽取粒度
  • 三粒度（原始对话片段 + 原子事实 + 合成画像）共存的记忆架构
  • TextGrad 提示优化——无需参数更新的终身演化

局限性：

  • 三粒度共存增加了存储和检索复杂度
  • TextGrad 优化依赖强 LLM（Claude Opus 4.6）进行文本逆传播
  • 画像合成的质量对下游推理影响大
  • 终身演化在分布漂移下的鲁棒性未充分验证

2.32 Memanto: Typed Semantic Memory with Information-Theoretic Retrieval for Long-Horizon Agents

填补的空白：

  • 提出 13 种预定义语义类型（fact、preference、decision、commitment、goal、event、instruction、relationship、context、learning、observation、error、artifact），填补了记忆内容缺乏类型化语义标注的空白——使检索可以基于语义类型进行精确过滤
  • Moorcheh 信息论搜索引擎（ITS）：基于最大信息量二值化（MIB）的确定性检索，无需索引/向量库/图谱，实现零摄入成本 + 单次查询确定性检索（<90ms）
  • 核心发现：”召回率胜过精度，LLM 是比预计算图结构更好的过滤器”——挑战了混合图系统是高性能记忆必要条件的普遍假设
  • 五阶段消融揭示最大增益来自召回扩展（k=10→40 提升 6.6pp），而非架构复杂性
  • 在 LoCoMo 上 87.1%（最高纯向量系统）和 LongMemEval 上 89.8% 的 SOTA 性能

局限性：

  • 13 种语义类型的覆盖度有限——某些领域特定记忆类型（如医疗诊断中的 symptom/treatment/medication）无法直接映射
  • 类型化方案需要预先定义语义分类，缺乏对新类型发现的在线自适应能力
  • ITS 的 MIB 二值化在极高维（>4096）嵌入上的信息损失未充分分析
  • 零摄入成本以牺牲摄入时语义理解为代价——写入时完全不做分析，仅依赖查询时的 LLM 过滤
  • 单次检索策略在需要多步推理的复杂记忆关联场景中可能不足
  • 评估在 LoCoMo/LongMemEval 上进行，对工具使用、代码生成的泛化性未知
  • 语义类型定义为人工设计，不同任务的最优类型体系可能存在差异

3. 所有论文的共同局限性

3.1 评估基准单一化与生态封闭

绝大多数论文（约 80%）仅在 LoCoMo 和/或 LongMemEval 上评估，包括新加入的 Memanto 也同样依赖这两大基准。这两个基准虽然重要，但覆盖场景有限：

  • 对话历史以文本为主，缺乏多模态（图像、代码、结构化数据）场景
  • 缺乏工具使用、代码生成、具身任务中的记忆评估
  • 缺乏标准化、被广泛认可的记忆系统评估协议
  • 各论文采用的指标（F1、BLEU、ROUGE、GPT-Judge、LLM-as-a-Judge）不统一，可比较性差
  • 部分论文自行构建了私有评估集，进一步加剧了生态碎片化
  • 值得注意的例外：Memanto 的五阶段递进消融（Naive Baseline → Recall Expansion → Prompt Optimization → Maximum Recall → Model Upgrade）提供了一个系统性的归因方法论，用于区分”架构贡献”和”配置贡献”，这一评估思路值得推广

3.2 对底层 LLM 的隐式依赖

几乎每篇论文的记忆系统都在某些关键步骤依赖 LLM 推理：

  • A-Mem 的链接生成、HiMem 的事件边界检测
  • D-Mem 的门控评估、AMA 的 Judge/Refresher 判断
  • HeLa-Mem 的蒸馏、TriMem 的 TextGrad 逆传播
  • GAM 的 Researcher 规划/整合/反思循环
  • Memanto 虽在检索阶段使用确定性 ITS（信息论搜索，零 LLM 调用），但在查询时仍依赖 LLM 作为最终内容过滤器

这引发了一个根本性问题： 记忆系统的性能提升有多少来自架构本身，多少来自更强的 LLM backbone？这种依赖性在跨模型迁移时是否成立？随着 LLM 能力提升（如上下文窗口扩展），部分记忆机制的价值可能被稀释。

值得关注的例外： Memanto 的 ITS 引擎在检索路径上是完全确定性的——基于 MIB 二值化和按位距离度量，不依赖向量索引、LLM 实体抽取或图谱遍历。这证明了”记忆检索可以脱离 LLM 独立运作”的设计空间存在，是当前少数尝试将记忆系统的”非 LLM 部分”与”LLM 部分”明确分离的工作之一。

3.3 缺乏对记忆写入路径的安全性研究

除 “Remembering More, Risking More” 外，几乎全部聚焦 读取路径（检索→推理），对 写入路径（记忆的创建、更新、合并）的安全风险关注不足。具体包括：

  • 记忆投毒（memory poisoning）——恶意内容可通过记忆写入影响后续决策
  • 对抗性记忆注入——微小的输入扰动导致有毒记忆被存储
  • 跨会话信息泄漏——一个 session 的记忆被另一 session 不当检索
  • 版本回滚攻击——强制系统使用过期信息

3.4 遗忘机制的系统性缺失

虽然多篇论文提到了遗忘的概念，但主动遗忘的深入研究仍然缺位：

  • 大多数系统通过隐式机制（LRU、预算约束、top-k）实现被动遗忘
  • 很少有系统研究 “何时忘记” 与 “记住什么” 同等重要这一角度
  • 遗忘策略与下游任务性能之间的因果关联未建立
  • 认知科学中的记忆巩固和再巩固（reconsolidation）机制尚未被充分借鉴
  • 哪些信息应该优先遗忘的标准缺乏理论支持

3.5 多场景泛化不足

各论文通常针对特定场景设计，泛化能力未系统验证：

  • 对话记忆系统 → 在工具使用、代码生成、多模态任务中表现未知
  • QA 优化系统 → 在开放生成、指令跟随中的性能存疑
  • 缺乏跨场景、跨领域、跨任务的 unified benchmark
  • 单一系统在多个异构任务上的表现极少被同时评估（PlugMem 是例外但场景仍有限）

3.6 可扩展性与资源效率的实证证据有限

  • 大多数评估在中等规模（几千到几万 token）上进行
  • 百万 token 级别的极致长上下文测试较少
  • 记忆规模增长时（从千级到百万级记忆条目）延迟、精度、成本的三维 Pareto 前沿缺乏绘测
  • 生产环境中多用户、多租户的隔离与性能竞争未被讨论
  • 记忆系统的长期运行稳定性（数周/数月）未经受考验
  • 值得注意的例外： Memanto 的零摄入成本和 <90ms 检索延迟展示了效率新边界，其 ITS 引擎的无索引确定性检索设计在实际可扩展性方面具有天然优势——但这一优势仅在目前实验规模上得到验证，在百万级记忆条目规模上的表现仍需实证

3.7 缺乏因果分析视角

现有工作主要关注 相关关系（更好的检索 → 更高的 QA 分数），但因果分析缺失：

  • 是什么具体的记忆机制驱动了性能提升？
  • 不同机制之间的交互效应是什么？
  • 消融研究只回答”有没有它”而不回答”它为什么有效”
  • 缺乏对记忆条目的”反事实推理”——如果这条记忆不存在，回答会有什么不同？

3.8 用户研究与实际部署验证匮乏

  • 几乎所有论文采用自动化基准评估（排除 MemPrivacy 和 Remembering More, Risking More 的部分实验）
  • 真实用户对记忆系统的感知、信任、隐私顾虑未纳入评价
  • 实际部署（超出学术基准）中的系统健壮性未知
  • 记忆错误对用户体验的长期影响缺乏数据
  • 记忆的可解释性和用户可控性（查看/编辑/删除记忆）未被讨论

4. 当下 Agent Memory 研究的共同空白

4.1 ◻ 记忆的理论基础薄弱

Agent Memory 领域缺乏统一的理论框架：

  • 什么是”记忆”在 Agent 语境下的精确定义？它与知识、技能、上下文有何本质区别？
  • 不同记忆类型（情节、语义、程序）之间的计算边界如何划分？
  • 是否存在 Agent Memory 的”记忆定律”或容量边界？
  • 认知心理学中的记忆理论（多重记忆系统、记忆的层次模型）在数字 Agent 中的映射缺乏形式化
  • 图记忆的优劣势缺乏理论边界（现有分析偏实证，如 Does Memory Need Graphs? 所示）

4.2 ◻ 多模态记忆的缺失

现有系统几乎完全基于 文本模态 运作：

  • 视觉记忆（图像、视频帧）在现有系统中缺席
  • 代码结构化记忆（AST、数据流图）与对话记忆的融合未探索
  • 音频/语音记忆被完全忽略
  • 多模态之间的关联记忆（”这张照片是上次会议时拍的”）缺乏支持
  • 多模态输入→多模态回忆（检索到图片/视频片段）的系统不存在

4.3 ◻ 协作记忆与记忆共享

当前系统均为 单 Agent 记忆：

  • 多 Agent 之间如何共享记忆没有系统方案
  • 记忆的访问控制、所有权、共享协议未探讨
  • 记忆的联邦学习或分布式记忆未涉及
  • 人-机记忆共享（用户能否查看/编辑/删除 Agent 的记忆）缺乏设计
  • 记忆的一致性问题在分布式 Agent 系统中完全空白

4.4 ◻ 记忆的情感与个性化维度

  • 记忆系统几乎完全关注”事实”，忽略情感记忆维度（”我记得那次对话让我不开心”）
  • 用户画像过度简化（偏好+事实），缺乏情感的动态建模
  • 情感状态对记忆编码和检索的影响（认知科学已充分证明）未被利用
  • 个性的个性化记忆组织方式几乎空白
  • 不同用户的记忆处理策略偏好未被建模

4.5 ◻ 记忆写入路径的决策理论

  • 绝大多数工作优化检索（读路径），写路径的决策理论不成熟
  • “什么值得写” 缺乏生成性原则（除了 NEMORI 的预测误差和 CMI-Mem 的互信息）
  • 记忆更新策略的长期影响（写一个记忆对未来所有检索的影响）缺乏建模
  • 写操作的事务性、原子性、一致性（ACID 性质）在 Agent 记忆中的映射缺失
  • 多条记忆之间的依赖关系和一致性约束未被建模

4.6 ◻ 记忆与学习的闭环

  • 记忆系统与参数学习（微调）的集成几乎不存在
  • 记忆内容如何指导模型持续学习（continual learning）没有研究
  • 学习后的知识如何回写记忆系统未被讨论
  • MemOS 的 Plaintext ↔ Activation ↔ Parameter 跨格式转换是初步尝试，但缺乏实证验证
  • 记忆→反馈→更新的闭环大多停留在阶段性评估，缺乏在线持续学习

4.7 ◻ 欺骗与对抗鲁棒性

  • 对抗性输入的记忆注入防御完全空白
  • 记忆被操纵后的检测和恢复机制（provenance + audit trail 仅 Zep 和 MemOS 初步涉及）
  • 基于记忆的 Agent 行为操纵（通过植入误导性记忆改变决策）缺乏防御
  • 记忆中毒攻击的纵向影响（”Remembering More, Risking More” 已揭示问题但未提供解决方案）
  • 记忆系统的对抗性测试框架不存在

4.8 ◻ 记忆的元认知与自省

  • Agent 能否意识到”自己记住了什么”以及”记住了错误的东西”？
  • 记忆不确定性（confidence of recall）的建模缺失——检索到的记忆是否可靠？
  • 元记忆（metamemory / memory about memory）：检索策略选择、记忆缺口识别、检索信心判断基本空白
  • 记忆的自我监测和自我修正缺乏系统机制
  • 记忆校准（calibration：准确知道哪些记忆可靠）不存在

4.9 ◻ 记忆的价值与生命周期成本

  • 没有系统的方法来衡量”记忆条目的价值”（ROI of a memory entry）
  • 记忆维护（cleanup、defragmentation、schema migration）的运营成本被忽略
  • 记忆老化与数据生命周期管理在 Agent 语境中缺乏工程设计
  • memory tax（记忆对推理速度和质量的综合影响）不是评估指标的一部分
  • 记忆存储成本 vs 检索收益的经济学分析不存在

4.10 ◻ 标准化与互操作性

  • 缺乏统一的记忆表示格式（AtomMem 有部分尝试但未达标准化）
  • 不同记忆系统之间的互操作性为零——Mem0 的记忆不能在 Zep 中使用
  • 没有标准化的记忆 API（Mem0、Zep、MemOS、AM 各有专有接口）
  • 记忆导出/导入/迁移的工具和格式不存在
  • 缺乏统一的记忆评估框架（类似 GLUE/SuperGLUE 对于 NLP 的意义）

4.11 ◻ 记忆的时间尺度连续体

  • 短时记忆到长时记忆的巩固过程在大多数系统中是离散的、工程化的
  • 缺乏对记忆 时间分辨率 的系统研究——什么粒度的时间戳足够？
  • 记忆的因果关系（A 事件导致 B 事件）在时间轴上的建模缺失
  • 前瞻性记忆（prospective memory：”将来需要做某事”）完全空白
  • 时间推理中的记忆衰退曲线缺乏个性化建模

4.12 ◻ 记忆幻觉与事实性

  • 没有系统研究记忆系统中的”记忆幻觉”——Agent 在回忆时”记住”了未发生的事
  • 记忆的置信度评估与下游推理的事实性之间的关联未建立
  • 记忆污染（多个相似但冲突的记忆）对推理的影响未量化
  • 记忆的正确性校验机制缺乏
  • 外部世界变化后记忆的自动失效检测不存在（除 Zep 的双时模型初步尝试）

5. 总结与展望

5.1 综合评估

上述论文构成了 2024-2026 年 Agent Memory 研究的全景图。该领域正处于从”简单存储检索”向”可学习、自适应、多维度记忆系统”快速演进的过程中。

已取得的进展：

5.2 前瞻方向

  1. 统一记忆理论：形式化 Agent Memory 的容量边界、记忆类型计算划分、记忆行为的预测性理论。认知心理学中的记忆研究成果向 Agent Memory 的形式化映射。

  2. 多模态融合记忆：图像-文本-代码-语音的统一记忆表示与跨模态关联检索，支持多模态输入→多模态回忆。

  3. 写入-读取对称设计：写入路径的安全、价值和生命周期管理与读取路径同等重要——两者需要同等深度的理论研究。

  4. 记忆-学习飞轮：记忆→持续学习→模型更新→记忆增强的闭环。记忆不仅服务于推理，还应该服务于模型自身的持续改进。

  5. Safe Memory by Design：从架构层面保证记忆的隐私、安全和对抗鲁棒性，而非事后修补。

  6. 标准化生态：统一记忆格式（Universal Memory Format）、标准评估协议（Agent Memory Benchmark Suite）、互操作性 API。

  7. 元记忆与自我认知：Agent 对”自己知道什么、不知道什么、记得多准确”的自我监测和调控能力。

  8. 人机记忆交互：用户可理解、可编辑、可信任的 Agent 记忆——包括记忆可视化、编辑界面、选择性遗忘。

  9. 记忆时间连续体：从工作记忆到长期记忆的连续巩固过程，结合前瞻性记忆（prospective memory）和时序因果推理。

  10. 对抗鲁棒记忆：记忆注入攻击的防御、记忆中毒检测、记忆审计跟踪和恢复机制。
