RAG 与 Agent Memory 检索端文献综述（158 篇 · 表格版）

本表只回答一件事：每篇工作检索端做了什么、还卡在哪，方便思考。
语料渠道：Semantic Scholar（关键词检索+批量摘要），日期 2026-08-21。低引/在研项标 [待核]，引用前回原文核对。

0. 思考

「精度 ↔ 构建token ↔ 检索token」三者之和近似守恒（油桶定理）：写端多抽特征/建图→构建token涨、精度涨；查端多查询/分解→检索token涨、精度涨；压token→省这边、掉那边。同时满足三指标 = 打破守恒，必须靠「零边际token换高信息增量」的机制（写端去LLM化+懒构建、查端一次扩散、查询侧对齐）。

A. RAG

a1 经典RAG

论文检索端贡献未解问题 / 局限性
RAG（Lewis 2020）[17337]确立「双塔检索器 + 生成器联合训练」范式；知识外挂、可更新单次固定 top-k，无「该不该检索/够不够/要不要下一跳」；分块粒度是超参；无结构化、无遗忘/更新
RETRO（Borgeaud 2022）[1841]事实库前缀匹配 + chunked cross-attention；检索通道独立于参数记忆，可增量检索表征建库时冻结、不随任务自适应；字面相近语义相远时泛化差；需大库
RAG 综述（Gao 2023）[3911]Naive/Advanced/Modular 三分类；给出检索粒度、重排、融合等轴盘点性；未把「构建token成本」列为评测轴
RAG for AIGC 综述（Zhao 2024）[679]跨模态同一套「检索-融合-生成」；检索当作可溯源来源纯盘点；未提多查询vs token 权衡
RAG for NLP 综述（Wu 2024）[160]系统梳理检索时机/对象/融合/迭代检索默认「检索质量≈下游精度」；未把检索token当可优化目标
Knowledge-oriented RAG 综述（Cheng 2025）[72]知识组织（KG/向量/混合）与检索解耦暗示「组织形式越好检索越好」，但组织形式越好好建越贵——正是你的矛盾
Trustworthiness RAG 综述（Zhou 2024）[123]检索正确性/鲁棒性/可溯源维度可信与token负相关（多校验多token），无联合权衡
RAG 系统综述（Brown 2025）[53]整理 metrics-challenges 清单无 token 成本轴
RAG 最佳实践（Li 2025）[58]经验式：检索器选择/切片重叠/查询预处理/重排纯经验局部；无法三指标同时逼
Retrieval meets Long Context（Xu 2023）[142]RAG vs 长上下文：检索到正确片段足够时小模型也能逼近长上下文检索靠硬切分；长上下文模型对位置敏感

a2. 增强 / 自适应 / 自反思 RAG（精度主流线：几乎全用token换精度）

论文检索端贡献未解问题 / 局限性
Self-RAG（Asai 2023）[2417]训练LLM输出[Retrieve]+评审token，自问「要不要搜、搜到是否有用」要训一个带评审头的critic；评审框架本身就烧token；评审针对外部语料，未处理写端丢信息
CRAG（Yan 2024）[273]轻量检索评估器分Correct/Incorrect/Ambiguous，分别用/补/重检索+去噪再融合评估器额外训练/规则；Incorrect分支拉高检索token；纠正的是「查询错了」非「写入记错了」
Active RAG / FLARE（Jiang 2023）[801]用生成置信度/熵在线决定是否继续检索依赖置信度信号可靠性；每多一次检索多一轮生成+注入；决定「翻不翻记忆」也要烧一次LLM
RAFT（Zhang 2024）[382]训练期造「相关+干扰混合」，让生成器学会抗噪挑有用需领域微调；只作用生成期注意力，对检索器召回差无能为力；不省token
HyDE（Gao 2022）[868]用LLM把query改写成假想文档再做embedding，对齐问答表达鸿沟改写=一次LLM生成（构建token）；假想文档会跑偏；对记忆最不匹配——记忆不是「答案」
SeaKR（Yao 2024）[55]感知知识边界/不确定度决定是否检索兜底靠LLM判断；省token以「自我评估可靠」为前提
MBA-RAG（Tang 2024）[40]bandit按问题复杂度学「是否检索/轮数」，成本做进奖励只有「要不要检索」二元；成本-精度连续权衡没建模；记忆复杂度如何定未解
Adaptive RAG 会话（Wang 2024）/RetrievalQA（Zhang 2024）多轮判断是否更新检索；专门评测自适应收益多轮重复检索、历史累积；「何时翻记忆」仍启发式
CDF-RAG（Khatibi 2025）/ SARA（Jin 2025）/ MAO-ARAG（Chen 2025)因果动态反馈修正检索；选择性检索+上下文压缩；多代理编排检索都以多轮/多代理/多次压缩为代价；SARA压缩有损；多代理对单机记忆过重
RAT（Wang 2024）[104]检索从一次性前置拆成推理链上逐步「检索-再生成」极费token（每步检索）；对记忆多跳=多token，正中你痛点
ReaRAG / AirRAG / ThinkRetrieve（2025-26）迭代检索+知识引导；自主规划检索；增强推理迹「越多轮越好」，token与精度近似线性；不符合「检索token不变」
Question Decomposition（Ammann 2025）/ AtomRAG（Igolnikov 2026）/ Query Expansion RL（Zhao 2025）复合问题拆原子子问题；LLM查询改写；RL训练查询扩展就是你「多查询提精度但费token」的直接来源；子问题间重复检索；分解假设问题可分解为多跳
Search-in-the-Chain（Xu 2023）[45]生成链中动态插入检索节点，可溯源链越长token越多；中间态检索不可复用
Adaptive w/o Self-Knowledge（Moskvoretskii 2025）[39]指出自我评估不可靠，改用检索不确定性做零样本信号不确定性信号仍要算（成本）；记忆上未验证
SegMem-RAG（Fan 2026）[1]记忆分段+自适应[待核]；分段/选段仍启发式

a3. 图 / 知识图谱 RAG（用结构化换可达性，但建库巨贵）

论文检索端贡献未解问题 / 局限性
Graph RAG 综述（Peng 2024）[543]、定制综述（Zhang 2025）[138]、Graph Agent Memory综述（Yang 2026）[17]确立「建图-社区/子图/路径检索-生成」；图显著提升多跳/关联可达性建图token成本惊人（实体抽取/关系识别/共指消解/社区摘要全靠LLM）；选错子图引入噪声。完美命中你的矛盾
LightRAG（Guo 2024）[423]图+向量双通道；查询相关的局部图检索替代整库社区摘要，省token仍要LLM抽实体建图（构建token没省）；跨子图问题召回有限
G-Retriever（He 2024）[341]检索文本图上的问答子图再喂LLM子图检索每问题一次、可复用差；建图未省
Medical Graph RAG（Wu 2024/2025）[173/99]、MedRAG（Zhao）医学证据链图谱+图上证据检索，提高可信/可溯领域KG构建贵需人工校验；领域特定非通用
Think-on-Graph 2.0（Ma 2024）[92]、G-Refer（Li 2025）[63]、GFM-RAG（Luo 2025）[42]、GraphRAG-R1（Yu 2025）[12]沿图推理检索；可解释推荐检索；图基础模型编码；RL约束图检索全是「图检索轮数越多越准」；建图/沿图/每跳都烧token；全部超过「检索token不变」
HyperGraphRAG（Luo 2025）[69]、PathRAG（Chen 2025）[77]、LinearRAG（Zhuang 2025）[41]超图承载n-ary事实；关系路径剪枝省无关边；线性索引替代庞大图索引剪枝/线性化省token但丢召回；建图仍是LLM大户
When to use Graphs in RAG（Xiang 2025）[44]定量分析「图RAG何时真的比向量好」结论是并非必然；提醒你别默认用图（图RAG踩中构建token高的坑）
GraphRAG-Bench（Xiao 2025）[24]领域推理图RAG评测基准评测不带token成本轴

B. Agent Memory 框架 / 抽象

论文检索端贡献未解问题 / 局限性
MemGPT（Packer 2023）[1146]LLM当OS，显式分「main context受控窗口 / external memory分页」；工具调用做内存换页；分级内存母版策略全在推理时学（何时归档/翻页靠提示）；archive靠LLM总结→构建token大户；key-based search命中差；几乎不解决「写入是否可检索」
Generative Agents（Park 2023）[5219]记忆流+检索三重评分（相关/新颖/重要）+反思（综合成高层抽象）+计划反思与检索评分全用LLM，token极贵；重要度打分主观且每次要算；写端丢细节
MemoryBank（Zhong 2023）[621]记忆增强+遗忘曲线定重要性/衰减，检索按时效加权遗忘参数人工；记忆是「日结摘要」，写端丢细节
Mem0（Chhikara 2025）[560]免训练增量；每条对话LLM提取atomic facts（add/update/delete）+去重冲突；向量+语义聚类检索提取atomic fact一步是纯LLM，构建token高；去重/冲突靠LLM判断，写错丢事实；跨事实组合推理弱。你最直接的对位baseline
A-MEM（Xu 2025）[901]Mem0+Zettelkasten动态笔记连接+记忆演化，检索沿笔记链展开连接/演化全由LLM决定，构建token更高；链式检索噪声累积（从错邻居扩散）
HippoRAG（Jimenez 2024）[325]神经隐喻：海马体索引PPR（个性化PageRank）+开放KG+LLM链接实体；单次检索即多跳，省多轮检索离线建KG用LLM做实体链接，构建token高；PPR是检索端创新，但建图代价没省；新观察需增量链接
Zep / Graphiti（Rasmussen 2025）[320]时态知识图：实体/关系/时间戳/有效区间；检索做时间感知+图遍历，对抗事实漂移/矛盾（越新优先）构建仍是LLM抽triple/对齐/判冲突，构建token成本存在；时态图检索需额外维护；最适合长期经历型，事实型QA未必最优
MemOS（Li 2025）[52]OS式内存可执行token+复用/压缩统一调度工程重；写端仍靠LLM生成可执行token
Memory机制综述（Zhang 2024）[723]、Externalization（Zhou 2026）[48]、From Storage to Experience（Luo 2026）[18]按写/存/取分层；外化（memory/skill/protocol）梳理；记忆四步抽象综述无联合成本-精度权衡；指「写端决定检索上限」但未给代价模型
SCM / 无限长SCM（Liang 2023）[95/44]自控记忆框架+分层摘要，破上下文窗口，记忆归纳复用归纳靠LLM；摘要丢细节
Hello Again!（Li 2024）[142]、In Prospect&Retrospect（Tan 2025）[112]、Timeline Memory（Kim 2024）[41]、动态人记忆（Hou 2024）[56]长对话个性化：用户画像+时间线+回顾/前瞻反思；何时回顾用LLM决策全靠LLM反思/画像，构建token高；时间线检索对非时间性知识弱；多用户不通用
MIRIX（Wang 2025）[144]、MemAgent（Yu 2025）[195]、HiAgent（Hu 2024）[98]多代理记忆；多卷积RL记忆代理；分层工作记忆管理长程任务多代理=多LLM调用token翻倍；RL训练贵；分层要判断「该放哪层」（烧LLM）
Evo-Memory（Wei 2025）[113]、Memory-R1（Yan 2025）[176]、Memory Matters（Hatalis 2024）[117]、How Memory Mgmt Impacts（Xiong 2025）[83]把「test-time记忆进化」当评测与优化目标；RL让模型学会记忆-检索-利用；经验研究记忆管理影响RL训练token不计入运行时构建token；评测把「进化本身」当指标；构建vs检索token比无标准
M+ : MemoryLLM（Wang 2025）[42]记忆在模型参数/隐藏态中，检索=从参数记忆读；可扩展长程记忆参数化记忆难解释难增量；改一条要重训；构建成本与精度耦合不透明
Agentic Memory（Yu 2026）[50]、ActMem（Zhang 2026）[3]、主动记忆提取（Yang 2026）[14]统一长短期记忆管理；弥合检索与推理衔接；对话中主动判断并写入[待核]；主动提取=每条写端烧LLM；「何时值得记」仍靠LLM
AtomMem（Yao 2026）[1]、ByteRover（Nguyen 2026）[1]、H-Mem（Yu 2026）[2]、SGMem（Wu 2025）[28]、Editable Memory Graph（Wang 2024）[43]、DimMem（Qiu 2026）[1]atomic facts高效检索；LLM策展分层上下文；混合结构演化检索；句子图跨句检索；可编辑图RAG；维度结构化都靠LLM提特征/建图；「结构化提检索 ↔ 结构化费构建」这一对矛盾没一篇真正解开。适合做消融对照

C. 记忆构建 / 巩固 / 压缩

论文检索端贡献未解问题 / 局限性
MemRefine（Kim 2026）[2]用LLM引导的记忆压缩，压成长记忆以省上下文[待核]；压缩那步就是构建token——把成本从「检索端」搬到「构建端」，恰与你要的目的相反。警惕这类
RecMem（Dai 2026）[3]递归式巩固记忆（过去记忆状态作递归输入），降低重复总结成本[待核]；递归巩固=记忆仍反复过LLM；递归状态累积误差
Lightweight Memory w/ Small LLM（Zhang 2026）[6]用小模型替代大模型做写端，直接降构建token[待核]；小模型写端表征弱→检索命中降；「以小换省」没给出精度不掉的证据
Decision-Theoretic Memory（Sun 2025）[4]把记忆力管理形式化成决策论cost-benefit框架[待核]；理论好但「信息价值」估计难落地；未给可测token metric
ChronoMem（Su 2026）[1]、TA-Mem（Yuan 2026）[2]、Persistent Memory Modeling（Ying 2026）版本控制+语义回滚；工具增强自主记忆检索；长时程持久记忆建模[待核]；版本/回滚=写端冗余；持久建模=策略级LLM
Memory Grafting（Cheng 2026）[1]、Pre-training Limited-Memory LM（Zhao 2025）[9]、Pretraining Context Compressor（Dai 2025）[25]离线条件记忆嫁接预训练；内部+外部知识；embedding-based记忆+压缩器预训练都是训练期方案，记忆更新需重训/缺柔性；预训练压缩器与运行时增量写不匹配。Dai 2025最小接近你想要的「写端免LLM总结」
Neural Procedural Memory（Zhao 2026）、Hindsight（Latimer 2026）、Validation-gated Hebbian（Singh 2025）隐式激活引导；结构化保留-回忆-反思；验证门控Hebbian（受奖励门控更新）[待核]；激活/反射式可解释性差；Hebbian门控仍要验证信号
Learning to Learn from Experience（Ferraz 2026）[5]把过去经验当检索源，训练模型学会调用经验检索的写端提取仍是LLM
Filesystem-based Memory（Zhou 2026）用文件系统分层组织记忆，省检索成本[待核]；组织靠命名/分类，写端仍要判断

D. 上下文压缩 / token效率 / KV cache

论文检索端贡献未解问题 / 局限性
xRAG（Cheng 2024）[137]一键压缩把多段检索结果压成极少数token再喂生成器，省上下文注入token压缩用可学习tokenizer需训练；压缩丢信息；省的是「注入token」非「构建/检索MIPS token」—需先定义口径
Landmark Embedding（Luo 2024）[19/17]、BGE Landmark免分块embedding，用landmark token做长文本锚点，打破chunk割裂需可学习编码；整段过长仍丢细；是「写端不分块保召回」代表
Semantic Compression（Fei 2023）[59]语义压缩扩展上下文窗口，通用LS=压缩token有损；与记忆检索弱相关
MiniCache（Liu 2024）[145]、D2O（Wan 2024）[27]、LISLLM、KV-CAR、Sliding Window（Fu 2025）[23]KV cache深度压缩/动态丢弃/滑窗——省长上下文推理显存与token运算在推理/KV层省，不是「构建省LLM」也不是「检索省查询」；对记忆构建无帮助；精度有损。需与构建/检索端严格区分
AdaComp（Zhang 2024）[10]自适应抽取式上下文压缩（adaptive predictor判断压哪些token）以压缩丢信息为代价；压缩决策需额外预测器
Prompt Compression实证（Zhang 2025）[10]系统评估prompt压缩的质量-成本结论是压缩有损
Token Compression多模态综述（Shao 2025）[19]、Context Compression&Extraction（Zhou 2024）[2]、ILRe（Liang 2025）[1]token压缩分类；中间层检索压缩；上下文压缩与抽取多模态/推理层；对「构建token」无直接改观

E. 长上下文 vs RAG / Lost-in-the-Middle

论文检索端贡献未解问题 / 局限性
Lost in the Middle（Liu 2023）[4723]实证LLM对上下文中间位置的证据利用率最低只揭示位置问题，给重排/可训练位置编码缓解；对记忆：检索到的记忆放哪个位置直接决定有没有被用上→「检索到≠被用上」
Retrieval meets Long Context（Xu 2023）[142]RAG与长上下文模型对比（见A表）检索硬切分；模型对位置敏感
LaRA（Li 2025）[33]基准发现 LC与RAG无银弹，需按任务路由路由本身要判别（烧token）
Eliciting In-context Retrieval（Qiu 2025）[14]、Found in the Middle（Zhang 2024）[92]诱导长上下文模型在上下文里检索（免外挂检索器）；可插拔位置编码修偏差诱导依赖长上下文模型本身；位置编码需微调

F. 检索器基础 / 评测基准 / 鲁棒（「精度不高」的口径问题在基准）

论文检索端贡献未解问题 / 局限性
DPR: Is it Retrieving?（Reichman 2024）[21]批判验证DPR可能在学表层词汇/结构而非语义直接支撑「检索到≠命中语义」，是精度低隐性原因
PLAID/ColBERT（Santhanam 2022）[178]后期交互token级精准相似但可规模化计算成本换精度；写端embedding到token级+密集
RAGAs（Shahul 2023）[944]LLM-as-judge三指标（faithfulness/answer/context relevance）评测靠LLM，本身烧token；不测构建/检索token
Benchmarking RAG-LLMs（Chen 2023）[637]系统测各模型RAG能力（含噪声/缺失场景）实证「RAG提升有限」
RAGBench（Friel 2024）[133]、MultiHop-RAG（Tang 2024）[318]、Med/chem基准（Xiong/Zhong 2024-25）各领域多跳基准不带token成本轴
MTRAG（Katsis 2025）[80]、LONG²RAG（Qi 2024）[36]、UDA（Hui 2024）[57]多轮/长上下文+长答案/真实文档分析不带token成本轴
Very-Long-Term Conv Memory LoCoMo（Maharana 2024）[756]、Beyond a Million Tokens（Tavakoli 2025）[41]、Mem-Gallery（Bei 2026）[32]、MIRAGE（Park 2025）[19]长对话/百万级长记忆/多模态记忆基准几乎全部只报accuracy/recall/F1，不把「构建token」「检索token」做报告维度，更无三元帕累托前沿
FlashRAG（Jin 2024）[227]模块化RAG工具箱，便于拆装检索器/重排/生成工具，不解决权衡
AgentIR（Yuan 2026）[1]工作量自适应级联检索基座[待核]；级联多级才省；自适应仍有判断
SafeRAG（Liang 2025）[42]、RARE（Zeng 2025）[10]、PoisonedRAG（Zou 2024）[282]、知识投毒防御（Edemacu 2025）、TrustRAG（Zhou 2025）[29]检索抗污染/安全/鲁棒与「token优化」正交

全领域共同局限

#共同局限一句话解释思考
L1写端信息损失是精度天花板RAG/Memory写入都先压缩/结构化（atomic fact、三元组、摘要、维度、子图）→天然丢信息；检索器再强也只能找回已丢的东西。大家却把精度低归因于「检索器差」解释「精度不高」：不是查错，是写端先丢。Agent Memory的精度提升不能靠优化检索器单方面实现
L2「精度↔构建token↔检索token」守恒（油桶定理）写端加料→构建token涨精度涨；查端加料→检索token涨精度涨；压token→掉精度。没一篇把三者当同一优化问题的帕累托目标\
L3查询-记忆语义鸿沟，多查询是暴力对齐查询与记忆两种表述不同调→只能多查询/改写/分解（HyDE/decomposition）去暴力覆盖，撞上就准、撞不上浪费token直接解释「多查询提精度但费token」：多查询是暴力对齐，不是真对齐
L4检索粒度单一 vs 多粒度代价每种方法默认一种粒度（chunk/fact/node/summary/landmark）；单一粒度无法同时「细粒度命中+全局关联」；多粒度=多层构建+多层检索token一个事实该存哪个粒度，写端难一次定对
L5写端「要不要记、怎么记」全靠LLM「提取什么、建什么边、去不去重、反不反思」几乎全是LLM调用；每写一条至少一次LLM构建token大的主因；降写端需要LLM调用次数/长度
L6检索「查不查、查多少」的决策也都是LLM/启发式Active/FLARE/Self-RAG/CRAG/MBA用LLM或启发式决定；决策本身也算检索token；几乎无人在「本次信息增量 vs 本次token」间建模需要按信息增量分配固定检索预算
L7检索到≠被用上检索命中但放prompt中间→生成器忽略（LITM）；检索含噪→抗噪差（RAFT）不加工token提精度的最大杠杆，却被大多数RAG论文忽略
L8评测口径不报token，且评估本身烧tokenRAGAs等用LLM-as-judge（评估也在烧token）；无基准同报「构建token/检索token/精度」三维\
L9泛化vs特制高精度方案多绑特定领域/任务（医疗/法律/电商/对话/多跳）；通用、token感知、跨记忆类型的抽象几乎不存在Agent Memory不应当是只适配几个数据集，而是要做到适配到日常生活中

缺口 → 你的创新点落点

你的指标缺口建议落点
构建 −50%写端LLM化（L5）；构建token没被当优化目标①写端去LLM化：规则/轻量模型/编码器生成「免调用又保信息」的表示（参考Dai 2025 embedding记忆+可学压缩器）；②懒构建/惰性索引：先无损裸存，查到再按需结构化（与LazyMem撞车方向一致——要用「懒=不丢信息、查询驱动」区分）；③构建预算作一等约束（把MBA-RAG的bandit迁到写端）
检索不变查询-记忆鸿沟（L3）；检索决策不建模信息增量（L6）①一次seed图扩散替代N次查询（HippoRAG先例：一次MIPS/PPR覆盖多跳）；②写端以「查询侧语义」为坐标建索引，单次查询即对齐（替代HyDE查端生成）；③检索预算按信息增量自适应（固定token预算，按增益定查几条）
精度 +20%写端信息损失（L1）；检索到≠用上（L7）①无损/低损压缩编码（不是总结丢细节）；②注入位置优化（关键记忆放首尾高利用区）+轻量抗噪（RAFT）；③可归因诊断（写错/查错/读漏），既是卖点也帮定位-50%

一句话创新点（供打磨）：「写端非失真 + 查询侧对齐 + 检索端图扩散」的懒构建记忆系统：平时零/极低LLM成本无损写入；检索时一次seed扩散完成多跳、以查询侧语义坐标对齐单条、按信息增量分配固定检索预算；评测首次同报「精度×构建token×检索token」并给帕累托前沿——从而在构建token −50%、检索token不变下实现 QA精度 +20%。

下一步建议

  1. 先定「检索token / 构建token」精确口径（决定能否论证「检索不变」）：建议 构建token=写入一次LLM输入+输出；检索token=每问题的查询改写/分解token + 注入上下文token（不含生成答案）。并同报三者+精度。
  2. 三角对位baseline：Mem0（写端结构化、构建贵）、HippoRAG（检索端图扩散省检索）、Zep（时态图、构建尚可）——三篇各踩你一根轴。
  3. 优先攻「懒构建 + 查询侧对齐 + 一次扩散检索」，这是唯一能在守恒外同时满足三指标的机制。
  4. 做可归因诊断实验（写错/查错/读漏），把「精度低」归因清楚——既是卖点，也帮你定位 −50% 从哪来。
