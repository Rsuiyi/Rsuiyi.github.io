第一部分 · 综合分析

Agent Memory 检索端 文献综述：检索器特点、局限与共同局限性

范围：RAG 检索算法检索器 + Agent Memory 系统检索器。以下为综合分析，逐篇明细见第二部分。

0. 一句话结论

无论稠密、稀疏、重排、多跳、图、记忆还是条件/结构系统，几乎所有检索器都把”检索”当作 query 与 memory 之间的（主题/形状）相似度排序，用嵌入余弦 + top-k 完成。只有极少数（如 09 的 Entailment Tuning）把”检索”当作证据必要性推断（passage 是否蕴含可推导的答案），但其代价是要么停留整段级、要么训练一个模型。由此衍生出 6 条（L1–L6）跨家族、跨范式的共同局限——它们严格对应你观察到的现象（top-k 前几条不是真正想要的；多跳依据句缺失）以及”多查询能涨精度但费 token”的权衡。

2. 所有论文身上的共同局限（跨家族、跨范式）

L1 —— 检索被当作”相似度回归”，而非”证据必要性推断”

  • 几乎所有稠密编码器（DPR/Contriever/GTE/E5/SBERT/ColBERT/BGE-M3/Qwen3-E，01）都在 （question, passage）对比/释义目标上训练；监督单元是”这段文字与问题主题相近”。这造成第一层错位：检索器排的是”主题相似”，不是”足以作答”。
  • “取相关而非相似”并非真空。 08 与 09 共同揭示：确实存在真实、有名字的少数派方向，把 relevance 当作蕴含/答案可推导——旗舰是 Entailment Tuning（EMNLP 2024，把”passage 蕴含可推导答案”当正负监督）与 ARHN（CIKM 2026，以”能否出答案”重标定困难负例）；”相似≠相关”也被 2502.15025 明确命名。这说明”相关≈证据必要”是有文献支撑的直觉，不是孤例。
  • 但这一格没有占满。 这些做法几乎都要训练一个模型（NLI/cross-encoder/LLM 重标定），且停留整段级，监督单元是”passage 蕴含可推导答案”，从未以（疑问句 → 去语境化独立答案句）为监督单元、也从不做原子句级软条件包含；同时”相似 vs 相关”常被混同（MMR 的”相关”仍是余弦；多数记忆系统嘴上说 relevance 实为 cosine）。因此真正的缺口是 免训练 × 原子句 × 结构条件包含——而不是”从没人用答案可推导当监督”。
  • 2026 的低 token 记忆系统也没有填这一格。 05 的 Zero-Mem（零 token 记忆操作）、LazyMem（宽检索 + 选择性构造）、MRAgent（主动重建）都在猛攻”token 成本 × 精度”，但底层仍是 BM25+稠密相似、主动检索或选择性构造——没做”用条件包含而非相似”。所以”免训练 × 结构条件包含 × 构建端双层”至今仍无对应工作。
  • 条件/结构一支也未占满。 10 的 QO-Bench、HCQR、Retrieve-and-Fill、SchemaRAG、QBBN 确实把查询拆成条件/槽位/逻辑式来匹配——但它们要么靠训练模型或专门解析器（SchemaRAG 微调、QBBN 需语法引擎）、要么绑死特设领域（task-oriented、text-to-SQL、事件元组）、要么仍是逐查询改写（HCQR 每查询 3 次改写 + 检索）——没有”免训练 × 原子句 × 对齐到自建双层记忆 × 单遍”的版本。

L2 —— 余弦相似度的 top-k 返回的是”最相似”，不保证”答案就藏在其中”

  • 这是 AMem/Mem0/MemGPT/Generative Agents 等记忆系统检索端的共同批评（05 综述 #16 直接把”top-k 抓不到真证据”列为领域级弱点）。A-Mem 的多维属性（keywords/tags/description）能缓解，但删掉属性检索质量明显下滑——而这些属性恰恰是构建 token 的成本来源。
  • 拓扑型召回 vs 主题型召回：余弦相似度衡量的是主题密度，不是”这条是否在答案的推理路径上”（04 中 Simple-is-Effective、MuSiQue、GRITHopper 都印证）。

L3 —— 多跳的”中间事实”因与问题不相似，首轮 top-k 直接丢失

  • 这是整条多跳/图流派的开创动机（04）：MuSiQue 用”单跳子问题准确率”直接量化；HippoRAG/Simple-is-Effective 证明图的边际价值几乎全在”搭桥可达”；IRCoT/Self-Ask/FLARE 只能靠每跳额外付一次 LLM + 检索来补。HippoRAG 用单遍 PPR 以 ~1/10–1/30 成本匹配 IRCoT——但需离线建知识图谱（LLM 抽取），与持续更新的 agent memory 冲突。
  • 思考：句原子 + 余弦会把”想回答一个事实”切到多句，所以应当进一步思考如何尽可能消除”指代/实体重复”这一廉价又冗余的搭桥信号。

L4 —— “多查询/多跳能提升精度，但以 token 为代价”——token 侧没被量化

  • 质量侧被反复验证：Self-RAG 反思 token、LongMemEval 的时间感知查询扩展、Zep（+18.5% acc on LongMemEval）、CRAG 修正。但没有任何论文给出干净的”每精度点对应 token”表；token 侧通常被描述为延迟或定性（06 #17、#19 明确指认这是一条公开空缺）。PRISM 是在”严格上下文预算下”做同类事的第一批，占据”accuracy×context-cost 前沿的空角”。

L5 —— 预算化检索选择存在，但优化的是密度/效用，不是”正确性”

  • Bala（Recall Is Not Enough）、AdaGReS、M-RAG、SAGE、When-Knowledge-Is-Not-Free（07）确实把”固定 token 预算下打包上下文”建模为子模/效用优化，但都优化表面证据召回/相关性/读者置信度。没有一个优化”打包上下文足以使生成器答对”的校准概率——是密度/效用玩法，不是正确性保证。
  • VOI/信息增益选择存在但碎片化且昂贵：InfoGain-RAG 的 DIG 需每文档一次前向；VOILA/Know-Before-You-Fetch 用 VoI/校准不确定性做预算/保真分配，而非”哪条证据信息量最大”；GIP 只用于训练数据。”对检索集合的每 token 信息增益“这一目标仍被欠服务。

L6 —— 便宜信号有天花板：压缩/便宜重排无法找回已丢弃的证据

  • gist/LLMLingua/Matryoshka 截断/SAGE 注意力热图/便宜一阶检索器（07）都把 token 或算力省下来，但一旦证据在生产端被扔弃，任何便宜信号都救不回。因此 token 效率与多跳精确性在整条文献里是直接张力——直到今天没人打破。agent memory 里，”保存更少 token”与”抓准多跳证据”是同一个问题的两面。

第二部分 · 逐篇明细

01 — 稠密 vs 稀疏检索编码器

子主题：嵌入型检索模型（稠密双编码器、学习型稀疏、多向量晚交互、度量/压缩空间），对 Agent Memory / RAG 检索器设计相关（查询与记忆语句的相关性错配、精度/召回、token 成本）。
下文每篇：机制（1 句）与局限（1 句）。所有论文经 Semantic Scholar MCP（search_papers/get_paper）检索；ID 为真实 Semantic Scholar(以下简称S2) paperId；arXiv/DOI 尽可能给出。标题中括号内为原文。

1. 密集段落检索用于开放域问答（Dense Passage Retrieval for Open-Domain Question Answering 《DPR》)

  • 一作 / 会议 / 年份： Vladimir Karpukhin · EMNLP · 2020
  • ID / arXiv / DOI： paperId b26f2037f769d5ffc5f7bdcec2de8da28ec14bee · arXiv:2004.04906
  • 机制： 双 BERT 编码器把问题和段落嵌入同一稠密空间，以内积相似度检索。
  • 局限： 单向量压缩把一整段压成一个点，所以”主题匹配的句子”即使作答句缺失/被埋没也会排前——是语义匹配，不是证据匹配。

2. RocketQA：面向稠密段落检索的优化训练方法（RocketQA: An Optimized Training Approach to Dense Passage Retrieval）

  • 一作 / 会议 / 年份： Yingqi Qu · NAACL · 2021（arXiv 2020）
  • ID / arXiv： paperId f2c1ab4e850ad89bd6b6b9908e12a4151d152070
  • 机制： 用困难负样本 + 交叉编码器重排 + 去噪批次内负样本训练稠密检索器。
  • 局限： 需要昂贵交叉编码器蒸馏/过滤来造标签；仍是单向量，保持”主题相似但不可作答”的失效。

3. 无监督稠密信息检索（Unsupervised Dense Information Retrieval with Contrastive Learning 《Contriever》)

  • 一作 / 会议 / 年份： Gautier Izacard · arXiv/TMLR · 2021
  • ID / arXiv： paperId 4f4a409f701f7552d45c46a5b0fea69dca6f8e84 · arXiv:2112.09118
  • 机制： 无监督对比训练（动量编码器），用随机/增强文本跨度合成正负例，无标注负样本。
  • 局限： 对比目标奖励的是释义/主题相似，所以会排”形状像查询”的句子，而非”事实作答”的那句。

4. ColBERT：通过语境化晚交互实现高效有效段落搜索（ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction）

  • 一作 / 会议 / 年份： Omar Khattab · SIGIR · 2020
  • ID / arXiv： paperId 60b8ad6177230ad5402af409a6edb5af441baeb4 · arXiv:2004.12832
  • 机制： 晚交互——把查询和文档编码成逐 token 向量，用 MaxSim 词级交互打分，不做单向量压缩。
  • 局限： 词级向量精度高，但存储与逐查询计算远高于单向量模型（检索的 token 成本）。

5. ColBERTv2：通过轻量晚交互实现有效高效检索（ColBERTv2: Effective and Efficient Retrieval via Lightweight Late Interaction）

  • 一作 / 会议 / 年份： Keshav Santhanam · NAACL · 2022
  • ID / arXiv： paperId 590432f953b6ce1b4b36bf66a2ac65eeee567515 · arXiv:2112.01488
  • 机制： 同一 MaxSim 晚交互打分，用残差预测压缩 token 嵌入。
  • 局限： 压缩相对未压缩 ColBERT 削减精度，且语料仍每 token 存一个向量，索引规模与查询成本高。

6. SPLADE：用于第一阶段排序的稀疏词法与扩展模型（SPLADE: Sparse Lexical and Expansion Model for First Stage Ranking）

  • 一作 / 会议 / 年份： Thibault Formal · SIGIR · 2021
  • ID / arXiv： paperId 1e8a6de5561f557ff9abf43d538d8d5e9347efa0 · arXiv:2107.05720
  • 机制： 学习型稀疏——BERT 的 MLM 头配合 splade 算子，把查询/文档展开为词项权重向量，经倒排索引点积打分。
  • 局限： 词项扩展加入大量非关键词权重导致索引变大；词法式打分在”释义/词汇不匹配作答句”时仍失效。

7. Sentence-BERT：使用孪生 BERT 网络生成句嵌入（Sentence-BERT: Sentence Embeddings using Siamese BERT-Networks）

  • 一作 / 会议 / 年份： Nils Reimers · EMNLP · 2019
  • ID / arXiv： paperId 93d63ec754f29fa22572615320afe0521f7ec66d · arXiv:1908.10084
  • 机制： 孪生/三元组 BERT，每句产生一个均值池化 768 维向量，用余弦打分；是池化「工作马」。
  • 局限： 把所有 token 池化到一个点，只要查询匹配段落主题，无论作答句是否存在都打高分。

8. SimCSE：句子嵌入的简单对比学习（SimCSE: Simple Contrastive Learning of Sentence Embeddings）

  • 一作 / 会议 / 年份： Tianyu Gao · EMNLP · 2021
  • ID / arXiv： paperId c26759e6c701201af2f62f7ee4eb68742b5bf085 · arXiv:2104.08821
  • 机制： 自监督对比嵌入：无监督用 dropout 作增强，有监督用 NLI 对。
  • 局限： 批内”相似”来自浅层增强，表征捕获的是释义/主题接近，而非问答证据相关性。

9. 概率相关性框架：BM25 及其超越（The Probabilistic Relevance Framework: BM25 and Beyond）

  • 一作 / 会议 / 年份： Stephen Robertson · Foundations and Trends in IR · 2009
  • ID / arXiv： paperId 47ced790a563344efae66588b5fb7fe6cca29ed3
  • 机制： 经典稀疏——OKAPI 词频饱和 × 逆文档频率，倒排索引精确词项匹配。
  • 局限： 纯词法匹配：与记忆句措辞不同的自然语言查询存在巨大词汇不匹配；高召回但低语义广度。

10. BEIR：IR 模型零样本评价的异构基准（BEIR: A Heterogeneous Benchmark for Zero-shot Evaluation of IR Models）

  • 一作 / 会议 / 年份： Nandan Thakur · SIGIR · 2021
  • ID / arXiv： paperId 807600ef43073cd9c59d4208ee710e90cf14efa8 · arXiv:2104.08663
  • 机制： 18 个多样 IR 数据集的零样本评测框架，比较 BM25 vs 稠密/学习型模型。
  • 局限： BM25 在精确作答型查询上胜稠密、稠密跨域降级——基准域相关性与”变动记忆语料库内部的相关性”不同。

11. 弱监督对比预训练文本嵌入（Text Embeddings by Weakly-Supervised Contrastive Pre-training 《E5》)

  • 一作 / 会议 / 年份： Liang Wang · arXiv/TMLR · 2022
  • ID / arXiv： paperId 5a3c1afe73d8bcc8288d17cb17be2baec8a98464 · arXiv:2212.03533
  • 机制： 在大规模异构网页文本上弱监督对比预训练，双编码器带 “query:”/“passage:” 前缀。
  • 局限： 前缀 + 对比目标偏向释义/主题匹配、缺乏落地（grounding），所以主题匹配的记忆句可能胜过字面含答案的句子。

12. 迈向通用文本嵌入：多阶段对比学习（Towards General Text Embeddings with Multi-stage Contrastive Learning 《GTE》)

  • 一作 / 会议 / 年份： Zehan Li · arXiv · 2023
  • ID / arXiv： paperId 84109e1235b725f4bb44a54bab8b493bd723fdd3 · arXiv:2308.03281
  • 机制： 多阶段对比预训练 + 任务合并微调（GTE 模型族）。
  • 局限： 广泛任务混合带来冲突/数据失衡；单向量泛化仍匹配主题而非可作答证据。

13. 一个嵌入器，任意任务：指令微调文本嵌入（One Embedder, Any Task: Instruction-Finetuned Text Embeddings 《Instructor》)

  • 一作 / 会议 / 年份： Hongjin Su · EMNLP · 2022
  • ID / arXiv： paperId 63c0dbe2426f9c92f469151d1773e5265ae6580e · arXiv:2212.09741
  • 机制： 给查询和文档都附加任务专属指令，一个模型服务多任务。
  • 局限： 需要每任务正确指令——若不限定”找出作答此问题的句子”，检索退化为通用语义匹配；指令数据由 LLM 生成且昂贵。

14. 用大语言模型改进文本嵌入（Improving Text Embeddings with Large Language Models 《E5-Mistral》)

  • 一作 / 会议 / 年份： Liang Wang · EMNLP · 2023
  • ID / arXiv： paperId 88ca4ee548d07263386ca8e4effc4a001bb2716f · arXiv:2401.00368
  • 机制： 以 LLM（Mistral）为编码器主干，在带指令的合成对照数据上训练。
  • 局限： 7B 级主干推理/ token 成本很高；质量依赖合成数据；仍捕获主题而非证据相关性。

15. M3-Embedding：多语言、多功能、多粒度（M3-Embedding: Multi-Linguality, Multi-Functionality, Multi-Granularity 《BGE-M3》)

  • 一作 / 会议 / 年份： Jianlv Chen · Findings of ACL · 2024
  • ID / arXiv： paperId 677f89b61eff0f5ad3ae10c2b9208aaa16aa4239 · arXiv:2402.03216
  • 机制： 一个模型经自知识蒸馏，同时输出稠密、稀疏（词项权重）、多向量三种形式，跨多粒度。
  • 局限： 稠密+稀疏+多向量叠加会膨胀索引/计算；融合信号仍无法解决”主题匹配但非作答句”。

16. C-Pack：推进通用中文嵌入的打包资源（C-Pack: Packaged Resources To Advance General Chinese Embedding 《BGE》)

  • 一作 / 会议 / 年份： Shitao Xiao · arXiv · 2023
  • ID / arXiv： paperId 2ff694e20f492a7acf7fd0646c5e1576f0b3c901 · arXiv:2309.07597
  • 机制： 弱监督对比预训练 + 数据集/基准资源（bge-large 带指令前缀），用于中文检索。
  • 局限： 任务/领域受限（中文），跨多语言记忆泛化差；单向量故”主题但不可答”问题仍在。

17. 俄罗斯套娃表示学习（Matryoshka Representation Learning）

  • 一作 / 会议 / 年份： Aditya Kusupati · NeurIPS · 2022
  • ID / arXiv： paperId aa676125041cd284b4a1313d70143ba6f77c074b · arXiv:2205.13147
  • 机制： 训练嵌入使向量短前缀（截断）仍保持高准确率，实现自适应的压缩存储。
  • 局限： 精度-维度权衡——维度越小召回/精度越低；保留分量按余弦相似而非证据匹配选择。

18. Qwen3 Embedding：通过基础模型推进文本嵌入与重排（Qwen3 Embedding: Advancing Text Embedding and Reranking Through Foundation Models）

  • 一作 / 会议 / 年份： Yanzhao Zhang · arXiv · 2025
  • ID / arXiv： paperId 41a8c615b8fefdddbb28e1c0a9edcaa446d15451
  • 机制： 大型解码器基础模型直接产出嵌入 + 重排 LM 头（MTEB 领先）。
  • 局限： 大型解码器 → 高 token/推理成本；基准奖励相似度/STS（主题匹配），而非”可作答句精度”。

19. 无相关性标签的精确零样本稠密检索（Precise Zero-Shot Dense Retrieval without Relevance Labels 《HyDE》)

  • 一作 / 会议 / 年份： Luyu Gao · ACL · 2023（arXiv 2022）
  • ID / arXiv： paperId 5c32c653735b43a0a8923ca65ac191bd4bf15311 · arXiv:2212.10496
  • 机制： LLM 生成一个假设答案文档，嵌入后按与该合成文档的相似度检索——零样本、免相关性标签。
  • 局限： 假设文档可能偏离真实答案，降低逐查询精度；且每查询一次 LLM 生成（+token）。

20. 迷失在中间：语言模型如何使用长上下文（Lost in the Middle: How Language Models Use Long Contexts）

  • 一作 / 会议 / 年份： Nelson F. Liu · TACL · 2023
  • ID / arXiv： paperId 1733eb7792f7a43dd21f51f4d1017a1bffd217b5 · arXiv:2307.03172
  • 机制： LLM 在长检索上下文中关注位置的实证研究（非检索器，是检索消费方分析）。
  • 局限： 即使检索良好，token 预算强制截断、中部上下文证据被丢弃，作答句仍可能错过（检索 token 成本）。

21. 双曲（庞加莱）嵌入用于层级表示学习（Poincaré Embeddings for Learning Hierarchical Representations）

  • 一作 / 会议 / 年份： Maximilian Nickel · NeurIPS · 2017
  • ID / arXiv： paperId 1590bd1bca945fc6ff50b8cdf2da14ea2061c79a · arXiv:1705.08039
  • 机制： 用黎曼优化把符号数据嵌入双曲庞加莱球，捕捉层级与相似性。
  • 局限： 面向层级/分类学，非证据检索——双曲邻近反映结构/主题性，不代表”这句回答了查询”。

22. RAGAs：检索增强生成的自动化评测（RAGAs: Automated Evaluation of Retrieval Augmented Generation）

  • 一作 / 会议 / 年份： S. Es · EACL · 2023（arXiv）
  • ID / DOI： paperId f5e9e5bbe22f0263be1f1ce88c66978a2b927772 · DOI 10.48550/arXiv.2309.15217 · arXiv:2309.15217
  • 机制： 免参考指标（忠实性、答案相关性、上下文相关性）给 RAG 的检索+生成打分。
  • 局限： “上下文相关性”评的是上下文与问题主题相关，而非含作答证据，故可能奖励”主题匹配但不可作答”的上下文。

02 — 查询端增强 / 变换

主题：查询改写 / 查询扩展 / 多查询 / RAG 路由，对 Agent Memory 与 RAG 检索器设计相关。
20 篇真实论文，全部经 Semantic Scholar 验证（含 paperId）；arXiv/DOI 尽可能给出。括号内为原文标题。
图例：[LLM 调用] = 查询端步骤中 LLM 调用次数。

1. 无相关性标签的精确零样本稠密检索（Precise Zero-Shot Dense Retrieval without Relevance Labels 《HyDE》)

  • 一作：Luyu Gao。会议/年份：ACL 2023。
  • paperId：5c32c653735b43a0a8923ca65ac191bd4bf15311 | arXiv: 2212.10496 | DOI: 10.18653/v1/2023.acl-long.99
  • 查询端机制：用 1 次 LLM 调用生成”假设文档”替代查询，再按该文档嵌入/检索。
  • 关键局限：生成的文档是虚构的、会幻觉；多花 1 次 LLM 调用，且文档需经编码器稠密瓶颈”落地”。

2. Query2doc：用大语言模型做查询扩展（Query2doc: Query Expansion with Large Language Models）

  • 一作：Liang Wang。会议/年份：EMNLP 2023。
  • paperId：ccc772d88c231275f24c4fac9b28bbe0942e1107 | arXiv: 2303.07678
  • 查询端机制：1 次 LLM 调用生成若干伪文档（少样本提示），拼接到查询以丰富嵌入/搜索表征。
  • 关键局限：多 1 次 LLM 调用 + 更长查询 token；生成伪文档可能注入偏离主题或幻觉内容，伤及精度。

3. Self-RAG：通过自我反思学会检索、生成与批判（Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection）

  • 一作：Akari Asai。会议/年份：ICLR 2024。
  • paperId：ddbd8fe782ac98e9c64dd98710687a962195dd9b | arXiv: 2310.11511
  • 查询端机制：查询端主动性——训练 LM 发”反思 token”，按需决定每段生成时是否/取什么（多次检索决定，非固定 top-k）。
  • 关键局限：需专门的批判/检索 token 训练，且做大量细粒度”检索+批判”步骤，倍乘 LLM 调用与解码 token。

4. 主动检索增强生成（Active Retrieval Augmented Generation <>)

  • 一作：Zhengbao Jiang。会议/年份：EMNLP 2023。
  • paperId：88884b8806262a4095036041e3567d450dba39f7 | arXiv: 2305.06983
  • 查询端机制：迭代用预测的”下一句”作为检索查询（自回归式查询形成），仅在生成含低置信 token 时触发；约每句 1 次 LLM 调用加检索。
  • 关键局限：全程多次前向/检索，token（与延迟）随输出长度增长，且仍可能取到无关”未来”内容。

5. 修正型检索增强生成（Corrective Retrieval Augmented Generation <>)

  • 一作：Shi-Qi Yan。会议/年份：arXiv 2024。
  • paperId：5bbc2b5aa6c63c6a2cfccf095d6020b063ad47ac | arXiv: 2401.15884 | DOI: 10.48550/arXiv.2401.15884
  • 查询端机制：轻量检索评测器（1 次 LLM 调用）给某查询的检索结果分档，触发修正动作（网页搜索回退 + 检索文档”拆分-重组”）。
  • 关键局限：多一个评测 LLM 调用，可能升级到昂贵的大规模网页检索；且可能把查询误判为”检索差”。

6. 退一步思考：通过抽象唤起 LLM 推理（Take a Step Back: Evoking Reasoning via Abstraction in Large Language Models 《Step-Back Prompting》)

  • 一作：Huaixiu Steven Zheng。会议/年份：ICLR 2024。
  • paperId：0786c88990235414611478099e43611542d973b0 | arXiv: 2310.06117
  • 查询端机制：提示 LLM 把具体查询抽象成高层”退一步”查询（多 1 次 LLM 调用），按它检索，再用两者作答。
  • 关键局限：多 1 次 LLM 调用 + 第二次检索；抽象查询可能过泛，过度检索、膨胀上下文 token。

7. Adaptive-RAG：通过问题复杂度学习自适应检索增强 LLM（Adaptive-RAG: Learning to Adapt Retrieval-Augmented LLMs through Question Complexity）

  • 一作：Soyeong Jeong。会议/年份：NAACL 2024。
  • paperId：e5e8c6ac537e0f5b5db14170bc232d6f9e641bbc | arXiv: 2403.14403 | DOI: 10.18653/v1/2024.naacl-long.389
  • 查询端机制：小训练分类器（1 次廉价 LLM/LM 调用）据预测复杂度把查询路由到不检索/单步/多步检索。
  • 关键局限：路由质量取决于复杂度分类器；误路由要么浪费检索 token，要么对真正复杂查询失效；选定多步后不能降低每步成本。

8. RAG-Fusion：检索增强生成的新思路（RAG-Fusion: a New Take on Retrieval-Augmented Generation）

  • 一作：Zackary Rackauckas。会议/年份：IJNLC 2024。
  • paperId：b4d1da748ba87f38150ad38e30be68f3584ae462 | arXiv: 2402.03367 | DOI: 10.5121/ijnlc.2024.13103
  • 查询端机制：1 次 LLM 调用生成多个查询”视角”（通常 3–5 个），各查一次后用倒数排名融合（RRF）形成覆盖面更广的候选池。
  • 关键局限：N 次并发检索 + N× 上下文 → 1.77x 延迟；生成查询偏离意图时精度下降（需 RRF/重排恢复精度）。

9. 面向检索增强 LLM 的查询改写（Query Rewriting for Retrieval-Augmented Large Language Models 《Rewrite-Retrieve-Read》)

  • 一作：Xinbei Ma。会议/年份：arXiv 2023。
  • paperId：f743287be3ced6757de7ecb26d03815b22cd737b | arXiv: 2305.14283 | DOI: 10.48550/arXiv.2305.14283
  • 查询端机制：检索前改写用户查询，或用黑盒 LLM（1 次少样本调用）、或用小 RL 训练改写器，缩小查询-知识差距。
  • 关键局限：RL 改写器需按任务/从阅读器拿奖励做调参，多 1 次（冻结）或多步（可训练）生成；改写错误会带偏检索。

10. ReWOO：将推理与观测解耦以实现高效增强语言模型（ReWOO: Decoupling Reasoning from Observations for Efficient Augmented Language Models）

  • 一作：Binfeng Xu。会议/年份：arXiv 2023（发表 EMNLP 2023）。
  • paperId：90027ca7802645671a69b00b65e1fa94e6b63544 | arXiv: 2305.18323 | DOI: 10.48550/arXiv.2305.18323
  • 查询端机制：规划器在一次 LLM 调用中建立 (Plan,#E) 子问题/证据占位蓝图，使检索并行执行、无需反复回喂观测。
  • 关键局限：用 token 换成”一次性计划”，须在未见观测时预测需求；计划/证据错配（或需取却未取的证据）有害，且 worker 调用仍花 token。

11. 生成而非检索：大语言模型作为强力上下文生成器（Generate rather than Retrieve: Large Language Models as Strong Context Generators 《GenRead》)

  • 一作：Wenhao Yu。会议/年份：ICLR 2023。
  • paperId：b2542a738b75ee9b7ce1a13d8b78f9095d212412 | arXiv: 2209.10063
  • 查询端机制：完全以 LLM 生成上下文文档取代检索（基于聚类的不同提示 → 多次生成调用），再读之作答。
  • 关键局限：每生成一个文档 1 次 LLM 调用（多次）；生成上下文无法核实、无落地，幻觉风险高。

12. 何时检索：教会 LLM 有效利用信息检索（When to Retrieve: Teaching LLMs to Utilize Information Retrieval Effectively 《Adapt-LLM》)

  • 一作：Tiziano Labruna。会议/年份：RANLP 2024。
  • paperId：72e7a35f3ca5f8f890c32e33e89aa4e17475d989 | arXiv: 2404.19705 | DOI: 10.48550/arXiv.2404.19705
  • 查询端机制：训练 LM 在不知道时发出单个 <RET> token，查询端”要不要检索”约 0 额外改写 LLM 调用。
  • 关键局限：只决定是否检索（不决定如何改写），且训练限窄 QA 风格；调优外的知识缺口可能漏检，导致错误的不检索决定。

13. 面向检索增强生成的问题分解（Question Decomposition for Retrieval-Augmented Generation）

  • 一作：Paul Ammann。会议/年份：ACL 2025。
  • paperId：a9bef6726f9e1be4e75376e0b4bb53945650971e | arXiv: 2507.00355 | DOI: 10.48550/arXiv.2507.00355
  • 查询端机制：1 次 LLM 调用把查询分解为子问题，逐子问题检索后合并池，交叉编码器重排（免训练、即插即用）。
  • 关键局限：逐子查询检索翻倍检索调用/上下文，靠重排器消噪；分解次数需按题型调参。

14. RAG-R1：通过多查询并行激励 LLM 的搜索与推理能力（RAG-R1: Incentivizing the Search and Reasoning Capabilities of LLMs Through Multi-Query Parallelism）

  • 一作：Zhiwen Tan。会议/年份：AAAI 2026。
  • paperId：d8d8d50bde20280005a50ef9d0a89634dec20597 | arXiv: 2507.02962 | DOI: 10.1609/aaai.v40i39.40603
  • 查询端机制：RL 训练模型从单查询转向并行多查询，同时跑多个查询以降低延迟、扩大覆盖。
  • 关键局限：N 个并行查询 → N× 检索/上下文 token，即使墙钟延迟下降；单→多查询转换需昂贵 RL 与更强基座。

15. PropRAG：用命题路径上的束搜索引导检索（PropRAG: Guiding Retrieval with Beam Search over Proposition Paths）

  • 一作：Jingjing Wang。会议/年份：EMNLP 2025。
  • paperId：aae1d8e184c306b90cb51b205b8cb7ef718ebcdf | arXiv: 2504.18070 | DOI: 10.18653/v1/2025.emnlp-main.317
  • 查询端机制：把查询/语料转成丰富命题，跑 LLM 无关的在线束搜索，沿命题路径发现多步检索链（无 LLM 查询生成调用）。
  • 关键局限：需把语料”命题化”（构建/标注成本）；束搜索仍做多次候选检索/token；命题可能把细粒度事实过度碎片化。

16. 重新审视查询增强的在线策略优化（Rethinking On-policy Optimization for Query Augmentation 《OPQE》)

  • 一作：Zhichao Xu。会议/年份：TMLR 2025。
  • paperId：fa639b05ae4ad81aaada7089a95c0cdd61b512d2 | arXiv: 2510.17139 | DOI: 10.48550/arXiv.2510.17139
  • 查询端机制：在线策略 RL 生成”最利于检索”的伪文档（而非改写），并显示在同等算力下免训练提示常能匹配昂贵 RL。
  • 关键局限：RL 变体需奖励训练策略 + 每步伪文档生成调用；生成伪文档可能幻觉；算力感知比较显示额外成本多半不划算。

17. UniRAG：统一 RAG 框架……分解、拆解推理、迭代改写（UniRAG: A Unified RAG Framework … Decomposition, Break-Down Reasoning, Iterative Rewriting）

  • 一作：Gun Il Kim。会议/年份：EMNLP 2025（Findings）。
  • paperId：070d4ab06b32abb285aa88c892d5955d4bb2ebe5 | aclanthology: 2025.findings-emnlp.1022
  • 查询端机制：实体锚定分解把查询拆成子查询，RAGAs 置信门在证据不足时触发迭代查询改写（多调用循环）。
  • 关键局限：分解+改写+重排是多阶段、多 LLM 调用管线，token/延迟随子问题数与改写轮数增长。

18. 逐步忠实：通过查询分解改进 RAG 的泛化与引用（Faithful in Steps: Improving Generalization and Citation in RAG via Query Decomposition 《QDRAG》)

  • 一作：Yue Liu。会议/年份：AAAI 2026。
  • paperId：75f9da2bf165f170cb92faf43d9c7968daea07b1 | DOI: 10.1609/aaai.v40i42.40879
  • 查询端机制：零样本把问题分解为原子子问题（QD-C/QD-R）来显化隐式实体，加重排器削减干扰上下文。
  • 关键局限：分解成多个原子子问题多花 MLLM/LLM 调用与重排算力；主要恢复隐式实体召回，引用/过度引用益处取决于重排器。

19. REAP：用递归评估与自适应规划增强多跳 QA 的 RAG（REAP: Enhancing RAG with Recursive Evaluation and Adaptive Planning for Multi-Hop Question Answering）

  • 一作：Yijie Zhu。会议/年份：AAAI 2026。
  • paperId：e5e389cf43ce4df01d4a768c8857da877300f342 | arXiv: 2511.09966
  • 查询端机制：分解器把查询拆成依赖子任务计划，子任务规划器递归再规划/分支，事实抽取器逐子查询取事实（多调用循环）。
  • 关键局限：每子任务多次 LLM 调用、每子查询固定 top-k，成本随规划深度增长；它改进规划，非”逐查询检索 token 效率”。

20. MiniELM：面向电商搜索优化的轻量自适应查询改写框架（MiniELM: A Lightweight and Adaptive Query Rewriting Framework for E-Commerce Search Optimization）

  • 一作：Duy A. Nguyen。会议/年份：ACL 2025（Findings）。
  • paperId：5e5d09d770a18ae4f97bc1f4260e8468d3c3b254 | aclanthology: 2025.findings-acl.363
  • 查询端机制：轻量 LM 对搜索做自适应查询改写（检索/排序前的查询端变换）。
  • 关键局限：聚焦电商排序、需按域改写训练；且是”每查询都改写”，无法在检索前预知改写是否有益。

主导局限模式（简）

  • 多查询/扩展”提升召回但以 token 为代价”反复出现：RAG-Fusion（N 查询 + RRF，1.77x 延迟）、RAG-R1（并行多查询，N× token）、query2doc/OPQE/GenRead/HyDE（伪文档生成加一次调用 + 更长检索 token）。Self-RAG / FLARE / UniRAG / Question-Decomposition / QDRAG / CRAG 均加逐段或逐子查询检索，所以增益与 LLM 调用数、上下文 token 近线性上升。
  • 精度-召回权衡与漂移：生成查询/伪文档（RAG-Fusion, GenRead, HyDE, query2doc）常幻觉或偏离意图，扩大的召回需靠重排器（Question Decomposition, QDRAG, RAG-Fusion）补。
  • 路由/自适应方法（Adaptive-RAG, When to Retrieve, CRAG 评测器）避开统一检索，却把负担移给分类器——误路由浪费 token 或漏检；且多数只决定”要不要”，不决定”如何变换”。
  • 几乎没人零成本变换查询：例外是 PropRAG（命题路径上 LLM 无关束搜索，无 LLM 查询生成调用）与 When to Retrieve（单个 <RET> token，约 0 改写调用）。其余方法都为其召回增益付显式额外 LLM 调用或 N× 检索 token。

03 — 重排器与混合融合

面向 Agent Memory / RAG 检索器设计；聚焦首阶段检索之后的重排与混合融合。所有条目经 Semantic Scholar MCP（search_papers / get_paper）验证；ID 真实，无虚构。括号内为原文标题。
每条约：机制（如何重排/融合）+ 局限（关键弱点，强调排序 vs 覆盖）。

A. 交叉编码器 / 单流重排器（第一代）

1. 用 BERT 做段落重排（Passage Re-ranking with BERT）

  • 一作：Rodrigo Nogueira（与 Kyunghyun Cho）；会议/年份：arXiv (2019)；MS MARCO passage / TREC-CAR SOTA。
  • paperId：85e07116316e686bf787114ba10ca60f4ea7c5b2 | arXiv:1901.04085
  • 机制：整段查询-段落交叉编码（拼接 q + doc，每对各跑一次 BERT）给出单一语义相关分，用于重排首阶段列表。
  • 局限：原始交叉编码器——每 (查询, 文档) 对一次完整 BERT 前向，复杂度 O(N_pairs)，且只用来重排快检索器已拿到的内容；它永远发现不了未检索到的证据，是典型的”额外模型”高延迟。

2. 用预训练序列到序列模型做文档排序（Document Ranking with a Pretrained Sequence-to-Sequence Model 《MonoT5》)

  • 一作：Rodrigo Nogueira（与 Zhiying Jiang, Ronak Pradeep, Jimmy Lin）；会议/年份：Findings of EMNLP 2020（DOI 10.18653/v1/2020.findings-emnlp.63）。
  • paperId：f6e0164466e827112fd415afdc28ddf8e0eb1ba3 | arXiv:2003.05113（去重说明：在 S2 用 ARXIV:2003.05113 调 get_paper 会撞到无关论文——请用上面 paperId）。
  • 机制：单调 seq2seq（T5）——为每个候选项生成 “true”/“false” 作为相关性信号，实现大规模无标签数据合成训练（mono）的重排。
  • 局限：编码器-解码器（T5-base/large）远重于双编码器，且须逐候选调用；它只给首阶段已找到的候选项打分，弱首阶段召回封顶其上限。

3. ED2LM：编码器-解码器到语言模型，加速文档重排推理（ED2LM: Encoder-Decoder to Language Model for Faster Document Re-ranking Inference）

  • 一作：Kai Hui（Honglei Zhuang, Tao Chen, Zhen Qin, Jing Lu 等）；会议/年份：arXiv 2022。
  • paperId：04b176de2c3b29ebdfadd90fb5beab8323994a3f | arXiv:2204.11458
  • 机制：把逐候选的序列到序列编码器-解码器（T5）换成纯解码器 LM，降低重排推理开销并保留 seq2seq 式相关打分。
  • 局限：仍是逐候选打分的重排器——省了效率，但不扩大候选集；从未进入 top-k 的文档对它不可见。

B. 三编码器 / 多候选项”比较”式重排器（模糊边界）

4. 把邻居放在一起比较更容易：CMC（Comparing Multiple Candidates 《CMC》)

  • 一作：Jonghyun Song（Cheyon Jin, Wenlong Zhao, Jay-Yoon Lee）；会议/年份：EMNLP 2024。
  • paperId：f20dec2ff4cec8b5aa6c7371317debe14b24a87d | DOI 10.48550/arXiv.2405.12801 | arXiv:2405.12801
  • 机制：三编码器式中间重排器，通过浅自注意力层让查询同时与多个相邻候选嵌入共同打分，定位为 BE→CMC→CE。
  • 局限：论文自己承认——依赖双编码器选出的小子集”易受双编码器误差传播之害”；CMC 改善 recall@k，但只重排双编码器已拿出的候选；改进的是检索区域内的覆盖，而非超越它。

C. 列表式 / LLM 作为重排器（RankGPT 族）

5. ChatGPT 善于搜索吗？探究大语言模型作为重排代理（Is ChatGPT Good at Search? Investigating Large Language Models as Re-Ranking Agent 《RankGPT》)

  • 一作：Weiwei Sun（Lingyong Yan, Xinyu Ma, Peng Ren, Dawei Yin, Zhaochun Ren）；会议/年份：arXiv 2023（RankGPT）。
  • paperId：459c82205d2a27a8542bba7a4d478a8a23be2f5d | arXiv:2304.09542
  • 机制：列表式/置换式重排——提示 LLM 对一段（用滑窗）相关度排序，取代点式打分。
  • 局限：成本与延迟随 LLM 推理和上下文窗口切分增长；它只排”所给窗口”，未进入检索窗口的事实无法被排前。

6. RankVicuna：用开源 LLM 做零样本列表式文档重排（RankVicuna: Zero-Shot Listwise Document Reranking with Open-Source LLMs）

  • 一作：Ronak Pradeep（Sahel Sharifymoghaddam, Jimmy Lin）；会议/年份：arXiv 2023。
  • paperId：ba03ca8faa9f01cd9d26b80f08d421376f70de22 | arXiv:2309.15088
  • 机制：开源 LLM 列表式重排器，表明开源模型经过调提示可接近基于 GPT 的列表式重排。
  • 局限：每查询的指令微调 LLM 成本；严格受首阶段取回窗口限制（无机制找回缺失的多跳事实）。

7. 带大语言模型的自校准列表式重排（Self-Calibrated Listwise Reranking with Large Language Models）

  • 一作：Ruiyang Ren（Yuhao Wang, Kun Zhou, Wayne Xin Zhao 等）；会议/年份：SIGIR 2024（DOI 10.1145/3696410.3714658）。
  • paperId：059f8137f3c5439d59ea433c7ff91ab74da76bf0
  • 机制：校准 LLM 的列表式相关预测（自由/弱打分 vs 校准良好），以更好地整合/加权重排分数。
  • 局限：改善答案融合质量，但仍消费首阶段列表；覆盖不变，校准本身依赖初始排序质量。

8. JudgeRank：利用 LLM 做推理密集型重排（JudgeRank: Leveraging LLMs for Reasoning-Intensive Reranking）

  • 一作：Tong Niu（Shafiq Joty, Ye Liu, Caiming Xiong, Yingbo Zhou, Semih Yavuz）；会议/年份：arXiv 2024。
  • paperId：9933a51591a449875e046a0fe21a6b50a5c200ce
  • 机制：用 LLM”裁判”推理重排，面向需多步/常识推理、超出表层词法匹配的查询。
  • 局限：推理成本高、受位置/顺序偏见；它在已检索文档上推理，真正缺失的桥接证据仍不会被引入。

9. Rank-K：列表式重排的测试时推理（Rank-K: Test-Time Reasoning for Listwise Reranking）

  • 一作：Eugene Yang（Andrew Yates, Kathryn Ricci, Orion Weller 等）；会议/年份：arXiv 2025。
  • paperId：eb00b03933c67b763fdd43331a82178e003874dd
  • 机制：给列表式重排器加测试时”推理”token/草稿，以改善排序质量。
  • 局限：更高推理成本与延迟；纯排序改进，无法将召回扩展到首阶段候选集之外。

10. PaRaDe：用示例做段落排序（PaRaDe: Passage Ranking using Demonstrations with LLMs）

  • 一作：Andrew Drozdov（Honglei Zhuang, Zhuyun Dai, Zhen Qin 等）；会议/年份：arXiv / Google DeepMind 2023。
  • paperId：0ff758908dab76e80cc6ff14737391b9afc976e3
  • 机制：上下文示范示例教 LLM 如何排序段落（而非原始”给这些排序”），改善上下文中列表式排序。
  • 局限：长提示/token 成本与示范敏感性；仍只重排检索器返回的段落。

11. 用段落嵌入实现高效列表式 LLM 重排（Leveraging Passage Embeddings for Efficient Listwise Reranking with LLMs）

  • 一作：Qi Liu（Bo Wang, Nan Wang, Jiaxin Mao）；会议/年份：SIGIR 2024（DOI 10.1145/3696410.3714554）。
  • paperId：e030fe3a67d91e85f7da6a599b7fde7289062a25
  • 机制：用段落嵌入（非原文）作为 LLM 列表式输入，削减 token 成本同时保留列表式质量。
  • 局限：嵌入的是首阶段已找到的文档；便宜输入是对既有候选列表的压缩，故覆盖被首阶段召回内在限定。

12. 缩小规模、轻量化：用 seq2seq 编码器-解码器做高效零样本列表式重排（Scaling Down, LiTting Up: Efficient Zero-Shot Listwise Reranking with Seq2seq Encoder-Decoder Models）

  • 一作：Manveer Tamber（Ronak Pradeep, Jimmy Lin）；会议/年份：arXiv 2023。
  • paperId：4267ba44ced8e2c6afa39547aa6657aef62502e1
  • 机制：小 seq2seq 编解码模型（经少样本上下文中）做廉价零样本列表式重排。
  • 局限：轻量但容量受限——对困难语义/多跳重排更弱，且仍受限于首阶段候选列表。

13. 先压缩再排序：用排序感知段落压缩实现更快更好列表式 LLM 重排（Compress-then-Rank: Faster and Better Listwise Reranking with LLMs via Ranking-Aware Passage Compression）

  • 一作：Zhewei Zhi（Yingyi Zhang, Yi Jing, Xianneng Li 等）；会议/年份：AAAI 2026（DOI 10.1609/aaai.v40i41.40811）。
  • paperId：146641a067125c4b583f363bac68e331f09e98ce
  • 机制：列表式 LLM 排序前先压缩段落（排序感知压缩）以提速并改善重排。
  • 局限：对已检索列表做压缩可减 token，但非增加覆盖；无法浮现从未进入候选集的证据。

D. 高效 / “轻量”重排器（面向部署）

14. LURE-RAG：面向高效 RAG 的轻量效用驱动重排（LURE-RAG: Lightweight Utility-driven Reranking for Efficient RAG）

  • 一作：Manish Chandra（Debasis Ganguly, Iadh Ounis）；会议/年份：arXiv 2026。
  • paperId：377ef091a3c2462e9d347221751066ebf6a1b3f9
  • 机制：效用驱动轻量重排器，目标是削减 RAG 成本同时保住生成所需证据。
  • 局限：以效率为先——为重排强度换速度，且只重排检索器产出的内容；无法为多跳事实补上缺失桥接证据。

15. 逐层 token 压缩用于高效文档重排（Layer-wise Token Compression for Efficient Document Reranking）

  • 一作：Shengyao Zhuang（Zhichao Xu, Ivano Lauriola）；会议/年份：arXiv / CIKM 2026（DOI 10.1145/3805712.3809871）。
  • paperId：03e8814aebd36523c521e60fba26c7e28acb1210
  • 机制：逐层压缩 token 表征，以降低交叉编码器重排的计算/延迟。
  • 局限：只是重排步骤的压缩/吞吐技巧——不改变取回了哪些文档，故精度仍被首阶段召回限定。

16. KaLM-Reranker-V1：快速但不做晚交互的压缩文档重排（KaLM-Reranker-V1: Fast but Not Late Interaction for Compressed Document Reranking）

  • 一作：Xinping Zhao（Jiaxin Xu, Ziqi Dai, Xin Zhang 等）；会议/年份：arXiv 2026。
  • paperId：79b07497a186156e8608f47a0394d6f5d62071f2
  • 机制：压缩文档重排器，刻意不做完整晚交互却保持大部分信号。
  • 局限：明确牺牲晚交互模型依赖的细粒度交互；权衡换速度，但模型只能重排已取回候选。

E. 晚交互 / 多向量（模糊”阶段一 vs 阶段二”边界）

17. ColBERT：用 BERT 之上的语境化晚交互实现高效有效段落搜索（ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction over BERT）

  • 一作：Omar Khattab（Matei Zaharia）；会议/年份：SIGIR 2020（DOI 10.1145/3397271.3401075）。
  • paperId：60b8ad6177230ad5402af409a6edb5af441baeb4 | arXiv:2004.12832
  • 机制：晚交互（”MaxSim”）——查询与文档各编码为逐 token 向量，相关分 = Σ 最大余弦；文档向量可预计算，故它既是可扩展首阶段检索器又是高质量打分器。
  • 局限：模糊了阶段一/二，但并非对广泛扇出的真正重排：MaxSim 打分仍在它选出的索引 top-k 上，故若正确段落未入索引/未浮现，继承同样”垃圾进”上限；且空间占用大于单向量。

18. ColBERTv2：通过轻量晚交互实现有效高效检索（ColBERTv2: Effective and Efficient Retrieval via Lightweight Late Interaction）

  • 一作：Keshav Santhanam（Omar Khattab, Jon Saad-Falcon, Christopher Potts, Matei Zaharia）；会议/年份：NAACL 2022（DOI 10.18653/v1/2022.naacl-main.272）。
  • paperId：590432f953b6ce1b4b36bf66a2ac65eeee567515 | arXiv:2112.01488
  • 机制：ColBERT + 残差压缩 + 去噪监督（自 MiniLM 交叉编码器蒸馏），把多向量足迹缩小 6–10x。
  • 局限：与 ColBERT 相同的晚交互双用途；去噪监督用交叉编码器重排器造困难负样本，故间接依赖强逐候选打分器，且仍从索引选择而非重排广泛检索集。

19. 用 EMVB 实现高效有效多向量稠密检索（Efficient and Effective Multi-Vector Dense Retrieval with EMVB）

  • 一作：Franco Maria Nardini（Cosimo Rulli, Rossano Venturini）；会议/年份：SEBD 2024。
  • paperId：cd310fd144551f3513c616106cd9901cae304771
  • 机制：全量/部分积量化（”vanilla” 与 “efficient” 多向量），使多向量（ColBERT 式）检索便宜到能端到端搜索。
  • 局限：聚焦编码/量化效率；多向量打分仍在索引上运作，只降晚交互那段的空间/延迟成本。

F. 融合：倒数排名融合与词法+稠密混合

20. 倒数排名融合优于 Condorcet 与个体排序学习方法（Reciprocal Rank Fusion Outperforms Condorcet and Individual Rank Learning Methods）

  • 一作：Gordon V. Cormack（Charles L. A. Clarke, Stefan Büttcher）；会议/年份：SIGIR 2009。
  • paperId：9e698010f9d8fa374e7f49f776af301dd200c548
  • 机制：Score = Σ 1/(k + rank_i) 跨系统——基于排名的、免分数的多结果列表组合（如 BM25 + 稠密），无需分数归一化。
  • 局限：纯”再融合各系统返回内容”：RRF 只能合并至少某检索器找到的候选。若所有系统错过同一个多跳事实，RRF 只是把排名堆在共同盲区——它从不检索缺失证据。

21. M3-Embedding（BGE-M3）：经自知识蒸馏的多语言、多功能、多粒度文本嵌入（M3-Embedding: Multi-Linguality, Multi-Functionality, Multi-Granularity Text Embeddings Through Self-Knowledge Distillation）

  • 一作：Jianlv Chen（Shitao Xiao, Peitian Zhang, Kun Luo, Defu Lian, Zheng Liu）；会议/年份：Findings of ACL 2024（DOI 10.18653/v1/2024.findings-acl.137）。
  • paperId：677f89b61eff0f5ad3ae10c2b9208aaa16aa4239 | arXiv:2402.03216
  • 机制：一个模型同时做稠密 + 稀疏（词法）+ 多向量检索并融合其输出（常用 RRF），跨模式自知识蒸馏。
  • 局限：混合融合靠多样化检索模式提升召回，但仍受”任一模式找到”的召回限制；三模式可能同时错过同一桥接事实，且稀疏/多向量模式增加索引与推理成本。

22. DualView：面向多跳文档重排的自适应局部-全局融合（DualView: Adaptive Local-Global Fusion for Multi-Hop Document Reranking）

  • 一作：Litong Zhang（Jiaxin Li, Kuo Zhao）；会议/年份：arXiv 2026。
  • paperId：02b7cdceebff7e0fb50bdbf2d8863f0988fa3c88
  • 机制：重排时自适应融合局部（逐跳）与全局证据视角，更好连接”单次难以横跨”的多跳链。
  • 局限：直接针对”已召回候选”的多跳缺口，但作为重排器仍假设桥接文档已在池中——它重加权局部 vs 全局信号，而非主动重查/检索缺失中间跳。

A. 迭代 / 交错检索-推理（IRCoT 式、self-ask、回溯）

1. IRCoT │ 用链式思维推理与检索交错，解决知识密集型多步问题（IRCoT — Interleaving Retrieval with Chain-of-Thought Reasoning for Knowledge-Intensive Multi-Step Questions）

  • 一作：H. Trivedi（Hanh Trivedi）丨会议：ACL 2023（预印 2022）
  • ID：paperId f208ea909fa7f54fea82def9a92fd81dfc758c39 | arXiv 2212.10509
  • 链/跳：把一句 CoT 与一次检索交错，用部分推理发下一次查询，并把取回的每句回喂以延伸 CoT。
  • 局限 (A+B)：连接跳的”桥（中间）”句常与原始问题词法或语义不相似，一次性检索会放过它——IRCoT 只在每跳多付 1 次 LLM 调用 + 1 次检索的成本下修复，即每查询 O(hops) 额外 token。

2. Self-Ask │ 衡量并收窄组合性缺口（Self-Ask / Measuring and Narrowing the Compositionality Gap）

  • 一作：Ofir Press丨会议：NeurIPS 2022
  • ID：paperId e070ff286709db28312e08b52b05539debe88146 | arXiv 2210.03350
  • 链/跳：让模型显式把问题分解为后续子问题，递归地检索/回答每个（”self-ask”），把中间答案串进最终上下文。
  • 局限 (A)：中间子问题由模型生成而非检索发现，故对未见/词法距离远的桥接事实的覆盖完全取决于模型自身生成；且 (B) 每个子问题多一次 LLM 调用。

3. 主动检索增强生成（Active Retrieval Augmented Generation 《FLARE》)

  • 一作：Zhengbao Jiang丨会议：EMNLP 2023
  • ID：paperId 88884b8806262a4095036041e3567d450dba39f7 | arXiv 2305.06983
  • 链/跳：预测即将出现的内容，凡生成含低置信 token 即触发检索，迭代填补每个低置信span。
  • 局限 (B)：事件驱动而非图串联，故模型未预测到的远处桥接事实会被跳过；低置信触发在生成不确定时增加反复检索（LLM+搜索）轮次。

4. 分解式提示：用模块化方式解决复杂任务（Decomposed Prompting: A Modular Approach for Solving Complex Tasks）

  • 一作：Tushar Khot丨会议：ACL 2023（预印 2022）
  • ID：paperId 07955e96cbd778d0ae2a68f09d073b866dd84c2a | arXiv 2210.02406
  • 链/跳：把多跳问题归结为一系列更便宜、可复用的子问题（检索、数学、推理模块），由其中间输出串联。
  • 局限 (A)：分解是任务/提示撰写的，子查询仍须靠相似度命中语料——与子问题词法不同的桥接事实仍被放过；(B) 子问题调用链倍增每模块的 LLM/检索调用。

5. ReAgent：面向知识增强多跳 QA 的可逆多代理推理（ReAgent: Reversible Multi-Agent Reasoning for Knowledge-Enhanced Multi-Hop QA）

  • 一作：Xinjie Zhao丨会议：EMNLP 2025
  • ID：paperId 33de8e46815c4ccbbdf0012d82db64bce0a4698c | arXiv 2503.06951
  • 链/跳：多代理”规划器-执行器”，执行器可反转错误一跳并重新探索，即在扩张的检索/推理路径上显式回溯。
  • 局限 (B)：回溯是昂贵路径——每次反转丢弃已做工作并重跑检索，故整场是多次 LLM 调用；且不改变”首遍相似检索可能永不浮现不相似桥接句”（只在答案错后才恢复）。

6. 多跳问答中的”先生成再落地”（Generate-then-Ground in RAG for Multi-hop Question Answering）

  • 一作：Zhengliang Shi丨会议：ACL 2024
  • ID：paperId 403ff3523a949743290d4ce7b770da28ef3e1953 | arXiv 2406.14891
  • 链/跳：先对取回证据做跨文档推理，再把每个中间推理状态”落地”到其出处段落，串联文档图推理。
  • 局限 (A)：落地发生在生成后，故若初始检索窗口漏掉不相似中间段，后续落地只能重取/重排文档图边所暴露的内容；(B) “对取回证据推理”每链多一次 LLM 遍。

B. 分层 / 树式摘要 RAG

7. RAPTOR │ 为树式组织检索做递归抽象处理（RAPTOR — Recursive Abstractive Processing for Tree-Organized Retrieval）

  • 一作：Parth Sarthi丨会议：ICLR 2024
  • ID：paperId 1d40f07569482d24e3335ffb31394d4bf1567e6f | arXiv 2401.18059
  • 链/跳：递归嵌入、聚类、摘要块为自底向上的树，使检索能返回覆盖很多块的合适抽象层摘要。
  • 局限 (C)：树从整库一次性构建（每层聚类 + LLM 摘要），故离线构建成本随库规模增长（每簇几十个摘要）；摘要由 LLM 生成，凝聚时可能丢失桥接细节。
  • 备注 (A 部分修复)：因父节点是抽象摘要，查询可匹配”任何单个叶子都词法缺失”的概念——论文头条正是这种分层召回。

8. MuSiQue │ 通过单跳问题组合构多跳问题（MuSiQue: Multihop Questions via Single-hop Question Composition）

  • 一作：H. Trivedi（Hanh Trivedi）丨会议：TACL 2022（预印 2021）
  • ID：paperId ec307b17f193b14292206b65a1bcc95bfd8f02ed | DOI 10.1162/tacl_a_00475
  • 链/跳：一个基准，通过组合单跳问题使每个桥接跳都被标注；它暴露”多跳系统常在没真正触到中间段落的情况下’逆向套出’正确答案”。
  • 局限 (A)：它按构造隔离了”桥接句只能经中间实体检索到、而非经查询”这一失效——正是一次性 top-k 检索失败的原因，也是论文测得单跳子问题准确率的诊断价值所在。

9. 多跳 QA 系统会答单跳子问题吗？(Do Multi-Hop QA Systems Know How to Answer the Single-Hop Sub-Questions?)

  • 一作：Yixuan Tang丨会议：EACL 2021
  • ID：paperId 94f4d2de078455d1335130a0057a93f29c153b59 | arXiv 2002.09919 | DOI 10.18653/v1/2021.eacl-main.283
  • 链/跳：探测多跳系统是否真的分解并答出单跳子问题，分解问题并逐一测子答案。
  • 局限 (A)：发现即使答案对了，系统也常未能正确作答/检索桥接子跳；(B) 分解成本在每子问题多一次检索。

C. 基于图的 RAG（GraphRAG / HippoRAG / everything-graph / KG-RAG）

10. 从局部到全局：面向查询聚焦摘要的图 RAG 方法（From Local to Global: A Graph RAG Approach to Query-Focused Summarization 《GraphRAG》)

  • 一作：Darren Edge丨会议：arXiv 2024（微软）
  • ID：paperId c1799bf28d1ae93e1631be5b59196ee1e568f538 | arXiv 2404.16130
  • 链/跳：从语料构建完整实体关系图，做局部（社区）或全局（社区摘要）查询回答，跨社区串联实体。
  • 局限 (C)：构建需对全库做 LLM 实体/关系抽取 + 社区检测 + 社区级 LLM 摘要，一次性索引成本大；(A) 因检索走类型化图边而非原始查询相似度而缓解——但仅限抽取器实际连进图的那些关系。

11. HippoRAG │ 受神经生物学启发的 LLM 长期记忆（HippoRAG: Neurobiologically Inspired Long-Term Memory for LLMs）

  • 一作：Bernal Jimenez Gutierrez丨会议：NeurIPS 2024
  • ID：paperId 4308208fac24626e0c927ee728038aadc4e87266 | arXiv 2405.14831
  • 链/跳：一次性构建 KG，再从查询种子实体出发跑个性化 PageRank（PPR）跨图——单遍检索沿边跳，而非常用迭代 LLM 检索。
  • 局限 (A+B)：明确为解决桥不相似问题设计（PPR 可达查询不像的中间实体）；论文报告单步 HippoRAG 以 10–30x 更低的成本 / 6–13x 更快匹配 IRCoT；残余 (C) 是离线 KG 构建 + 大图上 PPR。

12. LightRAG：简单而快速的检索增强生成（LightRAG: Simple and Fast Retrieval-Augmented Generation）

  • 一作：Zirui Guo丨会议：EMNLP 2024 / arXiv 2024
  • ID：paperId 1ea143c34b9bc359780f79ba4d68dee68bcc1129 | arXiv 2410.05779
  • 链/跳：双层（低层实体 / 高层关系）图检索 + 键值索引，同时用实体与关系查询跨图廉价跳转。
  • 局限 (C)：仍需 LLM 实体+关系抽取与双索引图构建；其权衡是比 GraphRAG 便宜得多（单遍、更轻提示）的索引，但损失部分跨社区全局一致性。

13. 简单即有效：图和 LLM 在知识图谱 RAG 中的角色（Simple is Effective: The Roles of Graphs and LLMs in Knowledge-Graph-Based RAG）

  • 一作：Mufei Li（Siqi Miao, Pan Li）丨会议：ICLR 2025
  • ID：paperId 16b459de55727171aff6ea674535bea499e58261 | arXiv 2410.20724
  • 链/跳：辨识哪些 KG-RAG 信号来自图、哪些来自 LLM，显示图的贡献主要在于达及查询未提及的一/两跳邻居。
  • 局限 (A+C)：提供最干净的证据，证明图的价值恰恰是”中间事实与查询不相似”的修复；同时显示图构建（KG 抽取）成本是主要开销，且在”LLM 已懂桥接”的语料上增益缩小。

14. G-Retriever：面向文本图理解与 QA 的检索增强生成（G-Retriever: Retrieval-Augmented Generation for Textual Graph Understanding and QA）

  • 一作：Xiaoxin He丨会议：NeurIPS 2024
  • ID：paperId a41d4a3b005c8ec4f821e6ee96672d930ca9596c | arXiv 2402.07630
  • 链/跳：GNN 检索器，在图被问题剪枝后的子图上运作、槽位填充邻域以回答图式问题，再微调 LLM 于取回邻域。
  • 局限 (C)：需预建图 + 训练 GNN 检索器（训练成本 + 每查询全图子图采样）；且面向结构化图问题，而非自由文本桥。

15. Walk&Retrieve：经知识图谱行走的简单有效的零样本 RAG（Walk&Retrieve: Simple Yet Effective Zero-shot RAG via Knowledge Graph Walks）

  • 一作：Martin Bockling丨会议：SIGIR IR-RAG Workshop 2025
  • ID：paperId 07982a06afd97d6d3c0bbe881c2657d8617c6256 | arXiv 2505.16849
  • 链/跳：在既有 KG 上从查询实体做零样本 BFS 行走，扩张并取回可达三元组，免训练。
  • 局限 (A)：只恢复以显式边存在于 KG 的桥——若语料金标事实未被抽取为关系，行走无法达及；且继承 KG 构建 (C) 成本。

16. HopRAG：面向逻辑感知检索增强生成的多跳推理（HopRAG: Multi-Hop Reasoning for Logic-Aware Retrieval-Augmented Generation）

  • 一作：Hao Liu丨会议：ACL 2025
  • ID：paperId f92fd02f5bc38802d7ddd91b4bc4e3001573f5d6 | arXiv 2502.12442
  • 链/跳：把段落转成图，做”逻辑感知”的跳式检索（跨跳查询/知识融合），而非平坦 top-k。
  • 局限 (A)：跳逻辑构建在抽取出的段落相互关系上，故未接进段落图的桥接事实仍被丢弃；且在每跳重嵌入/精修 (B)。

D. 递归 / 显式多跳检索管线与代理预算

17. ReLOOP：面向异构 QA 的多跳推理器与规划器的递归检索（ReLOOP: Recursive Retrieval with Multi-Hop Reasoner and Planners for Heterogeneous QA）

  • 一作：Ruiyi Yang丨会议：arXiv 2025
  • ID：paperId 3fb7e0d8a52abaaa4f3927080e2f64797a56470c | arXiv 2510.20505
  • 链/跳：规划器递归分解查询，对每子任务套多跳推理器，并在异质源上重规划（递归检索）。
  • 局限 (B)：递归 + 规划意味着一次响应可烧很多 LLM 调用与 token；(A) 取决于规划器生成一个能真正浮现词法远桥接段的子查询。

18. DualRAG：整合推理与检索的双过程多跳 QA 方法（DualRAG: A Dual-Process Approach to Integrate Reasoning and Retrieval for Multi-Hop QA）

  • 一作：Rong Cheng丨会议：ACL 2025
  • ID：paperId a1c2e27b15388be62e36ec8fcfa960ad99c1c324 | arXiv 2504.18243
  • 链/跳：快系统 1 路径 + 慢系统 2 路径，慢路径在每个结构识别步交错检索与推理。
  • 局限 (B)：双过程设计意味着困难多跳查询落入慢路径，引发很多轮检索+推理；(A) 通过交错来针对但不保证”首遍相似不可见的桥”。

19. GRITHopper：免分解的多跳稠密检索（GRITHopper: Decomposition-Free Multi-Hop Dense Retrieval）

  • 一作：Justus-Jonas Erker丨会议：EACL 2025
  • ID：paperId 30e0d42e991d8532cecf3a9a66616fee84495a36 | arXiv 2503.07519
  • 链/跳：学一个稠密检索器，用多跳表征直接跳、避免显式问题分解（学习型”跳器”编码器从句传到后续句）。
  • 局限 (A+b)：必须在多跳相关性上训练（训练成本）；学习跳在”编码器从未见过的表层形式”的桥接句上仍失败——且它移除而非解决分解路径，故不相似桥召回被训练分布限定。

20. Self-RAG：通过自我反思学会检索、生成与批判（Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection）

  • 一作：Akari Asai丨会议：ICLR 2024
  • ID：paperId ddbd8fe782ac98e9c64dd98710687a962195dd9b | arXiv 2310.11511
  • 链/跳：检索 token 触发多轮检索，每段生成后获批判（自我反思）决定是否再检索。
  • 局限 (B)：反思 + 条件式多轮检索使 token/调用成本依赖数据与不确定性，常显著高于固定单次 RAG；(A) 它按相似度检索，故缺失桥仅在批判恰好触发另一次检索时才被修复。

21. 修正型检索增强生成（Corrective Retrieval Augmented Generation <>)

  • 一作：Shi-Qi Yan丨会议：arXiv 2024
  • ID：paperId 5bbc2b5aa6c63c6a2cfccf095d6020b063ad47ac | arXiv 2401.15884
  • 链/跳：轻量检索评测器给取回文档分档并触发修正动作（网页重取 / 精炼 / 剥离），把清理后的证据集传给生成器。
  • 局限 (B)：评测器 + 修正轮多一次 LLM 调用并可能触发升级回退检索（网页）翻倍成本；(A) 它只能修正判定为低置信的部分——首轮检索从未返回的桥仍需要一个”不相似触发”的第二次查询。

综合结论（供论文 related-work 框定）

  • “中间跳句子与问题在词法/嵌入上不相似、被一次性 top-k 丢弃“这一失效被充分记载，且基本上是整个多跳族谱的开创动机：MuSiQue（单跳子问题准确率）、Self-Ask / Decomposed Prompting（显式分解）、IRCoT（CoT+检索交错），最直接的是 GRITHopper 与图一线（Simple is Effective, HippoRAG），它们证明图的边际价值绝大多数正是这种桥可达。
  • 主导成本反作用力即 TOKEN / 调用爆炸：IRCoT, Self-Ask, FLARE, ReAgent（回溯）, ReLOOP, DualRAG, Self-RAG, CRAG 每跳都付 O(一次检索 + 一次 LLM 调用)，回溯/投票方法还为被丢弃路径付费。HippoRAG 是最清晰的反例：单遍 PPR 取代 ~许多次迭代调用，却仍相等/超越 IRCoT 且成本低 10–30x。
  • 第三轴是 图 / 树构建成本：GraphRAG, HippoRAG, LightRAG, G-Retriever, Walk&Retrieve, HopRAG, RAPTOR 都需离线抽取/索引构建（LLM 实体+关系抽取、聚类、摘要树或 GNN 训练）——这正是持续更新、动态 agent-memory 语料（图须不断更新）里所报告的拦路虎。

1. A-MEM：面向 LLM 代理的主动记忆（A-MEM: Agentic Memory for LLM Agents）＊即 “A-Mem”/“Agent Memory” 论文

  • 一作： Wujiang Xu（与 Zujie Liang, Kai Mei, Hang Gao, Juntao Tan, Yongfeng Zhang） · 会议/年份： NeurIPS 2025（神经信息处理系统进展 38） · S2： 1f35a15fe9df43d24ec6ea551ec6c9766c17eccf · arXiv： 2502.12110 · DOI： 10.48550/arXiv.2502.12110 · 引用： 901（S2）。
  • 存储单元 + 检索打分： 原子”笔记”（Zettelkasten），存有 LLM 生成的 上下文描述 + 关键词 + 标签，置于 ChromaDB 向量库（all-MiniLM-L6-v2 嵌入）；加笔记时与相似既有笔记建链并触发记忆演化（改写旧笔记的上下文/关键词）。检索 = LLM（GPT-4o-mini）生成查询笔记，然后对嵌入相似/已链笔记做选择性 top-k。它是 LLM-write + LLM-read，底层是向量搜索——不是纯新近/重要性/相关分数。
  • 关键局限： 构建耗 token（GPT-4o-mini 每次操作都做抽取 + 建链 + 记忆演化）；嵌入 top-k + LLM 重排可能返回相似但非真证据的笔记；建链基于单向量相似，故精确多跳路径须跨已链笔记拼接，脆弱。

2. MemGPT / Letta：迈向 LLM 即操作系统（MemGPT / Letta: Towards LLMs as Operating Systems）

  • 一作： Charles Packer（Vivian Fang, Shishir Patil, Kevin Lin, Sarah Wooders, Joseph E. Gonzalez） · 会议/年份： arXiv 2023（Letta/AGI-OS 谱系） · S2： 908dad62c0e43d80e3e3cb3c0402f7c71c70499c · arXiv： 2310.08560 · 引用： 1146（S2）。
  • 存储单元 + 检索打分： 分层 OS 式记忆：主上下文（只读系统指令 + 读/写工作上下文 + FIFO 队列）vs 外部上下文（原始消息历史的 recall 存储 + archival 存储=向量库）。LLM 通过发出记忆函数（page-in / page-out / search / summarize）管理自身记忆，由心跳与上下文溢出触发驱动，且事件触发时被推入主上下文；检索是 recall/archival 上的加权语义搜索。
  • 关键局限： 自我编辑记忆 = 每心跳多次 LLM 调用（摘要 + 分页 + 决策）→ 构建与维护耗 token；检索只返回放得进主上下文的内容，且取决于 LLM 发出正确查询/函数，故常抓 top-k 相似而非真相关段落；深层多跳事实埋在 archival，需反复成功的 page-in。

3. Mem0：用可扩展长期记忆打造生产级 AI 代理（Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory）

  • 一作： Prateek Chhikara（Dev Khant, Saket Aryan, Taranjeet Singh, Deshraj Yadav） · 会议/年份： ECAI 2025（arXiv 2025） · S2： 1d9c21a0fdb1cc16a32c5d490ebaf98436a23382 · arXiv： 2504.19413 · DOI： 10.48550/arXiv.2504.19413 · 引用： 560（S2）。
  • 存储单元 + 检索打分： LLM 抽取的原子事实作为向量库中的记忆单元（可选图变体 “Mem0g” 加实体/三元组边）。两阶段： (1) 抽取——LLM 从运行对话摘要 + 最近消息中抽出显著候选事实；(2) 更新——每条候选与 top-s 相似记忆比较，LLM 选择 ADD / UPDATE / DELETE / NOOP。检索 = 相关性向量搜索（含新近/重要性加权），返回 top-k 给提示。
  • 关键局限： 两阶段都被 LLM 支配（抽取 + 每条候选事实一次 ADD/UPDATE/DELETE/NOOP 判定）→ 耗 token/成本；更新/检索步是嵌入 top-k，故可浮出相似非决定性事实；多跳/时空矛盾只在图变体里解决得较好，且依赖 LLM 裁判。
  • 已报成本/精度： LoCoMo 92.5 @ ~6,956 tokens/查询 vs ~25,000+（全上下文）（LongMemEval 94.4 @ ~6,787）；厂商报约 90% token / 91% 延迟降低（对朴素全上下文）。

4. 生成式智能体：人类行为的交互式仿真（Generative Agents: Interactive Simulacra of Human Behavior）

  • Joon Sung Park · UIST 2023 · S2： 5278a8eb2ba2429d4029745caf4e661080073c81 · arXiv： 2304.03442 · DOI： 10.1145/3586183.3606763 · 5222 引。
  • 存储/检索： 记忆流 = 带时间戳、显著性打分的观察/事件对象；检索分 = α_recency·recency + α_importance·importance + α_relevance·relevance（α=1），其中 recency = 指数衰减（0.99）、importance = LLM 1–10、relevance = 嵌入余弦；反思写出更高层记忆。
  • 局限： importance 是每条事件一次 LLM 调用（规模化时耗 token）；余弦相关性拉回语义相似而非因果相邻证据；多跳链弱，因每条记忆独立打分。

5. Reflexion：带语言强化学习的语言代理（Reflexion: Language Agents with Verbal Reinforcement Learning）

  • Noah Shinn · NeurIPS 2023 · S2： 0671fd553dd670a4e820553a974bc48040ba0819 · arXiv： 2303.11366 · DOI： 10.52202/075280-0377 · 4897 引。
  • 存储/检索： 轨迹的片段存储 + 自然语言自我反思附加到下次尝试提示（无向量搜索 / 无打分——纯文本缓冲）。
  • 局限： 记忆单调增长且整体注入（耗 token），无固化/去重；无相关打成分，故错误反思原样注入；多跳任务结构仅如最近反思。

6. MemoryBank：用长期记忆增强大语言模型（MemoryBank: Enhancing Large Language Models with Long-Term Memory）

  • Wanjun Zhong · arXiv 2023 · S2： c3a59e1e405e7c28319e5a1c5b5241f9b340cf63 · arXiv： 2305.10250 · 621 引。
  • 存储/检索： 片段用户记忆在向量库；”AI 代理”做记忆固化（改写/摘要）；检索 = 余弦相似 + 艾宾浩斯遗忘曲线衰减（强/弱召回加权）。
  • 局限： 固化由 LLM 驱动（耗 token）；余弦 top-k + 遗忘衰减会抹掉旧但真的事实（对衰减过度的真理递归差）；多跳事实靠会丢关系的嵌入检索。

7. 代理工作流记忆（Agent Workflow Memory）

  • Zihao Wang（Z. Wang；Jiayuan Mao, Daniel Fried, Graham Neubig） · ICML 2024 · S2： c68cc84ec7808d7bbd5686a6bd1393752a9d8e8d · arXiv： 2409.07429 · DOI： 10.48550/arXiv.2409.07429 · 239 引。
  • 存储/检索： 把执行轨迹存为可复用片段”动作工作流”；检索 = 当前状态/动作与存储工作流轨迹的相似度；匹配的工作流被适配后执行。
  • 局限： 轨迹近乎原文存储（存储与检索时皆耗 token）；相似度 top-k 可匹配最相似但对新约束是错的工作流（top-k ≠ 真证据）；多步适配重解析整条工作流（昂贵、脆弱）。

8. HippoRAG：受神经生物学启发的 LLM 长期记忆（HippoRAG: Neurobiologically Inspired Long-Term Memory for LLMs）

  • Bernal Jimenez Gutierrez · NeurIPS 2024 · S2： 4308208fac24626e0c927ee728038aadc4e87266 · arXiv： 2405.14831 · DOI： 10.48550/arXiv.2405.14831 · 325 引。
  • 存储/检索： 知识图谱（LLM 实体+关系抽取 = 海马式索引）；检索 = 由查询实体播种的个性化 PageRank（聚合多跳路径），非纯余弦。
  • 局限： KG 构建是每段落一次 LLM 抽取（耗 token）；检索被图连通性限定——稀疏图丢多跳链路，PPR 可过度排名高连通但无关节点；单跳查询噪声。

9. 主动记忆：学习统一的长期与短期记忆管理（Agentic Memory: Learning Unified Long-Term and Short-Term Memory Management <>）

  • Yi Yu（Liuyi Yao, Yuexiang Xie, Q. Tan, Jiaqi Feng, Yaliang Li, Libing Wu） · ACL 2026 · S2： fddca50008a46c925b288bae079e43ead0bbeb6e · arXiv： 2601.01885 · DOI： 10.48550/arXiv.2601.01885 · 50 引。
  • 存储/检索： LRU（长期相关单元）+ MRU（短期）带学习写/移决策与摘要生成；检索 = 跨两层存储的学习相关打分。
  • 局限： 构建用 LLM 摘要 + 学习门控（耗 token）；相关性重排 top-k 可漏真证据；跨 LRU/MRU 的多跳事实需跨层检索。

10. MemAgent：用多会话 RL 记忆代理重塑长上下文 LLM（MemAgent: Reshaping Long-Context LLM with Multi-Conv RL-based Memory Agent）

  • Hongli Yu · arXiv 2025 · S2： 80a0548be8c857421aaf0602c6d83d3ef934a251 · arXiv： 2507.02259 · DOI： 10.48550/arXiv.2507.02259 · 195 引。
  • 存储/检索： RL 调优的记忆代理经语义相似 + 学习策略决定存什么、取什么；片段块存于记忆模块。
  • 局限： RL 训练 + 每步 LLM 存储决策昂贵（token/算力重）；相似 + 学习选择可丢弃关键多跳证据；固化成本随上下文上升。

11. Zep：面向代理记忆的时序知识图谱架构（Zep: A Temporal Knowledge Graph Architecture for Agent Memory）

  • Preston Rasmussen（Pavlo Paliychuk, Travis Beauvais, Jack Ryan, Daniel Chalef） · arXiv 2025 · S2： 12407be490a4e4633da7f25a93af000be573a288 · arXiv： 2501.13956 · DOI： 10.48550/arXiv.2501.13956 · 320 引。
  • 存储/检索： 时序知识图谱（Graphiti）：片段 / 语义实体 / 社区子图，双时序（有效 vs 摄取）且无损；检索 = 相关时间切片上的图 + 社区搜索（Deep Memory Retrieval 胜过 MemGPT），非余弦 top-k。
  • 局限： KG 构建（实体/关系抽取 + 社区检测）LLM 密集（耗 token）；召回由图完整性门控——缺边破坏多跳；只取一个时序”切片”，深层推理仍需图遍历。

12. MIRIX：面向基于 LLM 代理的多代理记忆系统（MIRIX: Multi-Agent Memory System for LLM-Based Agents）

  • Yu Wang（Xi Chen） · arXiv 2025 · S2： a38a3460a68c50270548977e66162e92f195334c · arXiv： 2507.07957 · DOI： 10.48550/arXiv.2507.07957 · 144 引。
  • 存储/检索： 多代理编排器（架构/摘要/检索）共享记忆库；片段经嵌入 + 代理策展检索。
  • 局限： 多代理 LLM 编排 = 很多 LLM 调用（耗 token）；嵌入 top-k 返回相似非真证据；多跳片段须由摘要代理拼接。

13. Mem-π：学习何时、生成什么的适应记忆（Mem-π: Adaptive Memory through Learning When and What to Generate）

  • Xiaoqiang Wang（Chao Wang, Hadi Nekoei, Christopher Pal, Alexandre Lacoste 等） · arXiv/ICLR 2026 · S2： 12d960f48ac9ca424a48e3bb1be76e930629e25d · 1 引。

  • 局限： 写入需单独训练的 KNN（构建开销）；检索 = 最近邻，故可能选中”记住了但错”的字节；潜空间多跳组合有限。

14. MemTool：优化动态工具调用的短期记忆管理（MemTool: Optimizing Short-Term Memory Management for Dynamic Tool Calling）

  • Elias Lumer（Anmol Gulati 等） · arXiv 2025 · S2： cfe33b869e5e1976f8294d1610ee9314698c38dd · arXiv： 2507.21428 · DOI： 10.48550/arXiv.2507.21428 · 17 引。

15. 用小型语言模型实现轻量 LLM 代理记忆（Lightweight LLM Agent Memory with Small Language Models）

22. Zero-Mem：面向 LLM 智能体的零 token 记忆操作（Zero-Mem: Zero-Token Memory Operations for LLM Agents）

  • 年份/来源：2026 · arXiv:2607.29377 · S2 b649b6df4be51e4268cf5eadd2b6661ccc51537a

23. LazyMem：宽检索、精构造（Retrieve Broadly, Construct Selectively for Efficient Long-Term Agent Memory）

  • 局限：图构建 + 检索代理都有 LLM 调用；”解析冲突”是查询时推理；检索产出摘要靠图/代理，未用”已知/未知条件包含”。

30. MemWeave：统一图与向量记忆的适应性框架（MemWeave: An Adaptive Framework for Long-Term Agent Knowledge Management via Unified Graph and Vector Memory）

  • 年份/来源：2026 · DOI 10.1109/CAIBDA70336.2026.11621567 · S2 076984cc6e188f885abcfa2dc14e3e666d795511

C. 构建 vs 检索 token 失衡与成本/精度前沿

17. 超越上下文窗口 —— 基于事实的记忆与长上下文 LLM 的成本性能分析（Beyond the Context Window — A Cost-Performance Analysis of Fact-Based Memory vs. Long-Context LLMs）

  • 一作：Natchanon Pollertlam；会议：arXiv；年份 2026。
  • paperId 2366402832e46a565bf96a1f1796861a88ea1d2c；arXiv 2603.04814；DOI 10.48550/arXiv.2603.04814。
  • 研究（1 句）：Mem0 式事实记忆 vs 长上下文 GPT-5-mini，在 LongMemEval + LoCoMo + PersonaMemv2 上按准确率与累计 API 成本（含缓存感知成本模型）打分。
  • 关键发现 [ABS]：长上下文在 LongMemEval/LoCoMo 上实现更高事实召回；记忆仅在 PersonaMemv2 上有竞争力。成本曲线结构性不同：长上下文是随上下文增长的逐轮计费（即使缓存），而记忆的逐轮读成本在一次性写阶段后基本固定。在 100k token 上下文下，记忆在 ~10 轮交互后更便宜，随上下文增长盈亏点降低。[WEB] 论文正文报 20 轮 ~26% 成本节省、LongMemEval 准确率低 ~33–35 分——即记忆更便宜但欠准确：精度上限与 token 做权衡。

18. PRISM —— 意图感知结构化记忆上的帕累托高效检索（PRISM — Pareto-Efficient Retrieval over Intent-Aware Structured Memory）

  • 一作：Jing Peng；会议：arXiv；年份 2026。
  • paperId 7e6bdf1fc5a332732034a9f34de501e2c0fb737a；arXiv 2605.12260；DOI 10.48550/arXiv.2605.12260。
  • 方法（1 句）：免训练检索侧框架（层级束搜索 + 查询敏感边成本 + 证据压缩 + 意图路由），把记忆当作严格上下文预算下的联合检索与压缩问题。
  • 关键发现 [ABS]：在 LoCoMo 上，以量级小得多的上下文预算胜过每个同协议基线的 LLM-judge 准确率，占据”准确率×上下文成本前沿的一个此前空角”。这是多查询/检索侧在边界 token 内提升准确率的直接展示。

19. Mandol —— 面向长程会话的凝聚式代理记忆系统（Mandol — An Agglomerative Agent Memory System for Long-Term Conversations）

  • 一作：Yuhan Zhang（ISCAS + 微软研究院）；会议：arXiv；年份 2026。
  • paperId 7c31c2a517bcab53fd7c6d2767c3f53356e5bdb8；arXiv 2606.29778；DOI 10.48550/arXiv.2606.29778。
  • 架构（1 句）：统一记忆原生层级（基础 + 抽象层），融合键值 / 向量 / 图 + 聚合混合检索、定量查询路由/去噪与 token 受限上下文生成，检索全 LLM-free。
  • 关键数字 [ABS]：在 LoCoMo + LongMemEval 上为代表性代理记忆系统最优总体准确率；商用硬件 10 QPS 下 5.4× 检索加速与 4.8× 插入加速。明确攻击”无 token 预算控制会消解 LLM 准确率”，即取回更少、更干净 token。

20. 代理计划缓存 —— 面向快速、成本高效 LLM 代理的测试时记忆（Agentic Plan Caching — Test-Time Memory for Fast and Cost-Efficient LLM Agents）

  • 一作：Qizheng Zhang；会议：NeurIPS；年份 2025。
  • paperId cd09ab0315169ce0037dd1cf601f3f24729453f2；arXiv 2506.14852；DOI 10.52202/085713-3451。
  • 方法（1 句）：跨语义相似任务从先前代理执行中抽取/适配/复用结构化计划模板（关键词匹配 + 轻量适配）。
  • 关键数字 [ABS]：跨真实代理应用平均 −50.31% 成本与 −27.28% 延迟，且维持性能。具体证明可复用（非内容）记忆——绕开取回原始事实——是最便宜达准确率之路，补齐上下文缓存。

为本任务汇总之数字（已确认 vs 推断）

(a) 构建 token vs 检索 token 失衡。

  • 已确认 [ABS]：Mem0 省 >90% token 成本与 91% 更低 p95 延迟 vs 全上下文。Beyond-the-Context-Window 给结构性规则——记忆读成本在一次性写后基本固定；长上下文逐轮增长；~10 轮 @ 100k 盈亏平衡。Agentic Plan Caching 以可复用计划记忆 −50.3% 成本。PRISM 以量级更小的上下文预算工作。MemoRAG 把便宜记忆/线索阶段与昂贵生成器分开。
  • 推断 [INF]：“写入”侧是写时抽取/固化（MemInsight 增广、A-MEM 重链、MemOS 压缩）；“检索”侧是逐轮循环成本。两个来源（GAIR/MemOS 面板、Moltbook 审计）强调循环检索读取是主导的循环成本，且 ~85% 取回上下文被注入但被忽略——但这是灰色文献面板/博客，非 S2 论文，故我标记为未计数上下文、非已验证论文。

(b) 精度/准确率上限。

  • 已确认 [ABS]：CRAG —— LLM ≤34%、朴素 RAG 44%、最佳产业 RAG 63% 无幻觉。LongMemEval —— 跨稳定交互 30% 准确率下降。Zep 94.8% DMR vs MemGPT 93.4%。LoCoMo —— LLM “substantially lag behind human performance”。Mem0 ~+26% judge 指标 相对 OpenAI 基线。
  • 已确认 [WEB]：MemGPT DMR 每配置 32.1%→92.5% / 35.3%→93.4%（固定上下文 vs MemGPT），及广报结论 DMR 现接近饱和。（Beyond-the-Context-Window）正文：长期记忆用得少但 LongMemEval 召回~33–35 分更低。

(c) “多查询提升精度但费 token”是否被量化？

  • 部分。机制已确认但无干净的每精度点 token 表：Self-RAG 的反思 token 就是自适应多遍检索，在非检索基线上提质量（Self-RAG）；LongMemEval 的时间感知查询扩展 + 事实增强键扩展提升召回但费额外查询构建（LongMemEval）；Zep 的时序/多查询扩展给出 +18.5% 准确率（LongMemEval）同时 ~90% 延迟降低（Zep）；PRISM 在严格上下文预算下做同类事，使准确率上升而 token 无界增长（PRISM）。结论：该权衡的质量侧量得好；token侧通常定性或按延迟，而非按每精度点 token——文献中的开放缺口，也是论文可贡献处。

07 — 面向检索/记忆的 token 效率、压缩与廉价信号

验证方式：每条经 Semantic Scholar（search_papers / get_paper）确认；所有 ID 均真实。21 篇，按机制族分组。括号内为原文标题。

A. 作为可检索单元的分层 / 递归摘要

1. RAPTOR：面向树式组织检索的递归抽象处理（RAPTOR: Recursive Abstractive Processing for Tree-Organized Retrieval）

  • Parth Sarthi 等 • ICLR 2024 • arXiv:2401.18059 • S2 ID: 1d40f07569482d24e3335ffb31394d4bf1567e6f
  • 机制：递归嵌入、聚类、LLM 摘要块为递增抽象层的检索节点树，故少量摘要节点取代很多原始块。
  • 局限：多步/归属所需的精确证据粒度丢失——高层摘要节点可携带大意却丢验证特定事实所需 span。

2. M-RAG：面向检索增强生成的语义键值索引（M-RAG: Semantic Key-Value Indexing for Retrieval-Augmented Generation）

  • Xu Sun 等 • 2026 • arXiv:2603.26667 • S2 ID: 4a9d5671ca964d82139be97f7afaaa4e4e879be0
  • 机制：把查找”检索键”与生成”信息值/证据负载”分离，故索引项紧凑且有判别力，仅在 token 预算下把值装配进上下文。
  • 局限：负载粒度在索引时固定；预算受限的保真只在装配时重解，故高价值键仍可映射到低粒度负载。

B. 记忆作为压缩 / 摘要表征

3. MemGPT：迈向 LLM 即操作系统（MemGPT: Towards LLMs as Operating Systems）

  • Charles Packer 等 • arXiv 2023 • arXiv:2310.08560 • DOI: 10.48550/arXiv.2310.08560 • S2 ID: 908dad62c0e43d80e3e3cb3c0402f7c71c70499c
  • 机制：虚拟上下文管理，把事实/recall/核心记忆层分页，把证据逐出并 LLM 摘要进主上下文，仅工作集占有限窗口。
  • 局限：分页决策是启发式且未学习，故摘要/逐出质量随上下文长度衰减，无预算最优”保留什么”策略。

4. 生成式智能体：人类行为的交互式仿真（Generative Agents: Interactive Simulacra of Human Behavior）

  • Joon Sung Park 等 • UIST 2023 • arXiv:2304.03442 • DOI: 10.1145/3586183.3606763 • S2 ID: 5278a8eb2ba2429d4029745caf4e661080073c81
  • 机制：记忆流由定期 LLM”反思”压缩为更高层抽象洞见，并以新近/重要性/相关性打分检索。
  • 局限：反思有损且无界（无预算控制器），importance 是 LLM 赋值标量、不测信息增益；不相关但新近的记忆可挤掉决定性记忆。

5. 让语言模型适配压缩上下文（Adapting Language Models to Compress Contexts <>）

  • Alexandre Chevalier, Alexander Wettig, Anirudh Ajith, Danqi Chen • EMNLP 2023 • arXiv:2305.14788 • S2 ID: 2f7364d8e5cf94315bf8905f57de9c5543e9a4bf
  • 机制：学习摘要向量（软提示）无监督压缩长文档段；预算好的摘要向量作为可检索/重排单元用于 RAG。
  • 局限：压缩向量不透明并蒸馏为固定大小的软提示，丢失证明某主张所需的 token 级证据；效率增益依赖段边界。

6. 用端到端摘要式上下文管理扩展 LLM 多轮 RL（Scaling LLM Multi-turn RL with End-to-end Summarization-based Context Management <>）

  • Miao Lu 等 • 2025 • arXiv:2510.06727 • S2 ID: fc329a561cad5ab623241bd512170a1021ae14e0
  • 机制：RL 同时优化工具使用行为与周期性压缩工具历史的摘要策略，以紧凑保留上下文换展开（rollout）。
  • 局限：摘要为奖励而非”答案正确粒度”训练，故可压缩掉稍后推理步所需的证据；摘要质量依赖奖励模型。

7. 主动上下文工程（ACE）：为自改进语言模型演化上下文（Agentic Context Engineering (ACE): Evolving Contexts for Self-Improving Language Models）

  • Qizheng Zhang 等 • 2025 • arXiv:2510.04618 • S2 ID: 7d5b2865243015196ffaf0543f579c3d8901af40
  • 机制：把上下文当作演化的”playbook”，Reflector 抽取教训、确定性更新器合并增量——增量、嵌入相似度门控更新，避免单体重写。
  • 局限：针对上下文塌缩（过压缩）而非预算精确；增量合并是相似度启发式，从不保证合并上下文含给定查询的精确证据。

C. Gist token / 提示压缩（上下文压缩）

8. 用 Gist Token 学习压缩提示（Learning to Compress Prompts with Gist Tokens）

  • Jesse Mu, Xiang Lisa Li, Noah D. Goodman • NeurIPS 2023 • arXiv:2304.08467 • S2 ID: b9870e130f61ff900fe00dbcc5782c9b31773d32
  • 机制：用修改注意力掩码把提示压入少数软”gist” token（至多 26x），推理时无额外训练成本。
  • 局限：gist 存分布对齐摘要而非个别 token；值取决于精确措辞的证据不可恢复，且性能在 ~20x 压缩后急剧下降。

9. LLMLingua：压缩提示以加速大语言模型推理（LLMLingua: Compressing Prompts for Accelerated Inference of Large Language Models）

  • Huiqiang Jiang, Qianhui Wu, Chin-Yew Lin, Yuqing Yang, Lili Qiu • EMNLP 2023 • arXiv:2310.05736 • S2 ID: 2392b6d3a5cad9e5cf349169eaeee848266adf6a
  • 机制：粗到细提示压缩，预算控制器对指示/示范/问题分配不同压缩比，并丢低困惑度 token。
  • 局限：用小模型困惑度作代理丢 token，无法区分”冗余”与”措辞异乎寻常但决策关键”；被移除证据对多跳推理永久不可用。

D. 面向更便宜检索的廉价信号 / 表征学习

10. 俄罗斯套娃表示学习（Matryoshka Representation Learning）

  • Aditya Kusupati 等 • 2022（NeurIPS）• arXiv:2205.13147 • S2 ID: aa676125041cd284b4a1313d70143ba6f77c074b
  • 机制：嵌套维度，使嵌入短前缀已编码粗语义，让廉价截断嵌入做候选检索、更长嵌入确认。
  • 局限：截断换粒度；”廉价”套娃前缀宜排序但精确匹配细节在尾部，故短向量检索可漏决定性文档。

11. 量化感知俄罗斯套娃适配（Quantization Aware Matryoshka Adaptation <>）

  • Faizan Ahemad • CIKM 2025 • DOI: 10.1145/3746252.3761077 • S2 ID: df8c9f3e73a336a318843e08798851281e5135c7
  • 机制：结合嵌套（Matryoshka）学习与多级（0.5–2 比特）量化及位 XOR/POPCOUNT 相似，削减存储 >90% 并把检索速度提至恢复 FP32 准确率 95–98%。
  • 局限：量化为嵌入相似设计，非为证据内容忠实重建——它降距离计算成本，不降取回上下文的 token 成本；低比特损失是语义（海明）的而非词法的。

12. 强首阶段检索器时代的多向量重排（Multivector Reranking in the Era of Strong First-Stage Retrievers）

  • Silvio Martinico, Franco Maria Nardini, Cosimo Rulli, Daniela Rulli, Rossano Venturini • ECIR 2026 • arXiv:2601.05200 • S2 ID: 607fa2a63cb7841318dfbb98650940e02499f3f7
  • 机制：用便宜单向量学习稀疏检索器 + 免推理查询编码，取代昂贵的多向量（ColBERT 型）token 级 gather，>24x 加速且质量相当。
  • 局限：便宜首阶段限定重排器所能见的范围——若所需文档被稀疏候选集错过，任何重排都救不回（经典廉价阶段上限）。

E. 信息论检索：信息增益 / VoI / 校准不确定性选择

13. InfoGain-RAG：基于文档信息增益的重排与过滤提升检索增强生成（InfoGain-RAG: Boosting Retrieval-Augmented Generation via Document Information Gain-based Reranking and Filtering）

  • Zihan Wang 等 • EMNLP 2025 • arXiv:2509.12765 • S2 ID: 91a3f096bd9b8061047797139e40280f8924fb77
  • 机制：定义文档信息增益（DIG）为”含 vs 不含某文档时 LLM 生成置信度变化”，训练重排器按边际贡献排序并丢负贡献文档。
  • 局限：DIG 须逐文档前向估计（昂贵）；且测对阅读器置信度的贡献，非真值正确性——故可提拔”自信但错”的证据。

14. 取前先知情：校准后的检索预算分配（Know Before You Fetch: Calibrated Retrieval-Budget Allocation for Retrieval-Augmented Generation）

  • Zhe Dong 等 • 2026 • arXiv:2606.29959 • S2 ID: f9ca787f68e456374cce3276deb1dc053aff3b7f
  • 机制：把 log-prob / 前缀 logit 不确定性校准为正确性概率，用其选分级上下文预算（闭卷 / k=1 / k=5 / 拒答），带显式 token-延迟权衡。
  • 局限：信号是正确性概率，而非缺的是哪里的信息——它能决定”多取”但不能选”哪些 token 信息量最大”；门控在某些模型规模甚至会加延迟。

15. VOILA：面向成本感知多模态问答的价值-信息引导保真选择（VOILA: Value-of-Information Guided Fidelity Selection for Cost-Aware Multimodal Question Answering）

  • R. Bhope 等 • 2026 • arXiv:2602.03007 • S2 ID: 9541b5fdb9ce5994e54d2de7cc92ca9f8ae320b4
  • 机制：用梯度提升回归器 + isotonic 校准按视觉保真预测正确性，再取最小成本保真最大化期望效用（准确率 − 检索成本），在模型执行前。
  • 局限：此处 VoI 在粗离散保真集上，且正确性估计器须按任务训练；效用基于预测准确率，只说明取回成本、不说哪条内容有信息量。

16. 信息价值：人机交流框架（Value of Information: A Framework for Human-Agent Communication）

  • Yijiang River Dong 等 • ACL 2026 • arXiv:2601.06407 • S2 ID: 25153f3188b6162793331e296fc032750fbccbef
  • 机制：免参数的决策论 VoI，判断代理应行动还是打断去问用户，平衡期望效用增益与用户认知成本。
  • 局限：优化”问 vs 动”决策，非”取哪些文档”——其”信息”是用户回答，故 VoI 这里不在 token 预算下选择已取回证据。

17. 面向 LLM 数据选择的贪心信息投影（Greedy Information Projection for LLM Data Selection 《GIP》）

  • Victor Ye Dong 等 • ICLR 2026 • arXiv:2603.13790 • S2 ID: 53a45b98b32188e543f53b04112eb0f93360afdd
  • 机制：把子集选择归结为最大化所选示例与查询信号嵌入间的封闭形式（联合高斯）互信息目标，用快贪心匹配追踪求解。
  • 局限：为训练数据选择而建，非查询时检索；精确互信息需高斯假设，贪心匹配追踪给近而非保证最优集合——无证书。

F. token/成本预算下的检索集选择（组合 / 效用优化）

18. 召回不够：预算约束检索增强生成的阅读器-上下文诊断（Recall Is Not Enough: A Reader-Context Diagnostic for Budget-Constrained Retrieval-Augmented Generation）

  • Ananto Nayan Bala • 2026 • arXiv:2607.00725 • S2 ID: b5630e62fdbef3b44ddf23dfb9af3656982c1d93
  • 机制：把固定 token 预算下打包上下文重构为预算化单调子模最大化（以”答案在上下文中”为效用），在同等或更低 token 成本下胜 top-k 截断与 LLMLingua-2 压缩。
  • 局限：子模保证是 (1−1/e) 式贪心界，且胜出取决于四个同时成立的条件；它靠”选哪些块保留”压缩，而非解锁精确证据粒度。

19. AdaGReS：经冗余感知打分的自适应贪心上下文选择用于 token 预算 RAG（AdaGReS: Adaptive Greedy Context Selection via Redundancy-Aware Scoring for Token-Budgeted RAG）

  • Chao Peng, Bin Wang, Zhilei Long, Jinfang Sheng • 2025 • arXiv:2512.25052 • S2 ID: 129469faa5ae27363dfc35469383a4311a094af7
  • 机制：优化”查询-块相关性减去冗余惩罚”的集合级目标，在 token 预算下贪心选择，用 ε-近似子模性证明近最优。
  • 局限：邻近/冗余度量基于嵌入相似，”冗余”近似为向量距离；贪心一旦丢掉一项即不回头，故低排名但决定性的块可在达到后续预算线前被丢。

  • Mingyang Wu, Haneul Yang, Omer Ben-Porat, Yftah Ziser • 2026 • arXiv:2606.02245 • S2 ID: 7e58dc8d98038d6b220c1ad952bbcf500e3ad4e4

  • 局限：作者发现静态选择脆弱、无固定选择器占优——更大预算可降低答案质量，且代理式控制器仍依赖模型与任务（无保证）。

08 — 去语境化、事实凝聚、查询↔证据不对称性

文献侦察输出。子主题：凝聚/抽象记忆、去语境化、问题↔陈述句不匹配。以下论文均与 Semantic Scholar 核对（真实 paperId / arXiv / DOI），无虚构条目。括号内为原文标题。
开头结论： “去语境化”是一个真实、有名字、已发表的技术（Choi 等，TACL 2021）。但没有广泛采用的嵌入模型训练在（疑问句, 陈述句证据）对比对上——仍是真正的开口。见文末总结。

(a) 去语境化 → 独立语句

1. 去语境化：让句子独立（Decontextualization: Making Sentences Stand-Alone）

  • 一作：Eunsol Choi；会议：TACL；年份：2021
  • ID：paperId 972a74968d2522908b06c5bd1e26266194c5a9ee · DOI 10.1162/tacl_a_00377
  • 机制：定义并命名”去语境化”——改写句子，使所有依赖上下文的指代（”the book”, “he”）变得自足（”Bob’s book”）→ 独立、自足的陈述句。
  • 关键局限：每句一次离线 LLM/规则改写（构建期成本，无梯度进入检索器），外加自身的指代/命名消错；原论文目标是通用句子改写，非检索。

  • 关键局限：只在查询侧加一次 LLM 改写；需合成数据 + 对话标注管线训练去语境化器。

(b) 事实凝聚 / 指代消解 / 叙事整合进记忆

3. ACoRN：检索增强语言模型中的鲁棒噪声抽象压缩（ACoRN: Noise-Robust Abstractive Compression in Retrieval-Augmented Language Models）

  • 一作：Singon Kim；会议：IJCNN；年份：2025
  • ID：paperId a4a4eabed8cd043f8c83054b7a0ddd9976d1d436 · arXiv 2504.12673 · DOI 10.1109/IJCNN64981.2025.11228443
  • 机制：把噪声取回段落抽象压缩成紧凑、抗噪的证据块喂给 LM（事实内容凝聚）。
  • 关键局限：抽象压缩有丢/失事实风险，需训练压缩器；目标是对噪声鲁棒，而非嵌入空间对齐。

  • 一作：Yeonseok Jeong；会议：ACL；年份：2025

  • 关键局限：压缩由上下文内证据性引导，而非训练过的查询↔证据嵌入；依赖生成器的注意力/置信度。

5. 稠密 X 检索：该用什么检索粒度？（Dense X Retrieval: What Retrieval Granularity Should We Use?）

  • 一作：Tong Chen；会议：EMNLP；年份：2023

  • 关键局限：命题仍来自同一 passage 训练过的嵌入模型；命题化是额外 SRL/PLM 分解步，且结果对粒度敏感。

  • 关键局限：LLM 固化昂贵，可丢/错并事实；在凝聚节点上检索用现成嵌入（同一不匹配）。

  • 关键局限：依赖 LLM 抽取步（误差与成本）；检索是图上实体/BFS，故继承实体消解误差并需 KG 构建。

最强局限：

  1. 去语境化已是”有名有姓”的发表技术。 规范论文为 Choi 等《Decontextualization: Making Sentences Stand-Alone》(TACL 2021)；直接检索应用为 Vlachos 等（SIGDIAL 2025），它对会话用户问题去语境化。故不要把”独立句改写”当创新——改定位为：它是独立 LLM 改写遍，有构建期成本与自身指代消错，关键是它改的是证据但不改查询↔证据嵌入几何。
  2. （疑问句, 陈述句证据）嵌入缺口真实且开放。 DPR/RocketQA/ColBERT 均训在 (问题, 整段 passage) 对比对上；”证据句”从不是监督单元。故检索器无归纳压力去排”回答该问题的独立陈述句”——它排主题相似块。Self-RAG/RAGAs/Yoran/Lost-in-the-Middle 只在生成/重排时诊断或打补丁（相关性过滤、批判 token、位置修复、上下文相关度量）。注意：Entailment Tuning（09）用”passage-蕴含-答案/claim”的 NLI 监督，属整段级 + 训练模型，并非“问题→独立答案句”映射（仍非”免训练×原子句”）。→ 故真正缺口是”免训练 × 原子句（问题→答案句监督）× 结构条件包含“（见 L1），而非”从没人训到’答案可推导’”。
  3. 没有公开嵌入模型端到端修此错配。 最近的是 Dense X Retrieval 的命题粒度（更小、更原子的证据单元），但其命题仍由同一 passage 训练编码器产出，非从 (问题, 答案句) 学来。结合所需标注 (问题, 证据句) 数据昂贵，”把嵌入训到 (问题, 陈述句证据) 对上”既欠探索又欠供给。
  4. 记忆-固化系统继承同一错配。 Mem0、HippoRAG、MemoryBank、MemGPT、Generative Agents 都固化/抽象/结晶事实（摘要、KG、反思），却用现成嵌入在凝聚节点上检索——故它们”事实更好”但留着”检索排相似非作答”。其写侧成本与事实丢/过度综合风险是需承认的权衡。

09 — 检索取相关而非相似（Relevance ≠ Similarity）

本分区收录检索按”相关 / 证据必要 / 蕴含”而非”相似”打分的一支——即把 relevance 当作与 cosine/topical 不同的东西来做的那批 RAG + Agent Memory 工作。它与前述各大”相似检索机制”家族（稠密/稀疏/重排/多跳/图/记忆系统）相对照。

1. 用蕴含调优改进稠密段落检索（Improve Dense Passage Retrieval with Entailment Tuning）

  • 一作：Lu Dai, Hao Liu, Hui Xiong · 会议/年份：EMNLP 2024 · arXiv:2410.15801 · S2 b7102e8534fec95fde5c6e5ceba278a75758b7cf
  • 检索端机制：观察”一大类 relevance 与 NLI 的 entailment 对齐“，遂把”passage 是否蕴含可推导的答案/claim“作为相关(正)/无关(负)的监督，用蕴含调优稠密检索器（passage 当 premise、claim 当 hypothesis，经 RoBERTa 类 NLI，NQ/SQuAD/MS-MARCO）。这是”取相关而非相似”的旗舰。
  • 关键局限：仍需训练一个检索器；且监督单元是”passage 蕴含可推导答案“，仍是整段级；蕴含判断本身靠 NLI/cross-encoder（要模型），不是”免训练软条件包含”。

2. ARHN：用开源 LLM 做答案中心的困难负例重标定（ARHN: Answer-Centric Relabeling of Hard Negatives with Open-Source LLMs for Dense Retrieval）

  • 一作：H. Choi, J. Choi, Hansol Jang, Hyun Kim, C. Yun, Changwook Jun, Stanley Jungkyu Choi · 会议/年份：CIKM 2026 · DOI 10.1145/3805712.3809628 · S2 275e8c528518772ac9bf49bf67ed6b37f78bead9
  • 检索端机制：用 LLM 以”答案可得/不可得”为中心重标定硬负例，把”相关”从”主题近”改成”能出答案“，再训稠密检索器。
  • 关键局限：是训练样本重标定（离线/构建端），部分还要 LLM 调用；不改变”检索打分本身是否答案中心”。

3. 面向实体中心问题的实体检索（Entity Retrieval for Answering Entity-Centric Questions）

  • 一作：(见 arXiv) · 会议/年份：arXiv 2024 · arXiv:2408.02795
  • 检索端机制：以”实体信息能否解答该实体中心问题“作为替代 DPR 的检索策略（entity detection / linking / relation prediction / evidence integration）。
  • 关键局限：仅覆盖实体中心/显式实体；仍是整段级，非原子句；需实体索引。

4. 相关性是否从检索器传播到生成器？（Is Relevance Propagated from Retriever to Generator in RAG?）

  • 一作：(见 arXiv) · 会议/年份：arXiv 2025 · arXiv:2502.15025
  • 检索端机制：把 relevance 明确分为 answer containment（KILT 里的”答案包含”）vs topical overlap（信息求索任务的”主题重合”），并研究二者对下游生成的传播差异。
  • 关键局限：只诊断/区分相似与相关，不修；仍假设检索上下文已在手。

5. 在神经 NLI 上解释文本匹配（Explaining Text Matching on Neural Natural Language Inference）

  • 一作：Y. Kim 等 · 会议/年份：2020 · DOI 10.1145/3418052
  • 检索端机制：论证”relevant 与 entailment 紧密相关“，期望 NLI 辅助 IR。
  • 关键局限：概念性/说明性，非可直接用的检索打分器。

6. 句子嵌入的相关性与蕴含联合学习（Joint Learning of Sentence Embeddings for Relevance and Entailment）

  • 一作：(见原文) · 会议/年份：2016（较早期）·（Semantic Scholar 记录）
  • 检索端机制：同时学”相关 + 蕴含”，共用句子嵌入。
  • 关键局限：早期、模型小、非 agent 记忆；相关与蕴含仍作为相似度训练目标的一类，未真正与之分离。

7. MMR：最大化边际相关（Maximal Marginal Relevance）

  • 一作：(经典) · 会议/年份：(经典，此处作”混合相关+另一信号”的形式先例)
  • 检索端机制：λ·relevance − (1−λ)·max_similarity(与已选)，在相关与去冗间平衡。
  • 关键局限：其”relevance”仍是 cosine/语义相似，不是证据必要性；它是”混合相关+另一信号”的形式先例——正是”相似×相关混合”会撞 MMR 的原因，且作者常把它与”证据必要”混同。

8. 让 RAG 对无关上下文鲁棒（Making Retrieval-Augmented Language Models Robust to Irrelevant Context）

  • 一作：Ori Yoran 等 · 会议/年份：ICLR 2024 · arXiv:2310.01558 · S2 3aee33831e0bdea1a1eaae21c7586e4f7c0396d6
  • 检索端机制：用相关性分类器 + 自一致性，过滤“主题相似但不含答案”的取回块。
  • 关键局限：加额外模型/过滤遍；只在推理时治标，未改底层检索打分。

9. 超越相关：LLM 时代的效用中心检索（Beyond Relevance: Utility-Centric Retrieval in the LLM Era）

  • 一作：Hengran Zhang, Minghao Tang, Keping Bi, Jiafeng Guo · 会议/年份：SIGIR 2026 · arXiv:2604.08920 · DOI 10.1145/3805712.3808641 · S2 bcbb5c08cd8abd82d6a2cddaf812e0ea2d963f47
  • 检索端机制：教程/框架——论证检索目标正从”主题相关”转向”LLM 中心效用”，提出统一框架（LLM-agnostic vs LLM-specific、context-independent vs -dependent、与 agentic RAG 的联系）：检索有效性应按”对生成质量的贡献”评估，而非仅靠相关性排名。
  • 关键局限：是号召/框架而非具体检索打分器；”效用”仍靠预测/度量，未落到”免训练 × 结构条件包含”的原子级实现。

10. 预测检索效用与答案质量（Predicting Retrieval Utility and Answer Quality in Retrieval-Augmented Generation）

  • 一作：Fangzheng Tian, Debasis Ganguly, Craig Macdonald · 会议/年份：ECIR 2026 · arXiv:2601.14546 · S2 2db6fa3c73adeff19e41fba97381c9c6471a3d5b
  • 检索端机制：定义 RPP（检索效用） 与 GPP（生成质量） 两个预测任务，用”检索器中心信号（主题相关）+ 读者中心信号（LLM 在查询条件下对已取回上下文的困惑度）+ 文档质量特征”训练线性模型预测效用与答案质量；NQ 上多类特征融合最准，且发现主题相关与效用相关但不等。
  • 关键局限：是测量/预测而非检索打分本身；需训练预测器（非免训练）；证据仍是整段语境。

主导局限模式（shared limitation）

  1. 方向已存在且正确，但”取相关而非相似”被证明可行、也仍未成为主流：旗舰 Entailment Tuning(EMNLP2024) 与答案中心重标定(CIKM2026)把”relevance≈蕴含/答案可推导”做成真的可训练方向——它证实的正是”相似≠相关、相关≈蕴含/证据必要”这一判断是有文献支撑的，不是孤例。
  2. 但几乎所有现有做法都在”相关”上用了训练过的模型：NLI/cross-encoder(Entailment Tuning)、LLM 重标定(ARHN)、相关性过滤分类器(Yoran)；没有“免训练 + 结构条件包含 + 构建端耦合“的版本。
  3. 几乎都停留在整段级：监督单元是”passage 蕴含可推导答案”，从未以（疑问句 → 去语境化原子答案句）为监督单元、也从不做原子句级软条件包含。
  4. “相似 vs 相关”常被混同或只被诊断：2502.15025 只区分不修；MMR 把”相关”仍当语义相似；多数记忆系统嘴上说 relevance(recency×importance×relevance) 但 relevance 就是 cosine。
  5. “效用中心”是再进一步、但仍偏框架/预测：本分区 #9 Beyond Relevance、#10 Predicting Retrieval Utility 把目标从”相关”推向”效用 / 答案质量”，并指明”主题相关≈效用但不等、读者中心特征可补”，但都停在框架或测量预测，未做成”免训练 × 原子句 × 结构条件包含”的检索打分。

10 — 结构 / 条件 / 槽位化检索（概念包含检索的家族）

这一支不看相似度，而是把查询拆成已知条件 / 槽位（或逻辑式 / 场景骨架），到结构化的记忆或索引上做条件匹配。它正是”条件概念包含性检索”所在的家族。

1. Retrieve-and-Fill：面向场景化任务式语义分析（Retrieve-and-Fill for Scenario-based Task-Oriented Semantic Parsing）

  • 一作：Akshat Shrivastava, Shrey Desai, Anchit Gupta, A. Elkahky, Aleksandr Livshits, Alexander Zotov, Ahmed Aly · 会议/年份：EACL 2023 · arXiv:2202.00901 · DOI 10.18653/v1/2023.eacl-main.32 · S2 7b4b1bab91319c63b7d247737f86a74428747b81
  • 检索端机制：把任务剖析为先判定“场景”（intent-slot 模板，含可变的叶子值）再生成 frame。架构 = (1) 检索模块按 utterance 给出”最佳场景”排序；(2) 填充模块把 spans 填入场景得到完整 frame。
  • 关键局限：是 task-oriented 语义分析里的”检索骨架再填空”，不是面向 agent 记忆的证据检索；”场景”是预定义 schema，非从记忆自建结构——与”已知 G + 未知槽 A 对齐到构建端双层”形似，但骨架来源与用途都不同。

2. QO-Bench：诊断”查询算子保持”检索（QO-Bench: Diagnosing Query-Operator-Preserving Retrieval over Typed Event Tuples）

  • 一作：Mengao Zhang, Xiangjie Yang, Chang Liu, Tianhui Tan, Kenfeng Huang · 会议/年份：arXiv 2026 · arXiv:2606.04646 · DOI 10.48550/arXiv.2606.04646 · S2 bc8cf0b6ff03d21d22d38fcf0ae170d5d9badad3
  • 检索端机制：为查询-算子问答（typed 事件元组上的 join / intersection 等）建诊断基准。核心发现：各范式都能取回相关文本，却丢弃算子所需的 typed 值；相似检索在 filter/project 领先、抽取-to-SQL 在 intersection/count 领先；两轴（建库时保持 vs 查询时执行）预测失败处；即便给金证据，长上下文 oracle 仍远未饱和——算子执行本身是瓶颈。
  • 关键局限：以诊断/基准为主，非检索算法；聚焦数据库式算子，覆盖窄；但它量化证实了”取回相似 ≠ 保住条件/值”这一 Idea 6 针对的失效。

3. HCQR：假设条件的查询改写（Hypothesis-Conditioned Query Rewriting for Decision-Useful Retrieval）

  • 一作：Hangeol Chang, Changsu Lee, S. Rho, J. Yeo, Jong Chul Ye · 会议/年份：arXiv 2026 · arXiv:2603.19008 · DOI 10.48550/arXiv.2603.19008 · S2 5f6f3fc30e436aab394267beae9ae71ba99c3ee3
  • 检索端机制：免训练的检索前改写——从（问题 + 候选选项）derive 一个轻量”工作假设”，再改写成三条定向查询（验证假设 / 区分竞争选项 / 核对关键线索），把 RAG 从”主题导向”转为”证据导向”。
  • 关键局限：仍需每查询 3 次改写 + 检索（token/调用开销）；条件是”假设”而非结构化 G/A；主要在多项选择（MedQA/MMLU-Med）验证，未覆盖开放域槽位与构建端耦合。

4. SchemaRAG：schema 感知的检索增强生成（SchemaRAG: A Schema-aware Retrieval-Augmented Generation Framework for Text-to-SQL）

  • 一作：Di Wu, Zetong Tang, Yi He, Xin Luo · 会议/年份：PODS 2026（DOI 10.1145/3786696） · S2 59795a2845002b8d75074e3f6bdd1efcd06f5f47
  • 检索端机制：SchemaLinker（微调，从高质量 CoT 蒸馏 + GRPO）+ schema 增强检索器（参照数据库 schema 取最相关示例）+ Pareto 最优候选选择，让生成与 SQL 结构对齐。
  • 关键局限：需要微调过的模型；严格绑定数据库 schema；属 text-to-SQL，非通用 agent 记忆，也非”免训练 × 原子句”。

5. QBBN：面向逻辑信息检索的统计解析（Statistical Parsing for Logical Information Retrieval）

  • 一作：G. Coppola · 会议/年份：arXiv 2026 · arXiv:2602.12170 · DOI 10.48550/arXiv.2602.12170 · S2 7c7413e5ed53d9e2863d2d4387f4885953dfe1b1
  • 检索端机制：把自然语言确定性地编译成带类型的逻辑式（typed slot grammar，33/33 零歧义）；LLM 做预处理/消歧/重排、grammar 解析、QBBN（带 NEG 因子的量化布尔贝叶斯网络）做推理——“LLM 消除标注瓶颈、grammar + QBBN 当验证器”。
  • 关键局限：属正式语义/推理方向，不是检索打分；需要语法/逻辑引擎（非仅嵌入）；面向精确逻辑，未处理 agent 记忆的相似-相关混同与 query-time 成本。
