Graph-Traversal Retrieval in Agent Memory & RAG — 调研笔记

日期: 2026-08-31

目的: 因为感觉简单的余弦相似度可能会是统一构建标准下精度的弊端来源,所以我们尝试将目光放在图遍历上。调研所有在检索端采用图遍历的 Agent Memory 与 RAG 论文,分析各自如何遍历、局限在哪,提炼总体局限,为课题(构建-检索 token 失衡, 检索端=门→填→闭包判停管线)提供定位与值得借鉴/避开之处。

说明: 覆盖以”图遍历作为检索机制”为核心的工作; 纯向量/纯 RAG 不在范围; A-Mem(MRR)等”近图”但非遍历检索的会标注说明。本文件只放”方法+机制+各自局限”(纯调研)

版本: v2.0 —— 新增 8 个子领域的 63 篇论文(共约 79 篇),并新增 7 条总体局限。

0. 一句话总览

图遍历检索的本质是:把”检索”从”向量相似”变成”沿图边扩散/导航去找证据子图”。 它天然解决”语义相似但断链”问题(向量是 bag-of-chunks, 会切断推理链), 但几乎所有方法都栽在同一批坑上:图质量依赖构建(贵且丢信息)、over-retrieval(hub 节点/噪声桥稀释密度)、连通≠相关(图连通 ≠ 逻辑蕴含)、LLM 引导遍历太烧 token。

最关键的一条(贯穿全篇):”证据链完整与否”长期被误当成”召回够不够”问题,几乎没人把它做成”收完候选后单独做的一次判定”。 —— 这是图遍历领域最空的一层,也是你立论真正能抓的位子。

所以检索端是否该用图遍历、怎么用,核心在”它只被当作’收集候选’的通道,还是’判定相关’的判据“。

2. Agent Memory 领域的图遍历检索

2.1 Zero-Mem (2026) — 零 token 图+时序遍历

  • 机制: 组织成(entity-context graph) + (temporal hierarchy)。查询”权衡两个视图、分别检索、沿结构恢复支撑关系或周围上下文”, 再确定性校准(丢弃冲突证据)。记忆操作全程不调 LLM(编码器单列); 只有最终 QA reader 用 LLM。
  • 局限: 遍历沿”entity-context 边+时序” → 恢复的是”支撑关系/上下文”而非答案; 召回上限=实体图质量; 实体抽取有损, 需上下文的对话可能偏移/丢节点; 实测精度未大幅提升, 只”省 token 不伤太多”。

2.2 Zep / Graphiti (2025) — 时序知识图谱

  • 机制: Graphiti = temporally-aware KG, 动态合成对话+业务数据, 保留历史关系; 检索做时序感知图遍历/跨会话合成。LongMemEval +18.5% 精度、-90% 延迟。
  • 局限: 构建重(逐条 eager 事实抽取); 遍历沿实体+时间边; 是”重构建换精度”的典型(与”构建-50%”相反)。

2.3 HippoRAG (2024) — KG + Personalized PageRank

  • 机制: KG 作记忆索引(节点=实体/事件); 查询实体为种子跑 PPR, 概率沿图谱扩散, 单步多跳。+20% 优于 SOTA, 比 IRCoT 便宜 10-30x、快 6-13x。
  • 局限: PPR 固定概率衰减、不迭代到覆盖闭包、不判相关只按可达性排; 锚定误差放大; hub 偏向; 未见”已知→推未知”对照。

2.4 RippleMem (2026) — 锚点联想扩展(★)

  • 机制: cue-rich 事件记忆单元 + 事件中心记忆图; ①混合线索(dense+sparse)召回锚点; ②沿语义+结构关联扩展恢复缺失证据。LoCoMo +3.95%, LongMemEval-S +11.87%, 图构建降 ~30x。
  • 局限/关系: 骨架与你的”已知→推未知”几乎重合(必先看)。但它扩展靠图结构关联而非相关性门/反事实判据; “补齐证据”是”召回更多”, 你的 f/y 是”判够不够/相不相关”——差别就在”扩展(召回) vs 门控/闭包(精度)”。事件单元非逐句 verbatim; 粒度不同。

2.5 MemWeave (2026) — 向量+图双存储 + 路由

  • 机制: 语义向量库 + 图谱库, 轻量 Memory Router(微调分类器) 按查询类型(factual/associative/complex)选检索路径; 图路径处理 associative/complex。LOCOMO F1 73.5%, 距全上下文上界 0.4 分, -95.7% 延迟、-90% token。
  • 局限: 靠 router 分型, 非深度遍历; router 需微调(监督成本); “混合两库”非”让遍历更准”。

2.6 PersonalAI / 2.0 (2025/2026) — 规划驱动遍历

  • 机制: KG 存储/检索系统对比; 2.0 叠加 planning mechanism(LLM 规划走哪条关系)。个人 agent。
  • 局限: LLM 规划烧 token+慢; 场景略异; 未专门处理 over-retrieval/闭包。

2.7 A-Mem (2025) / 2.8 D-Mem (2026) — 备注(近图/门控, 非遍历)

  • A-Mem: Zettelkasten 笔记+链接, 检索用 MMR(余弦+去冗余), 非图遍历; 是学生对比基线。D-Mem: dopamine-gated 门控路由, 与”何时固化”相关, 非遍历。

★2.9 LiCoMemory (ACL 2025, CogniGraph)

  • 机制: 轻量层级图(实体层+关系层做语义索引); 检索两段式——实体锚定把 query 落到子图, 再沿关系边做多跳、层级感知图搜索(配 temporal-aware search)收集候选, 最后独立 rerank。与”低token图遍历收集候选+单独判定”几乎完全同构。
  • 局限: 继续用实体-关系结构, 锚点外离散长尾信息落不进起点; 节点/关系需 LLM 抽取, 构建仍耗 token; 层级+时序搜索超参敏感; rerank 依赖额外模型, 遍历与判定未真解耦成”零 LLM”。
  • 成本: 层级图压缩冗余、降更新延迟; 但抽取为 LLM 调用, 构建 token 留存。

★2.10 G-Memory (NeurIPS 2025)

  • 机制: 三层图(insight/query/interaction), 多 agent 长交互; query 做显式”双向记忆遍历”(上向检索高层 insight、下向检索细粒度压缩轨迹)。遍历收集后再供系统进化/回答。
  • 局限: 专为多 agent 设计; 图由 LLM 抽取轨迹+insight 跨 trial 蒸馏(构建 token/延迟高); 遍历召回后仍靠 LLM 再过滤, 判定未解耦; insight 抽象忠实度依赖抽取。

★2.11 SGMem (2025)

  • 机制: 句子为节点、分块为单位建句级图, 边横跨 turn/round/session 三粒度捕获关联; 检索沿这些粒度关联边扩展, 原始对话与 summary/fact/insight 一起给 LLM。
  • 局限: 句级节点粒度细 → 图庞大、边稠密, 遍历带宽与噪声难控; 关联抽取+分块质量定召回上限; 只在端点间建关联, 隐式关联召回弱; 无实体锚定, 跨粒度易发散。
  • 成本: 句级图构建需 LLM 抽关联, 成本随对话长度近线性。

★2.12 AssoMem (2025)

  • 机制: 关联记忆图, utterance 锚定到自动抽取的 clue 节点; 检索由 query 沿锚定 clue 做重要性感知扩散/扩展(associative spread), 融合 relevance/importance/temporal 三维信号、自适应互信息(MI)融合做重要性置顶。扩散收集+信号裁决明确两阶段。
  • 局限: 锚定依赖 clue 抽取质量, 漏检落入盲区; MI 融合是 learned gating 而非纯 0-token; 稠密场景扩散易爆炸; 闭包/相关性判定被加权吸收而非独立。

★2.13 AriGraph (IJCAI 2024)

  • 机制: 环境中边探索边构/更新融合语义+episodic 的”记忆图(世界模型)”; agent 在图上做 A*/路径规划式遍历找可达目标, 静态任务做图上导航/多跳检索。
  • 局限: 图只随已访问区域生长, 未探区缺失; 必须可交互环境; 每步 LLM 抽三元组建图, token 随步数线性累; 无遗忘/衰减/压缩时序管理。
  • 成本: 每步 LLM 建图 token 累积; 图遍历本身廉价(A*/导航)。

★2.14 From Experience to Strategy: Trainable Graph Memory (2025)

  • 机制: 多层图: 原始轨迹抽象成状态机式”决策路径”结构图, 再蒸馏为高层”元策略”; 每步按当前状态沿状态机边匹配到路径/元策略, 回灌 meta-cognitive prompt。
  • 局限: 离散状态机匹配, 模糊状态无法落点; 需 RL 优化元策略权重(训练+推理成本高); 蒸馏丢失轨迹细节; 单步取一条策略, 无子图扩散。

★2.15 KOPE (2026, 经验图)

  • 机制: 把(决策、执行反馈、后续利用该证据的决策)记为 Experience Graph, 保留决策序/观测/备选分支; 固定 token 预算内检索相关经验注入。
  • 局限: 高度绑定硬件核优化域; 图按决策序而非语义实体锚定, 跨主题迁移弱; 固定预算截断可能丢关键分支。

★2.16 CompassMem (ACL 2026) — 事件中心逻辑图导航

  • 机制: 增量分割成事件(Event Segmentation), 显式连逻辑关系边成 Event Graph; 检索=图上结构化、目标导向的导航(沿逻辑关系逐步收集记忆), 而非纯语义检索。明确区分”图上导航收集候选”与”表面检索”。
  • 局限: 显式逻辑关系(因果/时序/指代)要 LLM 分割+连边, 构建成本高且事件边界噪声敏感; 只在 LoCoMo/NarrativeQA; 每条逻辑边可靠性未论证, 长程逻辑链易断。与”先遍历收候选再单独闭包判定”撞车度高。

★2.17 TRACE (2026) — 状态感知时序证据图

  • 机制: 对话建成 事件/会话/主题 三层图, 边带 时间/因果/更新/矛盾 类型+validity 标注; 查询先向量取笔记作种子, 再 graph-guided evidence search 沿图扩展出 validity-aware 支持路径重建证据; 历史过期事实保留但当前态降权。lexical recall 与 evidence reconstruction 解耦。
  • 局限: validity 标注+更新/矛盾边维护复杂、迁移成本高; 仍需向量检索做种子, 图只在种子附近精化, 非独立零 token 遍历。

★2.18 SYNAPSE (ACL 2026) — episodic-semantic + spreading activation

  • 机制: 记忆建成动态图, 相关性由 spreading activation 涌现(不预计算链接), 侧抑制+时间衰减动态高亮相关子图滤干扰; Triple Hybrid Retrieval 融合几何嵌入检索与 activation 图遍历(双路候选收集+相关性)。
  • 局限: 与 Pavlovic 式激活遍历同源, 新颖性要靠”时间衰减+识别式临时弱化”去 argue; 时间衰减是启发式权重非可学习; 只在 LoCoMo。

★2.19 MemoriesDB (2025) — 时间-语义-关系库

  • 机制: 每个记忆=时间-语义-关系三元实体(微秒时间戳唯一标识+嵌入), 有向边带标签/元数据; 单查询路径内做 time-bounded retrieval + 混合语义检索 + lightweight structural reasoning。
  • 局限: 单人概念原型(仅 PostgreSQL), 无基准/同行评测; 检索由时间+向量驱动, 无真图遍历; 与”零 token 遍历”无关。

★2.20 ARTEM (AAAI 2026) — 时空情景记忆

  • 机制: LLM 抽事件(时间/空间/实体/语义), 向量化后 instance-based incremental learning 存入自组织网络 STEM; 检索按精确 episode 索引取回。
  • 局限: 非图遍历(自组织网络 episode 索引), 无图结构不能做多跳/路径/时序链; 依赖 LLM 抽事件; 与”图上遍历收候选”基本正交(作对照)。

★2.21 RoMem (2026) — 时间连续相位旋转

  • 机制: 把时间从离散元数据变成连续相位旋转; Semantic Speed Gate 把关系文本嵌入映射成”易变性”分数, 配合 complex 空间相位旋转做 geometric shadowing(过时事实旋出相位、时间正确事实压过矛盾项)。
  • 局限: 检索是几何/相位邻近度, 无图遍历/子图扩散; 依赖需训练的 Speed Gate; 只给时间边打”可靠性/时效”分。价值在验证”时间确权”与”遍历”是两条独立轴。

3. RAG 领域的图遍历检索

3.1 GraphRAG (2024, Microsoft)

  • 机制: 实体 KG + Leiden 社区检测, 预生成社区摘要(离线缓存、跨查询共享); 点查询走 local search(实体锚定+邻域/社区遍历), 全局问题走 global search(社区摘要)。
  • 局限: 依赖高质量 KG; 查询-无关的静态离线索引, 无法对特定查询动态裁剪链; 社区级摘要丢细粒度。

3.2 LightRAG (2024)

  • 机制: LLM 从查询抽 entities+relations keys; 按 local(实体)+global(关系)双锚定沿邻接边遍历并合并, 结合向量。增量更新。
  • 局限: 无闭包/覆盖判据、无相关性门、无 over-retrieval 惩罚; 扩散原语被大家共享(非新)。

★3.3 G-Retriever (NeurIPS 2024) — 文本属性图上 PCST 子图

  • 机制: 把”在文本属性图上找最能回答问句的子图”建模成 Prize-Collecting Steiner Tree(PCST) 优化: 用 GNN 编码节点、以问句相关节点为锚点向外扩散, 挑”能覆盖问句且代价低”的子图, 软提示给 LLM。锚点扩展+子图扩散+代价剪枝。
  • 局限: 强依赖预建文本属性图; PCST NP-hard 只能近似; 子图粒度可能过拟合问句漏跨子图关联; 无独立判定环节, 子图直接喂 LLM(收集与判定纠缠典型)。

★3.4 GNN-RAG (ACL 2025 Findings) — GNN 子图检索器

  • 机制: ①训练 GNN 在稠密 KG 子图上做消息传递, 输出答案候选节点(收集); ②检索连接问句实体与候选的 KG 最短路径作推理路径, verbalize 后喂 LLM。图上消息传递(pick)+最短路径遍历(lift)。
  • 局限: GNN 需按数据集训练、依赖 ground-truth 子图/答案标签、跨 KG 不迁移; 候选漏了就抬不动(GNN 单点瓶颈); shortest-path 可能 over-retrieval 堆大量路径进 prompt; 收集后无独立门槛判定。

★3.5 LinearRAG (2025) — 无关系分层图

  • 机制: 不做关系抽取, 只用轻量实体抽取+语义链接建无关系分层图 Tri-Graph(线性扩展、零额外 token); 检索①局部语义桥接激活相关实体(锚点激活), ②全局重要性聚集做段落检索(沿层级向上聚合)。
  • 局限: 去关系建模, 关系依赖的多跳/长链只能靠共现与层级, 可能漏关系依赖型; 全局聚合粗粒度, over-retrieval; 无显式预算/判定门。

★3.6 GraphFlow (NeurIPS 2025) — 学习型图检索策略

  • 机制: 把 KG-RAG 检索当序列决策, transition-based flow matching 联合训练检索策略+flow estimator, 把”检索结果奖励”因子分解到中间状态, 引导策略在 text-rich KG 上”按 reward 比例”扩展候选。
  • 局限: 需 process-level reward(PRM 式, 昂贵); 依赖 text-rich KG; 优化目标是 hit-rate/recall, 无独立”相关性/闭环判定”判定停; 需训练且查询时也跑策略。

★3.7 GFM-RAG (NeurIPS 2025) — 图基础模型检索

  • 机制: 8M 参数图基础模型直接在图上消息传递, 学”问句-知识”图结构关系并检索; 60 KG/1400 万三元组+70 万文档两阶段预训练, 未见数据免微调即可检索。
  • 局限: 需大规模 KG+文档预训练(门槛高); GNN 隐含打分黑盒、无显式子图路径/无独立判定; 对图噪声/不完备敏感; 域外泛化有限。

★3.8 KET-RAG (KDD 2025) — 多粒度索引

  • 机制: LLM 只对少量关键文本块建 KG 骨架(skeleton), 再用全部文本块建 text-keyword 二部图作轻量替代; 检索时骨架 local search + 二部图复刻遍历, 两路并行提覆盖。
  • 局限: 需 LLM 抽骨架(索引成本+噪声); 二部图粗粒度无法表达关系; 双路可能重复/发散、无判定门、over-retrieval; 省索引但依赖图结构。

★3.9 LazyGraphRAG (2024, 微软技术报告) — ★

  • 机制: 索引端不预生成摘要/嵌入, 只用名词短语抽取+社区统计建分级社区图; 查询端”迭代加深”: 先用 best-first(向量局部)再 BFS(全局社区), 按”相关性测试预算”逐层扩——先跑轻量相关性测试当”门”, 仅通过才让 LLM 深入, 最后做全局综合。贴近一种”廉价收集+门槛判定”
  • 局限: 非正式论文; 依赖社区结构与短语共现图, 弱于显语义; 相关性测试是启发式”预算”非学习型闭合/相关判据, 阈值难自适应; 对”必经特定中间实体的深链”可能过早剪枝。
  • 成本: 索引约原版 GraphRAG 的 0.1%; 查询约其 global search 的 4%~700 倍降幅(视预算)。

★3.10 BYOKG-RAG (EMNLP 2025) — 多策略图检索工具

  • 机制: LLM 先生成”问题实体、候选答案、推理路径、OpenCypher”等工件, 图工具再把这些工件链接到 KG 检索相关图上下文; 多策略工具互补绕开单 agent 遍历的初始化敏感性, 迭代 refine。
  • 局限: 每工件都 LLM 生成, 查询时 LLM 调用多、token 高; 实体链接错误仍传播; 依赖检索工具而非图结构; over-retrieval 靠迭代重试兜底, 无独立判定。

3.11 Think-on-Graph 1.0 (2023) — LLM 迭代束搜索

  • 机制: LLM 在 KG 上迭代遍历, 每步选 top 关系继续探索、剪枝, 形成推理路径(BFS/beam)。training-free。
  • 局限: 每步调 LLM(慢+贵); 依赖 KG; 束宽/深超参; 推理路径正确性由 LLM 挑边决定 → 有推理崩溃/过早剪枝。

3.12 Think-on-Graph 2.0 (2024) — 图+文档紧耦合

  • 机制: 交替”图检索(沿实体-关系)”+”文档上下文检索”, 紧耦合; 文档给图提供实体上下文、图链接文档。SOTA 6/7; 让 Llama-2-13B 到 GPT-3.5。
  • 局限: LLM 驱动迭代、token/延迟高; 未解决 over-retrieval; 文档+图双迭代放大成本。

3.13 Think-on-Graph 3.0 (2025) — 多智能体动态索引

  • 机制: MACER; 动态构建 Chunk-Triplets-Community 异构图索引(按查询定制), Dual-Evolution(查询与检索子图协同演化)驱动; 多智能体; 面向轻量 LLM。
  • 局限: 为克服 KG 依赖+LLM 抽取受限而动态建索引 → 查询时成本; 多智能体结构复杂; 查询特定 vs 离线索引的权衡。

3.14 Search-on-Graph (KDD 2025) — LLM 自主导航

  • 机制: LLM 自己选关系, observe→think→navigate(每步观察当前实体可用关系、推理哪条最推进作答、导航), 用完整推理历史, 不靠独立分模块替代准则。无任务微调、跨 schema。
  • 局限: 每步 LLM → 每查询烧大量 token; 聚焦”路径选择”而非”证据子图相关性/闭包”。

★3.15 RoG (ICLR 2024) — 关系路径检索

  • 机制: 两段式: ①LLM 生成关系序列(planning) + RL 预训练关系路径检索模块, 在 KG 上采多跳 reasoning paths(沿关系采路径)作检索证据; ②路径喂 LLM 生成答案。路径生成由 RL 预训练模型驱动, 非逐跳 LLM。
  • 局限: 需额外 RL/监督训练 planning 模型; 路径受规划模型见过的关系约束; 检索阶段仍须线上查 KG; 规划+答案均生成式, 幻觉/无依据路径风险; 对领域/图谱迁移差。
  • 成本: 离线 RL 产出路径可近零逐跳 token, 但 RL 训练成本高; 路径送入生成长上下文 token。

★3.16 KG-Agent (ACL 2024)

  • 机制: 自主 LLM agent 循环: 内置工具箱+KG executor+知识记忆; 小 LLM 每步决策”选哪个工具”并更新记忆, 用程序语言表述并执行多跳推理查/遍历 KG。
  • 局限: 需代码化指令数据集微调(10K 样本); 每步 LLM 选工具, token 随跳数累积, 非低 token; 正确性耦合同题分解+工具执行。
  • 成本: 每轮 LLM 选工具+执行器写回, token 随跳数线性增长; 优势在 10K 微调而非少训练。

★3.17 Graph-CoT (ACL 2024)

  • 机制: 每轮三步: LLM reasoning → LLM-graph interaction → graph execution(调外部图算子/子图查询), 把图结构喂 LLM 驱动逐跳推理。
  • 局限: 每迭代 LLM+图执行两调用, token 高且串行; 受限上下文; 大图无法免调用扩散。

★3.18 Chain-of-Knowledge (2024)

  • 机制: 在 KG 上用规则挖掘建 KnowReason 数据, 试错机制训练 LLM 做内部知识探索(把 KG 推理内化为内部逐步走索)。
  • 局限: 依赖规则挖掘的 KG; 规则过拟合; 推理在内部、不一定 faithful; 不做外部图导航、无法保证候选可溯源。

★3.19 KAG (WWW 2024) — 逻辑式引导检索

  • 机制: 语义解析把问题转成带语义类型与关系的 Logical Form, 预测 LF 元素与结构化 KG 索引的语义关系定位所需引用(非”图行走”)。
  • 局限: 需构建领域 KG+mutual-index(预处理高); 依赖 LLM 语义解析质量; 逻辑式对口语化问题脆弱; 一次 LF→检索, 非逐步 agentic 遍历。
  • 成本: 一次语义解析+关系预测即得候选, 避免逐跳 LLM; 但逻辑式+互索引构建高, 依赖专用 KG 引擎(OpenSPG)。

★3.20 GraphRAG-R1 (WWW 2025) — RL + 过程约束

  • 机制: 改造版 GRPO 训 LLM: 自动分解难题、自主调检索工具并推理; 配两个过程奖励——PRA(渐减检索衰减)惩罚浅检索、CAF(代价感知 F1)抑制过度思考/控成本; 图+文混合检索。
  • 局限: RL 多阶段冷启动成本高; “图遍历”仍靠调预定义图/文本检索工具, 非每跳细粒度子图行走; reward 设计偏启发式。
  • 成本: 专设 CAF/PRA 控计算成本(直接对”过度思考/浅检索”), 显著省 token, 但仍基于 LLM 检索。

★3.21 RouteRAG (ACL 2025) — RL 混合检索路由

  • 机制: RL 联合优化统一策略: LLM 在”何时推理、从文本还是图检索、何时出答案”间自适应决策, 做多轮 text+graph 混合 RAG; 两阶段训同时考虑任务结果与检索效率。
  • 局限: 需同时有文本+图语料; 图证据检索更贵; 策略在”每跳/每子步”粒度较粗; RL 两阶段训练成本高; 依赖检索算子非原生图行走。

★3.22 READS (2024) — 判别式推理

  • 机制: 把生成式子图规划/推理重表述为一组判别性子任务, 每个对候选实体/子图做”判别/校验”而非自由生成, 逐子任务压缩搜索空间。
  • 局限: 需预先抽取候选实体+切分子任务; 判别步仍由 LLM 逐子任务打分(有 token); 偏 KGQA 端到端; 子任务切分可能漏解。

★3.23 CatRAG (2026) — 上下文感知遍历(建在 HippoRAG 2 上)

  • 机制: 把静态 KG 转成 query-adaptive 导航结构: Symbolic Anchoring(弱实体约束)正则化 PPR + Query-Aware 动态边权(prune 离题路径、amplify 对齐 query 路径) + Key-Fact 权重偏置锚定证据。全程 PPR 遍历, 不加 LLM。
  • 局限: 仍依赖 HippoRAG 2 基座; hub/语义漂移只是缓解非根除; Recall 提升有限主要赢 reasoning completeness; 需离线 KGs 与 passage 锚点。
  • 成本: PPR 遍历零 LLM 便宜; 每查询动态边重加权增加一次图侧计算(低)。

★3.24 S-Path-RAG (WWW 2026) — 语义感知最短路径

  • 机制: 混合权重 k-最短路径+束搜索+受限随机游走枚举有限长语义加权候选路径, 学可微路径打分器+对比编码器+轻量验证器, 路径潜在变量跨注意注入 LLM; 并在”神经-苏格拉底图对话”循环里把 LLM 诊断映射为图编辑或种子扩展。
  • 局限: 路径打分器需监督训练; bounded-length 枚举漏长证据链; 检索与 LLM 对话交替, 不确定时才触发扩展, LLM 往返累积 token。

★3.25 LiteSemRAG (2026) — 完全无 LLM 语义图

  • 机制: 完全无 LLM: 上下文 token 级 embedding 建异构语义图, 表层词汇与上下文语义分离; 查询两步语义感知检索: 共现图加权+孤立语义恢复。
  • 局限: 共现加权游走+语义恢复, 图结构依赖共现统计, “语义相隔但拓扑远”证据召回弱; hub/高共现节点拉高无关分; 无闭环。
  • 成本: 索引+查询全零 LLM token(其卖点); 宣称 MRR@10 全 best、Recall@10 与 LLM 基 GN 打平。

★3.26 SAGE (2026) — 结构感知图扩展

  • 机制: 离线用元数据相似度+百分位剪枝建 chunk 级图; 在线基检器拿 k 个种子 chunk, 只扩一阶邻居, 再用 dense+sparse 过滤选回 k’ 个额外 chunk。
  • 局限: 只扩一阶, 无法找回多跳但语义远的证据链(无闭环); 上限被种子 k 锁死; 图质量依赖离线相似度+剪枝阈值。
  • 成本: 遍历无 LLM, token 只含最终 k+k’ 个 chunk; 离线建图开销大。

★3.27 GraphWalk (2026) — 工具化图导航

  • 机制: 免训练”工具化”图上导航: 给 LLM 一组正交图操作(取邻居/查边/跑一跳), 让 LLM 一步步走, 每步工具调用是可验证透明 trace。
  • 局限: 遍历由 LLM 指挥, token/延迟随深度/试错线性甚至爆炸(正是”零/低 token”对立面); 假设 LLM 会正确组合操作; 无图侧去重/剪枝, 易绕路。

★3.28 Query-Aware GNN (2025) / Beam Retrieval (NAACL 2024)

  • Query-Aware GNN: 每 episode 建”文本 chunk+顺序/语义关系”KG, 增强图注意力+查询引导池化+学习打分头, 查询感知多跳消息传给 chunk 打分。局限: GNN 需训练+每 episode 建图; 只判 chunk 相关度无闭环回扩。
  • Beam Retrieval: 多跳检索建模为跨跳束搜索, 每跳 MIPS 密集检索候选 passage, 维护多个 beam 扩展, 联合优化编码器+两个分类头; 检索不用 LLM。局限: 端到端监督训练; beam 宽固定漏长链; 依赖密集编码器对结构不敏锐; 属”passage 链”非强图遍历。

★3.29 StepChain GraphRAG (2025) — BFS 证据链

  • 机制: 推理时把检索到的 passage 实时解析成 KG, 复杂 query 拆子问题; 每个子问题用 BFS 沿相关边动态展开, 组装显式 evidence chain, 避免无关上下文淹没 LLM。
  • 局限: 自述 computational overhead 与 LLM 幻觉未解决; BFS 展开未做显式断链兜底/完整性闭环; 子问题分解+on-the-fly KG 解析需额外 LLM。

★3.30 HopRAG (ACL 2025) — 逻辑感知多跳

  • 机制: 索引期用 LLM 生成 pseudo-queries 作图中边, 建 passage graph(文本 chunk 为点、逻辑连接为边); 检索期 retrieve-reason-prune: 从语义相似 passage 出发, 沿 pseudo-query 引导的多跳邻居做 LLM 推理, 逐跳扩 scope 并剪枝。
  • 局限: 每 hop 都 LLM 推理(token 重); 伪查询边引入索引期噪声/错误传播; 侧重”逻辑相关”而非”证据链完整性”, 对 gap/断链无显式机制; 可能先错过关键桥接节点。

★3.31 GRAG (NAACL Findings 2024) — 文本图子图检索

  • 机制: 对文本图(引文/社交/KG)用 divide-and-conquer 在线性时间检索最优 textual subgraph; 检索后以 text+graph 两视角喂 LLM 多跳推理。
  • 局限: 建立在子图内连通/类 clique 假设, 稠密大图/跨簇证据(真实断链)覆盖弱; 无显式 gap 检测; 两视角拼接, token 随子图规模增长。

★3.32 SG-RAG MOT (2025)

  • 机制: Cypher 在 KG 上检索回答所需 subgraph; MOT 步: 重叠子图 hierarchical merging(去冗余)+BFS 遍历给三元组排序喂 LLM。
  • 局限: 必须存在 KG+依赖 Cypher/schema; 只在 MetaQA(电影域); merging 启发式, 过度合并掉精度; 未处理证据链断缺——只有当相关子图都找齐才有效。

★3.33 Query-Driven Graph Retrieval w/ Adaptive Pruning (Electronics 2026)

  • 机制: 统一异构图(实体-关系-文本)上 joint retrieve over entities+relations + lexical 信号, 动态构建候选子图; reasoning path 用 structural strength+contrastive 打分, adaptive pruning 按 query 复杂度与路径分数分布动态缩放证据规模。
  • 局限: contrastive 打分需训练; 自适应剪枝按分数分布而非显式”证据链完整性”判定(可能 over-pruning 掉关键桥接); HotpotQA/2Wiki, MuSiQue 未报。

★3.34 HyCE-RAG (2026) — 超图证据链

  • 机制: 把实体-关系-上下文证据组织成 hyperedge, 建 query-aware evidence hypergraph; entity-hyperedge incidence 结构上 confidence propagation + confidence-guided evidence assembly 选/连/排证据路径; 打分看语义相关、实体连通、证据覆盖、关系可靠。
  • 局限: 需额外构造超图/超边抽取(离线+构建成本); evidence assembly 多因子复杂打分, 最终证据链交 LLM; “证据覆盖”只是打分一项, 无显式断链定位/闭包证明。

★3.35 MEGRAG (2026) — 多粒度证据图

  • 机制: 多跳推理表示为 path-structured multi-granularity evidence graph; 离线跨粒度索引 passage-sentence-triple; 在线先取 compact triples 再按需加 sentence/passage(自底向上扩粒度); 用中间答案+先前推理判断”初始问题是否已解决”, 未解决则定位缺失信息、生成下一问。
  • 局限: 依赖 iterative RAG, 每步”是否解决/缺失信息”需 LLM 判定(额外调用); 缺失信息定位是 LLM 生成的、非确定性图闭合; 中间检索错误累积; 自底向上扩可能因早期 triple 选取不当走偏。

★3.36 GRASP (2026) — 命题图 agentic 搜索

  • 机制: agentic: 多跳 query 分解为 dependency-aware plan, 按复杂度动态伸缩 sub-agent 数; 每 sub-agent 在 entity-proposition-passage 三层图上探索, entity 层定向 traversal、proposition 层 high-recall passage 召回(reciprocal-rank voting)。
  • 局限: 本质多 sub-agent = 多 LLM 调用(token 根本重); 动态 sub-agent 数带来不可控深度/延迟; 三层图构造成本高; 用”每正确回答摊销 token(success economy)”度良, 说明承认高昂成本。

★3.37 RoT (2025) — 思维图检索复用

  • 机制: 把历史推理步骤组合成”思维图”(sequential+semantic 两种边); 推理时按 query 检索图上相关节点(基于 PPR/相似度), 再 reward-guided traversal 沿图拼出问题专属推理模板。
  • 局限: 建图+每条边/路径 reward 都靠 LLM 打分(多次调用); 遍历启发式无证明的相关性/闭包判定; 复用模板对全新推导泛化弱。
  • 成本: 目标省 token(输出最高 -40%, 延迟 -82%, 成本 -59%); 代价是建图+reward 额外 LLM。

★3.38 LogicRAG (AAAI 2025) — 自适应推理结构

  • 机制: 不做预制图, 推理时 query 分解成子问题集合, 建模为子问题依赖 DAG, 拓扑排序把图线性化成有逻辑序的检索序列, 按序逐子问题检索; 配图剪枝+上下文剪枝。图上遍历只用于”检索顺序/依赖序”, 不做相关性判定。
  • 局限: 无预制图→多跳关系不靠图索引, 强依赖 query 分解质量, 跨实体长程依赖易漏; 拓扑排序只保依赖序不证相关性; 每子问题独立检索累积 LLM 调用。
  • 成本: 明确以减少 token 为卖点(图剪枝+上下文剪枝降冗余检索)。

★3.39 RATT (AAAI 2024) — 检索增强思维树

  • 机制: 每思维分支做”规划+前瞻”探索多条后继推理步, 把 RAG 事实核验与 LLM 全局策略评估结合, 在思维树上 best-first/回溯搜索选最有希望分支; ToT 作可检索(逐节点取回事实)的推理骨架。
  • 局限: 对 ToT 的增强, 仍生成侧树搜索; 每节点 RAG 检索+策略评估, token/延迟大; 局部事实检索+全局策略靠手工协调, 无独立闭包判停。

★3.40 SCOUT-RAG (2026) — 分布式 agentic 图遍历

  • 机制: 分布式 agentic: 四个 agent 协作(估域相关性、决定何时向新域扩张、自适应遍历深度、合成答案), 以”增量效用目标”渐进跨域检索, 不要求全局图可见。
  • 局限: 依赖多 LLM agent 分工, 系统协调成本高; 效用/检索遗憾需估计; 在访问受限/无全局可见时信息天然不全。
  • 成本: 以控”检索遗憾”+API 成本为设计目标, 显著减跨域调用/token/延迟; 但多 agent=多次 LLM 固定开销。

★3.41 HELP (2026) — HyperNode 逻辑路径定位

  • 机制: HyperNode 展开: 三元组链式拼成连贯推理路径并抽象成 HyperNode 抓结构依赖; “逻辑路径引导的证据定位”把路径经预计算图-文本关联直接映射回语料, 绕开随机游走。
  • 局限: 要预计算图-文本关联(索引成本), 面向预制 KG 语料图; 路径→语料映射质量定证据定位准确性; 为求快牺牲探索性, 复杂隐式依赖可能漏。
  • 成本: 预计算映射替代随机游走, 最高约 28.8x 加速(低 token/低延迟遍历式证据收集)。

4. 总体图遍历检索的局限(核心)

  1. 图质量是天花板(写端)。 遍历质量 ≤ 图构建质量; 图构建要么人工(贵)、要么 LLM 自动(有损/不可靠)。→ 遍历绕不开写端瓶颈。
  2. Over-Retrieval(两犄角之一)。 语义 RAG 切断推理链(bag-of-chunks); 图遍历用 hub 节点+噪声桥维持连通反而稀释信息密度(StructReason)。→ 图遍历带回的是”结构化连接的”, 不是”能推出答案的”。
  3. 连通 ≠ 蕴含(necessary-not-sufficient)。 图连通/非环不代表能逻辑推出答案。所有纯图遍历只到”连通/覆盖”, 到不了”蕴含/充分性”。
  4. LLM 引导遍历太贵(违反 token 中性)。 ToG/SoG 每步 LLM; 非 LLM 遍历便宜但失去自适应推理。→ 检索端 token 不变约束下最难拿的平衡。
  5. hub/高连接度点主导。 PPR/激活/遍历都偏心高 degree 点, 稀释有效信息。
  6. 实体锚定的粒度盲区。 图节点常是实体/文档非”答案承载句”; 实体中心检索对事件语义、共指链、”哪次会话提到X”(答案是一个 turn)弱。
  7. 查询-无关静态索引 vs 查询-特定动态索引的权衡。 GraphRAG 静态省延迟, ToG-3 动态贴合但贵。

  8. 指标碎片化。 各报 accuracy/F1/latency/token/frontier 面积, 无统一”构建-检索约束”协议。

  9. 遍历原语单一且互斥。 低 token 遍历几乎都被绑定到单一原语——PPR(引向 hub)、BFS/最短路径(只覆盖有边连通的)、GNN(需训练+黑盒)、社区搜索(需社区结构且判粗)。没有工作同时压掉”hub 吞噬/锚点外长尾/免训练”三者缺陷。

  10. “断链/证据链完整”长期被误当召回问题而非独立判定问题(★最空的一层)。 多数工作把 gap 当”有没有把边找全”(recall-side); 几乎没人(仅 AriadneMem 少数, 且是单次调用、非可证明闭包)在收完候选后做显式”能否形成闭合证据链/是否需要桥接”判定。→ 这正是”遍历收集+独立闭包判定”立论最该抓的空位。
  11. 遍历只能证明”沿结构找到了”, 不能证明”够了”(完备性无界)。 图遍历天然结构驱动, 对”语义相关但结构不连”的证据本质盲; 任何”无需检索预算/无需判定门就能保证完备”的方案原理上不成立——低 token 遍历天花板是结构连通性, 而非语义覆盖。
  12. 省下的 token 多来自”把判定挪进图侧或训练侧”而非真免 LLM。 G-RAG/TAPE/M3KG-GRASP/AssoMem-MI 等实为把相关性判定交给 GNN 得分/社区粗打分/预设规则(需训练或特征工程); 一旦计入索引期 LLM 抽取、RL 训练、GNN 微调总成本, “零 token”叙事即被打破。真正 0-LLM 的只有建图前纯算法遍历(PPR/DFS), 但那又无判定能力。
  13. 社区/层级粒度带来”判定粒度错配”。 用社区搜索/层级聚合做遍历时(如 LazyGraphRAG/TAPE/G-Memory/AssoMem), 判定最小单位是”社区/层/聚合块”而非原子证据, 使相关性判定无法原子化, 并让 over-retrieval 与 under-retrieval 呈二象性。
  14. “实体锚定/种子”是低 token 遍历的真正命门。 几乎所有低 token 遍历(PPR、CatRAG 锚点正则、AriGraph A*、联想扩展)的召回上限被”query 能否正确锚到/抽到正确实体”锁死, 而实体抽取/锚定几乎都靠 LLM 或需训练。→ 故”零 token 遍历”更准确说是”零 token 扩散、非零 token 锚定”, 论证公平性时需主动坦白。
  15. 跨子图/社区长程关联是共性盲区。 层级聚合、子图 Steiner、束缚最短路径对”必须跨越多个不相连子图取证据”都缺”何时因不连通而停止/承认失败”的显式机制, 只靠超参预算截断, 缺乏可证伪性。
